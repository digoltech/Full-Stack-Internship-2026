## 3. How Authentication Works (Big Picture)

```text
1. User enters username + password in the login form
2. Browser ──POST /auth/login {username, password}──▶ Server
3. Server checks the credentials
      ├─ wrong ─▶ 401 + error message
      └─ right ─▶ 200 + { user data, accessToken }
4. The app stores the token (and user) and marks the user as logged in
5. For protected data the app sends:   Authorization: Bearer <token>
6. Server verifies the token and returns the data (or 401 if invalid/expired)
7. Logout: the app deletes the token
```

### Authentication vs authorisation

| Term | Question | Example |
|---|---|---|
| **Authentication** | *Who are you?* | Login with username and password |
| **Authorisation** | *What are you allowed to do?* | Only admins can delete products |

### What is a token?

A **token** (often a JWT, *JSON Web Token*) is a string the server gives you after login. It proves "this request comes from user X". You send it with each request instead of the password.

### A very important security truth

> **Frontend route protection is only about user experience, not security.**

Anyone can open DevTools and see your JavaScript. Hiding the `/dashboard` page in React only prevents honest users from seeing a page they cannot use. **The real protection must be in the backend**: the server must reject requests without a valid token. You will build this in the Express weeks.

## 5. Authentication Service

```js
// services/authService.js
const BASE_URL = import.meta.env.VITE_API_URL;

export async function loginRequest(username, password) {
  const response = await fetch(`${BASE_URL}/auth/login`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ username, password })
  });

  const data = await response.json().catch(() => ({}));

  if (!response.ok) {
    // The API sends { message: "Invalid credentials" }
    throw new Error(data.message || "Login failed");
  }

  return data;   // { accessToken, refreshToken, id, username, ... }
}

export async function getCurrentUser(token, { signal } = {}) {
  const response = await fetch(`${BASE_URL}/auth/me`, {
    headers: { Authorization: `Bearer ${token}` },
    signal
  });

  if (!response.ok) throw new Error("Session expired");
  return response.json();
}
```

Notes:

- We read the error `message` from the server so the user sees a helpful text.
- `.catch(() => ({}))` prevents a crash if the server sends a non-JSON body.

## 6. `AuthContext`

### 6.1 What do we store?

```js
{
  user: { id, username, firstName, ... } | null,
  token: "..." | null
}
```

Where to store the session so a refresh does not log the user out?

| Option | Good | Bad |
|---|---|---|
| React state only | Simple | Lost on refresh |
| `localStorage` | Survives refresh and tabs | Readable by any JavaScript on the page (XSS risk) |
| `sessionStorage` | Cleared when the tab closes | Same XSS risk |
| `HttpOnly` cookie set by the server | JavaScript cannot read it, so it is safer | Needs a proper backend |

For this learning project we use **`localStorage`**. In production, prefer **HttpOnly cookies** set by your own backend. We will revisit this in the security week. Never store the password.

### 6.2 The provider

```jsx
// context/AuthContext.jsx
import { createContext, useCallback, useContext, useEffect, useMemo, useState } from "react";
import { loginRequest, getCurrentUser } from "../services/authService";

const AuthContext = createContext(null);
const STORAGE_KEY = "session-v1";

function loadSession() {
  try {
    const saved = localStorage.getItem(STORAGE_KEY);
    return saved ? JSON.parse(saved) : null;       // { user, token }
  } catch {
    return null;
  }
}

export function AuthProvider({ children }) {
  const [session, setSession] = useState(loadSession);
  const [checking, setChecking] = useState(Boolean(loadSession()));   // validating a restored session

  // Persist the session
  useEffect(() => {
    if (session) localStorage.setItem(STORAGE_KEY, JSON.stringify(session));
    else localStorage.removeItem(STORAGE_KEY);
  }, [session]);

  // On start: verify that a restored token is still valid
  useEffect(() => {
    if (!session) {
      setChecking(false);
      return;
    }

    const controller = new AbortController();

    getCurrentUser(session.token, { signal: controller.signal })
      .then((freshUser) => setSession((current) => current && { ...current, user: freshUser }))
      .catch((err) => {
        if (err.name !== "AbortError") setSession(null);   // expired → log out
      })
      .finally(() => {
        if (!controller.signal.aborted) setChecking(false);
      });

    return () => controller.abort();
    // We intentionally verify only once, when the app starts.
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);

  const login = useCallback(async (username, password) => {
    const data = await loginRequest(username, password);
    const { accessToken, refreshToken, ...user } = data;     // keep tokens out of `user`
    setSession({ user, token: accessToken });
    return user;
  }, []);

  const logout = useCallback(() => setSession(null), []);

  const value = useMemo(
    () => ({
      user: session?.user ?? null,
      token: session?.token ?? null,
      isAuthenticated: Boolean(session),
      checking,
      login,
      logout
    }),
    [session, checking, login, logout]
  );

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) throw new Error("useAuth must be used inside <AuthProvider>");
  return context;
}
```

Key ideas:

- `checking` stops us from redirecting to `/login` **before** we know whether a stored session is still valid (prevents a flash of the login page on refresh).
- `login` **throws** on failure; the login form catches the error and shows it.
- We use `useCallback` and `useMemo` (Day 10) so that the context value is stable.
- `refreshToken` is removed from `user`; we do not need it now.

Place the provider in `main.jsx` **inside** `BrowserRouter` (so that auth code can use navigation) and above `App`:

```jsx
<BrowserRouter>
  <AuthProvider>
    <ThemeProvider>
      <CartProvider>
        <App />
      </CartProvider>
    </ThemeProvider>
  </AuthProvider>
</BrowserRouter>
```

## 7. The Login Page

```jsx
// pages/LoginPage.jsx
import { useState } from "react";
import { Navigate, useLocation, useNavigate } from "react-router-dom";
import { useAuth } from "../context/AuthContext";

function LoginPage() {
  const { login, isAuthenticated } = useAuth();
  const navigate = useNavigate();
  const location = useLocation();

  // Where did the user want to go before being sent here?
  const redirectTo = location.state?.from?.pathname ?? "/";

  const [form, setForm] = useState({ username: "", password: "" });
  const [errors, setErrors] = useState({});
  const [serverError, setServerError] = useState("");
  const [submitting, setSubmitting] = useState(false);

  // Already logged in? Do not show the login form.
  if (isAuthenticated) return <Navigate to={redirectTo} replace />;

  function handleChange(event) {
    const { name, value } = event.target;
    setForm((prev) => ({ ...prev, [name]: value }));
  }

  function validate() {
    const next = {};
    if (!form.username.trim()) next.username = "Username is required.";
    if (!form.password) next.password = "Password is required.";
    return next;
  }

  async function handleSubmit(event) {
    event.preventDefault();
    setServerError("");

    const validationErrors = validate();
    setErrors(validationErrors);
    if (Object.keys(validationErrors).length > 0) return;

    try {
      setSubmitting(true);
      await login(form.username.trim(), form.password);
      navigate(redirectTo, { replace: true });    // replace: Back will not return to /login
    } catch (err) {
      setServerError(err.message);
    } finally {
      setSubmitting(false);
    }
  }

  return (
    <section className="auth-card">
      <h1>Log in</h1>

      <form onSubmit={handleSubmit} noValidate>
        <div className="field">
          <label htmlFor="username">Username</label>
          <input
            id="username"
            name="username"
            value={form.username}
            onChange={handleChange}
            autoComplete="username"
            aria-invalid={Boolean(errors.username)}
            aria-describedby={errors.username ? "username-error" : undefined}
          />
          {errors.username && <p id="username-error" className="error">{errors.username}</p>}
        </div>

        <div className="field">
          <label htmlFor="password">Password</label>
          <input
            id="password"
            name="password"
            type="password"
            value={form.password}
            onChange={handleChange}
            autoComplete="current-password"
            aria-invalid={Boolean(errors.password)}
            aria-describedby={errors.password ? "password-error" : undefined}
          />
          {errors.password && <p id="password-error" className="error">{errors.password}</p>}
        </div>

        {serverError && <p role="alert" className="error">{serverError}</p>}

        <button type="submit" disabled={submitting}>
          {submitting ? "Logging in..." : "Log in"}
        </button>
      </form>

      <p className="hint">Demo account: <code>emilys</code> / <code>emilyspass</code></p>
    </section>
  );
}

export default LoginPage;
```

Points to notice:

- Everything from Day 4 (controlled inputs, validation) appears here.
- `location.state.from` is set by the protected route (next section).
- `navigate(..., { replace: true })` replaces the login entry in the history.
- `aria-invalid`, `aria-describedby` and `role="alert"` make errors accessible to screen readers.
- The submit button is disabled while the request is running.
- `autoComplete` helps password managers.

## 8. Protected Routes

### 8.1 The `ProtectedRoute` component

```jsx
// components/ProtectedRoute.jsx
import { Navigate, Outlet, useLocation } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import Loader from "./Loader";

function ProtectedRoute() {
  const { isAuthenticated, checking } = useAuth();
  const location = useLocation();

  if (checking) return <Loader text="Checking your session..." />;

  if (!isAuthenticated) {
    // Remember where the user wanted to go
    return <Navigate to="/login" replace state={{ from: location }} />;
  }

  return <Outlet />;     // render the protected child routes
}

export default ProtectedRoute;
```

### 8.2 Using it as a layout route

```jsx
// App.jsx
<Routes>
  <Route element={<MainLayout />}>
    {/* public */}
    <Route index element={<HomePage />} />
    <Route path="products" element={<ProductsPage />} />
    <Route path="products/:productId" element={<ProductDetailsPage />} />
    <Route path="login" element={<LoginPage />} />

    {/* protected */}
    <Route element={<ProtectedRoute />}>
      <Route path="cart" element={<CartPage />} />
      <Route path="checkout" element={<CheckoutPage />} />
      <Route path="profile" element={<ProfilePage />} />
    </Route>

    <Route path="*" element={<NotFoundPage />} />
  </Route>
</Routes>
```

Nesting `ProtectedRoute` as a **pathless layout route** protects every child with a single wrapper.

### 8.3 The flow

```text
Visitor opens /checkout
   └▶ ProtectedRoute: not authenticated
        └▶ <Navigate to="/login" state={{ from: "/checkout" }} replace />
             └▶ LoginPage: user logs in
                  └▶ navigate("/checkout", { replace: true })   ← back where they wanted to go
```

For requests that **need** the token, extend the API client so every call includes it automatically:

```js
// services/apiClient.js
const BASE_URL = import.meta.env.VITE_API_URL;

export async function request(path, { token, headers, ...options } = {}) {
  const response = await fetch(`${BASE_URL}${path}`, {
    ...options,
    headers: {
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...headers
    }
  });

  if (!response.ok) {
    const data = await response.json().catch(() => ({}));
    throw new Error(data.message || `Request failed (${response.status})`);
  }

  return response.json();
}

// usage
const me = await request("/auth/me", { token });
```

Real backends also return `401 Unauthorized` when a token expires. A central place for that logic (in the API client) can call `logout()` and redirect to the login page. We will do this properly with our own backend.

## 11. Accessibility and Semantic HTML Review

Accessibility (a11y) means everyone, including people using screen readers or keyboards, can use your app. It is also part of the capstone rubric. Use this checklist on **every page**:

| Check | How |
|---|---|
| Semantic landmarks | Use `<header>`, `<nav>`, `<main>`, `<footer>`, `<section>`, `<article>` instead of many `<div>`s |
| One `<h1>` per page, headings in order | Do not skip from `h1` to `h4` for styling |
| Images have `alt` | Meaningful text, or `alt=""` for decorative images |
| Every input has a `<label>` | `htmlFor` + `id` or wrap the input |
| Buttons are `<button>`, links are `<a>`/`<Link>` | Never `<div onClick>` |
| Icon-only buttons have `aria-label` | `<button aria-label="Remove item">🗑</button>` |
| Keyboard | Press `Tab`: can you reach everything? Is the focus outline visible? Can you activate with `Enter`/`Space`? |
| Colour contrast | At least 4.5:1 for normal text (check with Chrome DevTools or Lighthouse) |
| Dynamic messages | `role="alert"` for errors, `aria-live="polite"` for counts/status |
| Page title | Different `document.title` for each page |
| Language | `<html lang="en">` in `index.html` |
| Responsive | Works at 320px; text can be zoomed to 200% |

### Run Lighthouse

Chrome DevTools → **Lighthouse** → select *Accessibility* (and *Performance*, *Best Practices*, *SEO*) → *Analyze page load*. Aim for **90+ accessibility**. Fix the first three issues it reports.

```text
my-shop/

│   └── favicon.svg
├── src/
│   ├── main.jsx

├── .env.example               # variable names, no secrets
├── .gitignore
├── index.html
├── package.json
└── README.md
```

Guidelines:

- **Group by type** (components, hooks, pages) for small/medium projects. Large projects often group by **feature** (`features/cart/…`).
- A component file should usually stay under ~150 lines. If it grows, split it.
- Name files after what they export (`ProductCard.jsx` exports `ProductCard`).
- Avoid deep relative imports like `../../../utils/x`. Keep the structure shallow.
- Delete unused files, `console.log`s, and commented-out code before submission.

## 14. Deployment

### 14.1 Production build

```bash
npm run build      # creates the dist/ folder (HTML, JS, CSS, assets)
npm run preview    # serves dist/ locally to test the production build
```

Always run `build` and `preview` locally **before** deploying. It catches errors that `npm run dev` hides (case-sensitive file names, missing imports, environment variables).

### 14.2 Environment variables in production

- `.env` is **not** committed (it is in `.gitignore`).
- Set `VITE_API_URL` in the hosting dashboard (Environment Variables).
- Vite inserts the value **at build time**. After changing a variable, **re-deploy**.
- Remember: anything with `VITE_` is public in the final JavaScript.

### 14.3 The "404 on refresh" problem and its fix

On your computer, visiting `localhost:5173/products/5` works because Vite's dev server sends `index.html` for unknown paths. On a basic static host, `/products/5` looks for a **file** that does not exist and returns **404**.

Fix: tell the host to serve `index.html` for **all** paths (a *rewrite*; React Router then renders the correct page).

**Netlify**: create `public/_redirects`

```text
/*    /index.html   200
```

**Vercel**: create `vercel.json` in the project root

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

**Cloudflare Pages**: a SPA fallback is automatic when there is no `404.html` in the output; Cloudflare Workers/Assets need `"not_found_handling": "single-page-application"` in the asset configuration.

**GitHub Pages**: needs the `HashRouter`, or a `404.html` copy trick. Prefer Netlify, Vercel or Cloudflare for an SPA with real routes.

### 14.4 Deploy to Vercel (step-by-step)

1. Push the project to GitHub.
2. Go to vercel.com → **Add New → Project** → import the repository.
3. Framework preset: **Vite** (auto-detected). Build command: `npm run build`. Output directory: `dist`.
4. Add the environment variable `VITE_API_URL`.
5. Click **Deploy**. You get a URL like `https://my-shop.vercel.app`.
6. Every `git push` to `main` re-deploys automatically.

### 14.5 Deploy to Netlify (alternative)

1. Netlify → **Add new site → Import an existing project** → select the repository.
2. Build command `npm run build`, publish directory `dist`.
3. Add environment variables under *Site configuration → Environment variables*.
4. Make sure `public/_redirects` exists, then deploy.

### 14.6 Post-deployment checklist

- [ ] Open the live URL on your phone.
- [ ] Refresh on a deep link (`/products/5`): no 404.
- [ ] Log in and out; refresh while logged in.
- [ ] Open the browser console: no errors, no failed requests.
- [ ] Add the live URL to the README and to the GitHub repository's *About* section.

## 16. Common Mistakes

| Mistake | Problem | Fix |
|---|---|---|
| Believing a protected route is secure | Anyone can read your JS | The **server** must verify tokens |
| Storing the password | Severe security risk | Store only a token, never the password |
| Redirecting before the session check finishes | Flash of the login page after refresh | Use a `checking` state |
| Forgetting `replace` on login redirect | Back button returns to the login page | `navigate(..., { replace: true })` |
| Login error shown only in `console.log` | User sees nothing | Show an `alert` message |
| Not disabling the submit button | Double submissions | `disabled={submitting}` |
| Missing SPA rewrite on the host | 404 on refresh | `_redirects` / `vercel.json` |
| Env variable changed after deploy but no rebuild | Old value in the bundle | Redeploy |
| Case-sensitive import (`./productcard`) | Works on Windows, fails on Linux hosting | Match file names exactly |
| Committing `.env` or tokens | Leaked secrets | `.gitignore`, `.env.example` |
| `console.log(token)` left in the code | Sensitive data in the console | Remove it |
