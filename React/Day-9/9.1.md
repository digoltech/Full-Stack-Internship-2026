# Week 3 — Day 9.1: Context API and `useReducer`

## 1. Learning Objectives

By the end of this session, students should be able to:

- Explain prop drilling and when it becomes a real problem.
- Create a context with `createContext`, provide it with a Provider and consume it with `useContext`.
- Build a Provider component and a custom `useXxx` hook for a clean API.
- Decide when to use Context and when props are enough.
- Explain how `useReducer` works: state, action, reducer, dispatch.
- Choose between `useState` and `useReducer`.
- Combine Context + `useReducer` to build global state, such as a shopping cart.
- Persist reducer state in `localStorage`.
- Explain how Context causes re-renders and how to reduce them.

## 2. Recap

On Day 5 we lifted state to a parent. We also noticed **prop drilling**:

```text
App (state)
 └─ Layout        (passes through)
     └─ Navbar    (passes through)
         └─ CartBadge   ← finally uses `cartCount`
```

Today we solve it properly, and we also learn a better tool for state that has many different kinds of updates.

## 3. The Problem: Global-ish Data

Some data is needed in **many places** across the component tree:

| Data | Used by |
|---|---|
| Logged-in user | Navbar, profile page, protected routes |
| Theme (light/dark) | Almost every component |
| Shopping cart | Navbar badge, product cards, cart page, checkout |
| Language | All text |

Passing these through props at every level is exhausting and fragile. **Context** lets any component in a subtree read the data **directly**, skipping the middle components.

```text
BEFORE (props):   App → Layout → Navbar → CartBadge
AFTER  (context): App provides ──────────────▶ CartBadge reads
```

## 4. The Context API in Three Steps

### Step 1: Create the context

```jsx
// context/ThemeContext.jsx
import { createContext } from "react";

export const ThemeContext = createContext(null);
```

### Step 2: Provide a value

```jsx
import { useState } from "react";
import { ThemeContext } from "./ThemeContext";

function App() {
  const [theme, setTheme] = useState("light");

  function toggleTheme() {
    setTheme((current) => (current === "light" ? "dark" : "light"));
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <Layout />
    </ThemeContext.Provider>
  );
}
```

Everything inside `<ThemeContext.Provider>` (at any depth) can read the `value`.

### Step 3: Consume it with `useContext`

```jsx
import { useContext } from "react";
import { ThemeContext } from "../context/ThemeContext";

function ThemeButton() {
  const { theme, toggleTheme } = useContext(ThemeContext);

  return (
    <button onClick={toggleTheme}>
      Switch to {theme === "light" ? "dark" : "light"} mode
    </button>
  );
}
```

`ThemeButton` can be nested 10 levels deep. No props are passed through the layers in between.

### How it works

1. A component calls `useContext(ThemeContext)`.
2. React looks **upwards** in the tree for the nearest `ThemeContext.Provider`.
3. It returns that Provider's `value`.
4. When the `value` changes, every component that uses this context re-renders.

If there is **no Provider** above, you get the default passed to `createContext(...)` (here `null`), which usually causes a crash when you destructure it. We will protect against this next.

## 5. The Professional Pattern: Provider Component + Custom Hook

Putting state in `App` makes `App` messy. Create a dedicated Provider component and a custom hook.

```jsx
// context/ThemeContext.jsx
import { createContext, useContext, useEffect, useState } from "react";

const ThemeContext = createContext(null);

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState(
    () => localStorage.getItem("theme") ?? "light"
  );

  useEffect(() => {
    localStorage.setItem("theme", theme);
    document.documentElement.dataset.theme = theme;   // <html data-theme="dark">
  }, [theme]);

  function toggleTheme() {
    setTheme((current) => (current === "light" ? "dark" : "light"));
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

// Custom hook: the only thing components import
export function useTheme() {
  const context = useContext(ThemeContext);

  if (context === null) {
    throw new Error("useTheme must be used inside <ThemeProvider>");
  }

  return context;
}
```

Use it in `main.jsx`:

```jsx
<StrictMode>
  <BrowserRouter>
    <ThemeProvider>
      <App />
    </ThemeProvider>
  </BrowserRouter>
</StrictMode>
```

Use it anywhere:

```jsx
import { useTheme } from "../context/ThemeContext";

function Navbar() {
  const { theme, toggleTheme } = useTheme();
  return <button onClick={toggleTheme}>{theme === "light" ? "🌙" : "☀️"}</button>;
}
```

And in CSS:

```css
:root { --bg: #ffffff; --text: #111827; }
:root[data-theme="dark"] { --bg: #111827; --text: #f9fafb; }
body { background: var(--bg); color: var(--text); }
```

Why this pattern is good:

- Components do not know **how** the theme is stored.
- A helpful **error message** appears if someone forgets the Provider.
- `children` is passed through, so wrapping the app is easy.
- Changing the implementation later (for example, saving the theme on a server) affects only one file.

> **Fast Refresh note:** Vite's ESLint plugin may warn when one file exports both a component and a hook ("only-export-components"). For learning, it is acceptable. In larger projects, split into `ThemeContext.js`, `ThemeProvider.jsx` and `useTheme.js`.

## 6. When to Use Context (and When Not To)

| Use Context for | Do not use Context for |
|---|---|
| Authenticated user | Data used by 1–2 nearby components (use props) |
| Theme, language | Data that changes **very frequently** (mouse position, typing) |
| Shopping cart, notifications | Server data that you can fetch where needed (later you will learn caching libraries) |
| Settings shared by many pages | Everything "just in case" |

**Rule:** Start with props. Lift state. Use composition (`children`). Reach for Context only when prop drilling is truly painful.

### Context is not a magic performance tool

Every component that calls `useContext(X)` re-renders when X's value changes. Therefore:

- Keep contexts **small and focused** (`AuthContext`, `CartContext`, `ThemeContext`), not one giant `AppContext`.
- A new object in `value={{ ... }}` is created on **every render of the Provider**, so consumers re-render whenever the Provider re-renders. We will fix this with `useMemo` on Day 10.

## 7. Why `useReducer`?

A cart has many kinds of updates: add an item, remove it, increase quantity, decrease quantity, clear. With `useState`, you end up with many small functions, each containing update logic spread across the component. The rules of the data (for example, "quantity can never go below 1") are scattered.

`useReducer` puts **all update logic in one place**: a **reducer** function.

### 7.1 The concept: a reducer is a pure function

```text
newState = reducer(currentState, action)
```

- **State**: current data.
- **Action**: a plain object describing **what happened**: `{ type: "ADD_ITEM", payload: product }`.
- **Reducer**: a function that receives the current state and an action and **returns the new state**.
- **dispatch**: a function you call to send an action to the reducer.

It is the same idea as `array.reduce((acc, item) => ..., initial)`, but over time, as actions arrive.

```text
Click "Add"  ──▶ dispatch({type:"ADD_ITEM", payload})  ──▶ reducer(state, action)  ──▶ new state ──▶ re-render
```

### 7.2 The simplest example: a counter

```jsx
import { useReducer } from "react";

function counterReducer(state, action) {
  switch (action.type) {
    case "INCREMENT":
      return { count: state.count + 1 };
    case "DECREMENT":
      return { count: state.count - 1 };
    case "RESET":
      return { count: 0 };
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}

function Counter() {
  const [state, dispatch] = useReducer(counterReducer, { count: 0 });

  return (
    <div>
      <p>Count: {state.count}</p>
      <button onClick={() => dispatch({ type: "INCREMENT" })}>+</button>
      <button onClick={() => dispatch({ type: "DECREMENT" })}>-</button>
      <button onClick={() => dispatch({ type: "RESET" })}>Reset</button>
    </div>
  );
}
```

### 7.3 Rules of a reducer

1. It must be **pure**: same inputs → same output. No fetch, no `localStorage`, no random numbers, no `Date.now()`.
2. It must **not mutate** `state`. Always return a new object/array.
3. It must **always return** a state (the `default` case should throw or return `state`).
4. Generate ids and timestamps **before** dispatching, and send them in the action's payload.

### 7.4 `useState` vs `useReducer`

| | `useState` | `useReducer` |
|---|---|---|
| Best for | Simple, independent values | Complex state with many actions |
| Update logic | Inside event handlers | Centralised in the reducer |
| State shape | A single value or small object | Object/array with related fields |
| Testing | Needs a component | The reducer is a plain function, so it is easy to test |
| Example | `isOpen`, `query`, `count` | cart, form wizard, game state |

Neither is "better". Use `useState` first; use `useReducer` when updates become hard to follow.

## 8. Building the Shopping Cart: Context + Reducer

### 8.1 Design the state

```js
{
  items: [
    { id: 1, title: "Phone", price: 499, thumbnail: "...", quantity: 2 },
    { id: 7, title: "Mouse", price: 19.9, thumbnail: "...", quantity: 1 }
  ]
}
```

**Do not store** `totalItems` or `totalPrice`. They are derived data (Day 5).

### 8.2 The actions

| Action | Payload | Effect |
|---|---|---|
| `ADD_ITEM` | product | Add with quantity 1, or increase if it exists |
| `REMOVE_ITEM` | id | Remove the line |
| `INCREASE` | id | quantity + 1 |
| `DECREASE` | id | quantity − 1; remove at 0 |
| `CLEAR` | – | Empty the cart |

### 8.3 The reducer

```jsx
// context/cartReducer.js
export const initialState = { items: [] };

export function cartReducer(state, action) {
  switch (action.type) {
    case "ADD_ITEM": {
      const product = action.payload;
      const exists = state.items.some((item) => item.id === product.id);

      if (exists) {
        return {
          ...state,
          items: state.items.map((item) =>
            item.id === product.id
              ? { ...item, quantity: item.quantity + 1 }
              : item
          )
        };
      }

      return {
        ...state,
        items: [
          ...state.items,
          {
            id: product.id,
            title: product.title,
            price: product.price,
            thumbnail: product.thumbnail,
            quantity: 1
          }
        ]
      };
    }

    case "REMOVE_ITEM":
      return {
        ...state,
        items: state.items.filter((item) => item.id !== action.payload)
      };

    case "INCREASE":
      return {
        ...state,
        items: state.items.map((item) =>
          item.id === action.payload
            ? { ...item, quantity: item.quantity + 1 }
            : item
        )
      };

    case "DECREASE":
      return {
        ...state,
        items: state.items
          .map((item) =>
            item.id === action.payload
              ? { ...item, quantity: item.quantity - 1 }
              : item
          )
          .filter((item) => item.quantity > 0)
      };

    case "CLEAR":
      return initialState;

    default:
      throw new Error(`Unknown action type: ${action.type}`);
  }
}
```

Notice: we store only the fields we need (`id`, `title`, `price`, `thumbnail`) instead of the whole product. It keeps `localStorage` small.

### 8.4 The Provider with persistence

```jsx
// context/CartContext.jsx
import { createContext, useContext, useEffect, useMemo, useReducer } from "react";
import { cartReducer, initialState } from "./cartReducer";

const CartContext = createContext(null);
const STORAGE_KEY = "cart-v1";

// third argument of useReducer: a function that creates the initial state
function init() {
  try {
    const saved = localStorage.getItem(STORAGE_KEY);
    return saved ? JSON.parse(saved) : initialState;
  } catch {
    return initialState;
  }
}

export function CartProvider({ children }) {
  const [state, dispatch] = useReducer(cartReducer, initialState, init);

  // persist on every change
  useEffect(() => {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(state));
  }, [state]);

  // derived data
  const totalItems = state.items.reduce((sum, item) => sum + item.quantity, 0);
  const totalPrice = state.items.reduce(
    (sum, item) => sum + item.price * item.quantity,
    0
  );

  // friendly functions so components do not need to know the action names
  const value = {
    items: state.items,
    totalItems,
    totalPrice,
    addItem: (product) => dispatch({ type: "ADD_ITEM", payload: product }),
    removeItem: (id) => dispatch({ type: "REMOVE_ITEM", payload: id }),
    increase: (id) => dispatch({ type: "INCREASE", payload: id }),
    decrease: (id) => dispatch({ type: "DECREASE", payload: id }),
    clearCart: () => dispatch({ type: "CLEAR" })
  };

  return <CartContext.Provider value={value}>{children}</CartContext.Provider>;
}

export function useCart() {
  const context = useContext(CartContext);
  if (!context) throw new Error("useCart must be used inside <CartProvider>");
  return context;
}
```

`useReducer(reducer, initialArg, init)`: if the third argument `init` is given, React calls `init(initialArg)` **once** to create the initial state (like the lazy initialiser in `useState`).

### 8.5 Wire it up

```jsx

  <ThemeProvider>
    <CartProvider>
      <App />
    </CartProvider>
  </ThemeProvider>
</BrowserRouter>
```

### 8.6 Using the cart in components

**Navbar badge**

```jsx
import { Link } from "react-router-dom";
import { useCart } from "../context/CartContext";

function CartLink() {
  const { totalItems } = useCart();

  return (
    <Link to="/cart" aria-label={`Cart with ${totalItems} items`}>
      🛒 <span className="badge">{totalItems}</span>
    </Link>
  );
}
```

**Add to cart button**

```jsx
import { useCart } from "../context/CartContext";

function AddToCartButton({ product }) {
  const { items, addItem } = useCart();
  const inCart = items.find((item) => item.id === product.id);

  return (
    <button onClick={() => addItem(product)}>
      {inCart ? `In cart (${inCart.quantity}) — add one more` : "Add to cart"}
    </button>
  );
}
```

**Cart page**

```jsx
import { Link } from "react-router-dom";
import { useCart } from "../context/CartContext";

function CartPage() {
  const { items, totalItems, totalPrice, increase, decrease, removeItem, clearCart } =
    useCart();

  if (items.length === 0) {
    return (
      <section>
        <h1>Your cart is empty</h1>
        <Link to="/products">Browse products</Link>
      </section>
    );
  }

  return (
    <section>
      <h1>Your cart ({totalItems} items)</h1>

      <ul className="cart-list">
        {items.map((item) => (
          <li key={item.id} className="cart-row">
            <img src={item.thumbnail} alt="" width="64" />
            <div>
              <h3>{item.title}</h3>
              <p>${item.price.toFixed(2)}</p>
            </div>

            <div className="qty">
              <button onClick={() => decrease(item.id)} aria-label={`Decrease ${item.title}`}>−</button>
              <span>{item.quantity}</span>
              <button onClick={() => increase(item.id)} aria-label={`Increase ${item.title}`}>+</button>
            </div>

            <strong>${(item.price * item.quantity).toFixed(2)}</strong>
            <button onClick={() => removeItem(item.id)}>Remove</button>
          </li>
        ))}
      </ul>

      <p className="total">Total: <strong>${totalPrice.toFixed(2)}</strong></p>
      <button onClick={clearCart}>Clear cart</button>
    </section>
  );
}

export default CartPage;
```

*Floating-point note:* `0.1 + 0.2` is `0.30000000000000004` in JavaScript. Use `toFixed(2)` for **display**. Real shops store prices as integers (cents) to avoid errors. Mention this in your viva.

## 9. Testing a Reducer Without React

A big benefit: the reducer is a plain function.

```js
import { cartReducer, initialState } from "./cartReducer";

const product = { id: 1, title: "Phone", price: 100, thumbnail: "x" };

let state = cartReducer(initialState, { type: "ADD_ITEM", payload: product });
console.log(state.items.length);          // 1

state = cartReducer(state, { type: "ADD_ITEM", payload: product });
console.log(state.items[0].quantity);     // 2

state = cartReducer(state, { type: "DECREASE", payload: 1 });
state = cartReducer(state, { type: "DECREASE", payload: 1 });
console.log(state.items.length);          // 0 (removed at quantity 0)
```

## 10. Splitting State and Actions (Optional Pattern)

Components that only **dispatch** actions (like `AddToCartButton`) re-render when the **state** changes, because they use the same context. You can split into two contexts:

```jsx
const CartStateContext = createContext(null);
const CartActionsContext = createContext(null);
```

and provide `items/total` through the first, and the action functions through the second (memoised with `useCallback`, Day 10). Do this only when you can measure a problem.

## 12. Common Mistakes

| Mistake | Problem | Fix |
|---|---|---|
| Using a component outside the Provider | `useCart` throws / `null` | Wrap in `main.jsx`, add the guard error |
| Mutating `state.items.push(...)` in a reducer | Re-render may not happen; bugs in StrictMode | Return new arrays |
| Side effects in a reducer (`localStorage`, `fetch`) | Reducer not pure; runs twice in StrictMode | Do them in `useEffect` or handlers |
| Storing `totalPrice` in state | Stale values | Derive |
| One giant context for everything | Everything re-renders | Several small contexts |
| Forgetting `default` in `switch` | Typos silently ignored | `throw new Error` |
| Dispatching with misspelled type | Error thrown | Use constants or helper functions |
| Using Context for data used by 2 components | Over-engineering | Props or lifting state |
| Passing `dispatch` result to `onClick` directly: `onClick={dispatch({...})}` | Runs during render | `onClick={() => dispatch({...})}` |
