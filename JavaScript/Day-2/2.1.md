# Day 2.1 — Closures and Lexical Scope

## Learning Objectives

By the end of this session, students should understand lexical scope, nested functions, closures, and how closures help maintain private data.

## 1. Lexical Scope

Lexical scope means a function can access variables defined in its surrounding scope. JavaScript determines this from where the function is written, not where it is called.

```javascript
const course = "MERN Stack";

function displayCourse() {
  console.log(course);
}

displayCourse(); // MERN Stack
```

The function can access `course` because it is declared in the outer scope.

## 2. Nested Functions

A function can be declared inside another function. The inner function can access variables from its parent function.

```javascript
function outer() {
  const message = "Hello from outer";

  function inner() {
    console.log(message);
  }

  inner();
}

outer(); // Hello from outer
```

The inner function has access to `message`, but the outer function cannot directly access variables declared only inside `inner()`.

## 3. What Is a Closure?

A closure occurs when a function retains access to variables from its surrounding lexical scope, even after the outer function has finished executing.

```javascript
function createCounter() {
  let count = 0;

  return function () {
    count++;
    console.log(count);
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
counter(); // 3
```

**How it works:**

1. `createCounter()` creates the variable `count`.
2. It returns an inner function.
3. The returned function retains access to `count`.
4. Each call updates the same retained variable.

This is a closure.

## 4. Multiple Closures

Each call to a function that creates a closure can maintain its own separate state.

```javascript
function createCounter() {
  let count = 0;

  return () => ++count;
}

const counterA = createCounter();
const counterB = createCounter();

console.log(counterA()); // 1
console.log(counterA()); // 2
console.log(counterB()); // 1
```

`counterA` and `counterB` have separate `count` variables.

## 5. Practical Use: Private Data

Closures can keep data accessible through specific functions without exposing the variable directly.

```javascript
function createBankAccount(initialBalance) {
  let balance = initialBalance;

  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount(1000);

account.deposit(500);
console.log(account.getBalance()); // 1500
console.log(account.balance);      // undefined
```

The `balance` variable is not directly exposed as an object property. This is useful for managing private state, although production financial systems require additional security and validation.
