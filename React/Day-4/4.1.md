## 2. Introduction to Forms in React

Forms allow users to enter and submit information.

Examples include:

- Login forms.
- Registration forms.
- Contact forms.
- Product creation forms.
- Search forms.
- Profile editing forms.

In React, form values are often managed using state. This allows the application to access the current values, validate them, and display feedback.

## 3. Creating a Basic Form

```jsx
function ContactForm() {
  function handleSubmit(event) {
    event.preventDefault();
    alert("Form submitted!");
  }

  return (
    <form onSubmit={handleSubmit}>
      <label>
        Name:
        <input type="text" name="name" />
      </label>

      <button type="submit">Submit</button>
    </form>
  );
}

export default ContactForm;
```

### Explanation

- `<form>` groups the input fields.
- `onSubmit` handles form submission.
- `event.preventDefault()` prevents the browser's default form submission behaviour, which would otherwise normally navigate or reload the page.
- `type="submit"` makes the button submit the form.

**Important:** Use `onSubmit` on the form rather than handling only a button click. This also supports submitting the form with Enter.

## 4. What Is a Controlled Input?

A controlled input is an input whose displayed value is controlled by React state.

### Example

```jsx
import { useState } from "react";

function NameForm() {
  const [name, setName] = useState("");

  return (
    <div>
      <label htmlFor="name">Name</label>

      <input
        id="name"
        value={name}
        onChange={(event) => setName(event.target.value)}
      />

      <p>Your name: {name}</p>
    </div>
  );
}

export default NameForm;
```

### How it works

1. The initial value of `name` is an empty string.
2. The input displays the current value of `name`.
3. When the user types, `onChange` runs.
4. `setName()` updates the state.
5. React renders the updated value.

### Why use controlled inputs?

- Values are available in state.
- Validation becomes easier.
- The UI can respond immediately to user input.
- Inputs can be cleared or updated programmatically.

## 5. Handling Multiple Form Fields

A registration form may have several fields, such as name, email, and password.

Instead of maintaining a separate state variable for every field, we can store them in one object.

```jsx
import { useState } from "react";

function RegistrationForm() {
  const [formData, setFormData] = useState({
    name: "",
    email: "",
    password: ""
  });

  function handleChange(event) {
    const { name, value } = event.target;

    setFormData((previousData) => ({
      ...previousData,
      [name]: value
    }));
  }

  return (
    <form>
      <input
        name="name"
        value={formData.name}
        onChange={handleChange}
        placeholder="Full name"
      />

      <input
        name="email"
        type="email"
        value={formData.email}
        onChange={handleChange}
        placeholder="Email"
      />

      <input
        name="password"
        type="password"
        value={formData.password}
        onChange={handleChange}
        placeholder="Password"
      />
    </form>
  );
}

export default RegistrationForm;
```

### Understanding the update

```jsx
const { name, value } = event.target;
```

This retrieves the input's `name` and current `value`.

```jsx
setFormData((previousData) => ({
  ...previousData,
  [name]: value
}));
```

This creates a new object, preserves the other fields, and updates only the field that changed.

**Common mistake:** Forgetting the spread operator can replace the entire form object with only the updated field.

## 6. Handling Form Submission

Once the user enters data, the form needs to process it.

```jsx
function handleSubmit(event) {
  event.preventDefault();

  console.log(formData);
}
```

A typical submission flow is:

1. User fills out the fields.
2. User submits the form.
3. React prevents the browser's default submission.
4. The application validates the values.
5. If valid, the application processes or sends the data.

In a real MERN application, the final step might be an HTTP request to an Express API.

## 7. Basic Form Validation

Validation checks whether the entered values meet the application's requirements.

Common validation rules include:

- Required fields must not be empty.
- Email addresses must have a valid format.
- Passwords must meet minimum length requirements.
- Confirm password must match the password.
- Numeric values must fall within an acceptable range.

### Example: Required Name

```jsx
const trimmedName = formData.name.trim();

if (!trimmedName) {
  // The name is missing.
}
```

Trimming helps prevent input consisting only of spaces from passing a required-field check.

### Example: Basic Email Validation

For an introductory exercise, students can use a simple pattern:

```jsx
const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

const isEmailValid = emailPattern.test(formData.email);
```

This is a basic format check, not proof that the email address exists. More comprehensive validation may be required for production applications.

### Example: Password Length

```jsx
const isPasswordValid = formData.password.length >= 8;
```

This example requires at least eight characters. Real applications may need additional password rules based on their security requirements.

## 8. Displaying Validation Errors

React can display error messages conditionally.

```jsx
{errors.name && <p>{errors.name}</p>}
```

If `errors.name` contains an error message, React displays it.

If there is no message, the error paragraph is not displayed.

A common pattern is to store validation messages in an object:

```jsx
const [errors, setErrors] = useState({});
```

For example:

```jsx
setErrors({
  name: "Name is required",
  email: "Enter a valid email"
});
```

In a complete form, clear or update individual errors as the user corrects the fields, or revalidate the form when it is submitted again.

## 9. Complete Example: Registration Form

Create a file named `RegistrationForm.jsx`.

```jsx
import { useState } from "react";

function RegistrationForm() {
  const [formData, setFormData] = useState({
    name: "",
    email: "",
    password: ""
  });

  const [errors, setErrors] = useState({});
  const [submitted, setSubmitted] = useState(false);

  function handleChange(event) {
    const { name, value } = event.target;

    setFormData((previousData) => ({
      ...previousData,
      [name]: value
    }));

    setErrors((previousErrors) => ({
      ...previousErrors,
      [name]: ""
    }));

    setSubmitted(false);
  }

  function handleSubmit(event) {
    event.preventDefault();

    const newErrors = {};
    const name = formData.name.trim();
    const email = formData.email.trim();
    const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

    if (!name) {
      newErrors.name = "Name is required.";
    }

    if (!email) {
      newErrors.email = "Email is required.";
    } else if (!emailPattern.test(email)) {
      newErrors.email = "Enter a valid email address.";
    }

    if (formData.password.length < 8) {
      newErrors.password =
        "Password must contain at least 8 characters.";
    }

    setErrors(newErrors);
    setSubmitted(false);

    if (Object.keys(newErrors).length === 0) {
      setSubmitted(true);

      console.log({
        name,
        email
      });
    }
  }

  return (
    <div>
      <h1>Registration Form</h1>

      <form onSubmit={handleSubmit} noValidate>
        <div>
          <label htmlFor="name">Full Name</label>

          <input
            id="name"
            name="name"
            value={formData.name}
            onChange={handleChange}
            aria-invalid={Boolean(errors.name)}
            aria-describedby={errors.name ? "name-error" : undefined}
          />

          {errors.name && (
            <p id="name-error">{errors.name}</p>
          )}
        </div>

        <div>
          <label htmlFor="email">Email</label>

          <input
            id="email"
            name="email"
            type="email"
            value={formData.email}
            onChange={handleChange}
            aria-invalid={Boolean(errors.email)}
            aria-describedby={errors.email ? "email-error" : undefined}
          />

          {errors.email && (
            <p id="email-error">{errors.email}</p>
          )}
        </div>

        <div>
          <label htmlFor="password">Password</label>

          <input
            id="password"
            name="password"
            type="password"
            value={formData.password}
            onChange={handleChange}
            aria-invalid={Boolean(errors.password)}
            aria-describedby={
              errors.password ? "password-error" : undefined
            }
          />

          {errors.password && (
            <p id="password-error">{errors.password}</p>
          )}
        </div>

        <button type="submit">Register</button>
      </form>

      {submitted && (
        <p role="status">Registration form is valid!</p>
      )}
    </div>
  );
}

export default RegistrationForm;
```

### What students should notice

- One state object stores all three form values.
- `handleChange` updates the field identified by `event.target.name`.
- `handleSubmit` validates the values.
- The form displays errors when validation fails.
- The success message appears only when the current submission passes validation.
- The example logs only the name and email. It does not log the password.

**Security note:** Client-side validation improves usability, but it is not a security boundary. The backend must validate incoming data independently.

## 10. Controlled vs Uncontrolled Inputs

| Controlled Input | Uncontrolled Input |
|---|---|
| React state controls its value. | The DOM maintains its value. |
| Uses `value` and `onChange`. | Often uses `defaultValue` or a ref. |
| Convenient for live validation. | Useful for some simpler form scenarios. |
| State provides the current value. | The value is read from the DOM when needed. |

For this internship module, students should primarily practise controlled inputs.

## 11. Common Mistakes

### Mistake 1: Forgetting `event.preventDefault()`

A normal browser form submission may navigate or reload the page, interrupting the React interaction.

### Mistake 2: Forgetting `name`

If a shared change handler reads `event.target.name`, each managed input needs the correct `name` attribute.

### Mistake 3: Incorrect State Updates

Incorrect:

```jsx
setFormData({
  name: event.target.value
});
```

This removes the other properties from the state object.

Correct:

```jsx
setFormData((previous) => ({
  ...previous,
  [event.target.name]: event.target.value
}));
```

### Mistake 4: Validating Only on the Frontend

The backend must validate the data again. Users can bypass browser-side validation.

### Mistake 5: Using Labels Incorrectly

Prefer connecting each label to its input with `htmlFor` and `id`. This improves accessibility and makes the form easier to use.
