# 20.2 — Medium Projects (7 Projects)

**Level:** Intermediate · **Time per project:** 2–4 weeks · **Goal:** Build a multi-page app with real data flows and a maintainable structure.

Read [20.0 — Project Guide and Standards](20.0-Project-Guide-and-Standards.md) before starting. Medium projects build on the same definition of done as Easy projects, with more attention to routing, forms, reusable features, testing, and API state.

### What “Medium” means here

- Several related screens and user flows.
- A public API or backend-as-a-service such as Supabase or Firebase.
- Search, filtering, sorting, or pagination.
- More than one meaningful form or data interaction.
- A feature-based folder structure and a modest automated test suite.

### Do not skip

- All four data states: loading, empty, error, and success.
- Responsive layouts, keyboard access, and useful form validation.
- A deployed URL, screenshots, setup instructions, and honest limitations in the README.
- At least 6 meaningful tests; test key user actions, not component internals.
- Small Conventional Commits throughout development.

## Project 1 — E-commerce Storefront

### Definition

A product browsing and shopping-cart app where users can search a catalogue, view product details, manage a cart, and complete a demo checkout.

### What You Will Build

Create a home/catalogue page with category filters, sorting, and product cards. A product detail route shows photos, description, price, and availability. Cart items persist between visits; the cart supports quantity changes and removal. Finish with a checkout form that validates contact and delivery information, then shows a confirmation. This is a demo checkout only—do not collect real payment details.

### Use Cases

- A shopper browses items and narrows the catalogue by category or price.
- A shopper reviews quantities and total cost before checkout.
- A developer demonstrates reusable product cards, route parameters, derived totals, and form validation.

### Suggested Features

- Catalogue search, category filters, and sort by price or rating.
- Product detail route and image fallback.
- Cart drawer or page with quantity controls and subtotal.
- Persist cart with `localStorage` or a backend account.
- Validated demo checkout and confirmation page.
- Empty-cart, loading, error, and no-results states.

### Tech Stack

React · Vite · TypeScript (recommended) · Tailwind CSS · React Router · TanStack Query · DummyJSON or Fake Store API · React Hook Form + Zod · Vitest + RTL

### References

- Data: [DummyJSON Products API](https://dummyjson.com/docs/products) · [Fake Store API](https://fakestoreapi.com/)
- Routing: [React Router](https://reactrouter.com/)
- Forms: [React Hook Form](https://react-hook-form.com/get-started) · [Zod](https://zod.dev/)
- UI patterns: [Dribbble — ecommerce](https://dribbble.com/tags/ecommerce) · [shadcn/ui](https://ui.shadcn.com/)

### Stretch Goals

- Wish list, promo-code validation, and stock indicators.
- Compare products in a side-by-side view.
- Add a real backend cart, but keep payment processing out of scope unless using a properly configured test provider.

## Project 2 — Job Board

### Definition

A job discovery app where candidates search and filter job listings, save opportunities, and track their application status.

### What You Will Build

Build a listing page with keyword, location, and job-type filters. Each result links to a detail screen showing the description, company, location, and application link. Let users save jobs and update their own application status (Interested, Applied, Interviewing, Rejected, Offer). Start with a provided local dataset or a permitted public API; if a live API is unreliable, document the data source and use a local fixture for predictable demos.

### Use Cases

- A candidate finds jobs matching a role, location, and work arrangement.
- A candidate saves interesting roles and keeps an application pipeline.
- A reviewer tests filters, URL query parameters, empty results, and persistent state.

### Suggested Features

- Search and combine filters; show active filters and a clear-all action.
- Sort by newest or relevance; paginate results.
- Job detail route with an external apply link.
- Saved jobs and status updates persisted locally or per authenticated user.
- Responsive list/detail layout and an accessible filter panel.
- Clear empty, loading, and API-failure states.

### Tech Stack

React · Vite · TypeScript · Tailwind CSS · React Router · TanStack Query · Local JSON fixture or approved job API · Vitest + RTL

### References

- Search patterns: [React Router — URL Values](https://reactrouter.com/start/library/url-values)
- State and fetching: [TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)
- Accessibility: [WAI-ARIA — Listbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) (use native controls when they fit)
- UI inspiration: [Dribbble — job board](https://dribbble.com/tags/job-board) · [Mobbin](https://mobbin.com/)

### Stretch Goals

- User profile with skills and preferred locations.
- Resume upload UI with file type/size checks (do not store sensitive files without a secure backend).
- Saved-search alerts using a mock notification flow.

## Project 3 — Learning Management Dashboard

### Definition

A learning dashboard where a student browses courses, tracks lessons, and resumes learning from saved progress.

### What You Will Build

Create a course catalogue with topic and level filters. Course detail screens show modules and lessons. A student can mark a lesson complete, see progress summaries, and continue from the next incomplete lesson. Store progress locally for a frontend-only version, or in a user-scoped database if you add authentication. Use original or openly licensed learning content.

### Use Cases

- A learner discovers a course at the right level and subject.
- A learner resumes a lesson and sees progress without recounting completed work.
- An instructor or reviewer sees course completion at a glance.

### Suggested Features

- Catalogue, course detail, lesson view, and student dashboard routes.
- Progress indicator derived from completed lessons.
- Resume-learning action and completed lesson state.
- Search, category filters, and sort by duration or level.
- Accessible navigation between modules and lessons.
- Persist progress; explain that local browser data is not an account backup.

### Tech Stack

React · Vite · TypeScript · Tailwind CSS · React Router · Context or Zustand for UI state · Supabase (optional) · Vitest + RTL

### References

- Database and auth: [Supabase Docs](https://supabase.com/docs)
- Route layouts: [React Router — Nested Routes](https://reactrouter.com/start/library/routing)
- Progress patterns: [Dribbble — learning dashboard](https://dribbble.com/tags/learning-dashboard) · [Mobbin](https://mobbin.com/)
- Accessibility: [WAI — Disclosure Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)

### Stretch Goals

- Quiz after a module with score history.
- Course bookmarks and a weekly learning goal.
- Admin course editor with draft and published states.

## Project 4 — Event Discovery and Booking

### Definition

An event listing app where visitors discover events by date and category, inspect event details, and reserve a place in a demo flow.

### What You Will Build

Make a browsable event catalogue with date, category, and location filters. The detail page shows schedule, venue, accessibility information, and remaining demo capacity. A booking form collects only the minimum demo information and returns a confirmation screen. Use mock data or a backend you control; never imply that a real ticket is issued unless the backend actually handles it.

### Use Cases

- A visitor finds an event happening in a preferred date range.
- A visitor checks venue and accessibility details before reserving.
- An organizer tests how capacity and confirmation states appear to users.

### Suggested Features

- Event list, detail, and confirmation routes.
- Filters by date, category, free/paid label, and location.
- Validated reservation form and booking summary.
- Time-zone-aware date display and clear cancellation policy text.
- Capacity and duplicate-submission handling in the demo.
- Loading, no-events, error, and confirmation states.

### Tech Stack

React · Vite · TypeScript · Tailwind CSS · React Router · TanStack Query · React Hook Form + Zod · Supabase or mock API · Vitest + RTL

### References

- Date handling: [date-fns](https://date-fns.org/docs/Getting-Started)
- Validation: [Zod](https://zod.dev/) · [React Hook Form](https://react-hook-form.com/)
- UI inspiration: [Dribbble — event app](https://dribbble.com/tags/event-app) · [UI Patterns](https://ui-patterns.com/)
- Accessibility: [WAI — Date Picker Dialog Example](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)

### Stretch Goals

- Calendar view and add-to-calendar file.
- Organizer dashboard for creating and editing events.
- QR-code mock ticket after confirmation.

## Project 5 — Travel Planner

### Definition

A trip planning app where users build an itinerary, organize activities by day, and keep notes and travel details together.

### What You Will Build

Users create a trip with destination and dates, then add activities to each day. Each activity has a time, title, location, and note. A summary shows the itinerary in chronological order. Begin with local data and browser storage; optionally add authentication and a database for sharing across devices. Do not depend on paid booking APIs for the core experience.

### Use Cases

- A traveler organizes plans for a multi-day trip.
- A group member checks the schedule and location details on a phone.
- A reviewer sees date validation, editable nested data, and responsive navigation.

### Suggested Features

- Create, edit, and delete trips.
- Day-by-day itinerary with add/edit/remove activity.
- Sort activities by time and validate trip date ranges.
- Trip overview with destination, date, and activity count.
- Persist data and include a useful first-trip empty state.
- Mobile-friendly timeline and keyboard-accessible controls.

### Tech Stack

React · Vite · TypeScript · Tailwind CSS · React Router · `date-fns` · `localStorage` or Supabase · Vitest + RTL

### References

- Date utilities: [date-fns](https://date-fns.org/docs/Getting-Started)
- Database option: [Supabase Docs](https://supabase.com/docs)
- UI inspiration: [Dribbble — travel planner](https://dribbble.com/tags/travel-planner) · [Behance](https://www.behance.net/)
- Maps: [OpenStreetMap](https://www.openstreetmap.org/) (check tile usage policy before embedding)

### Stretch Goals

- Map view for itinerary locations.
- Shared read-only trip link.
- Estimated daily budget and currency formatting.

## Project 6 — Customer Support Ticket Portal

### Definition

A help-desk portal where a user submits a support request and tracks its status, while a demo support agent can update ticket status and add replies.

### What You Will Build

Build a ticket creation form with subject, category, and description. A customer sees their ticket list and details. A simple role switch or seeded demo account can show an agent view to assign priority and update status. Use Supabase/Firebase or a mock API. Make roles and data boundaries explicit; a frontend-only role switch is a demonstration, not secure authorization.

### Use Cases

- A customer reports an issue and follows its progress.
- A support agent prioritizes and replies to open requests.
- A reviewer explores forms, status filters, role-based views, and data permissions.

### Suggested Features

- Ticket create/list/detail routes.
- Status filters: Open / In progress / Resolved.
- Priority, category, and last-updated information.
- Reply thread with chronological messages.
- Input validation, confirmation, and duplicate-submit protection.
- Backend authorization rules if multiple real users can access the app.

### Tech Stack

React · Vite · TypeScript · Tailwind CSS · React Router · React Hook Form + Zod · Supabase or Firebase · Vitest + RTL

### References

- Backend/auth: [Supabase Auth](https://supabase.com/docs/guides/auth) · [Firebase Authentication](https://firebase.google.com/docs/auth)
- Security rules: [Supabase Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)
- UI inspiration: [Dribbble — help desk](https://dribbble.com/tags/help-desk) · [shadcn/ui](https://ui.shadcn.com/)
- Testing: [Testing Library — User Event](https://testing-library.com/docs/user-event/intro/)

### Stretch Goals

- Search tickets by ID or subject.
- File attachment metadata and a safe upload flow.
- Agent activity history and response-time summary.

## Project 7 — Personal Portfolio CMS

### Definition

A portfolio website with a private editing workflow for managing projects, biography, and contact details, without editing source files for every content change.

### What You Will Build

Create a polished public portfolio with project cards and detail pages. Add an editor route for adding, editing, reordering, and archiving projects. Use a real backend with authentication for the editor, or clearly label a local-only demo. Do not rely on hiding an admin link as access control. Add a contact form that validates input; use a backend service if it must deliver messages.

### Use Cases

- A developer presents work, skills, and contact information to recruiters.
- The portfolio owner updates project details through an editor.
- A reviewer evaluates routing, form state, responsive design, and accessible content.

### Suggested Features

- Public home, project list, project detail, and contact routes.
- Editor for project title, summary, technologies, links, and images.
- Draft/published state and preview before publishing.
- Authenticated editor if using a backend; backend rules enforce permissions.
- Metadata and descriptive page titles for sharing.
- Useful not-found and form submission states.

### Tech Stack

React · Vite · TypeScript · Tailwind CSS · React Router · Supabase/Firebase or local mock data · React Hook Form + Zod · Vitest + RTL

### References

- Metadata: [React Router — `meta`](https://reactrouter.com/how-to/route-module#meta)
- Backend: [Supabase Docs](https://supabase.com/docs) · [Firebase Docs](https://firebase.google.com/docs)
- UI inspiration: [Land-book](https://land-book.com/) · [Awwwards](https://www.awwwards.com/) · [Dribbble — portfolio](https://dribbble.com/tags/portfolio)
- Accessibility: [WAI — Forms Tutorial](https://www.w3.org/WAI/tutorials/forms/)

### Stretch Goals

- Markdown-based project descriptions with safe rendering.
- Upload project images to a storage service with size/type validation.
- Add a lightweight analytics dashboard with privacy-respecting metrics.

## Medium Level — Submission Checklist

- [ ] All Easy-level expectations from [20.1](20.1-Easy-Projects.md#easy-level--submission-checklist).
- [ ] Multiple routes work on direct load and refresh.
- [ ] Search/filter/sort state is reflected in the URL or documented.
- [ ] Forms have validation, success feedback, and error handling.
- [ ] Backend access controls are enforced by the backend, not just the UI.
- [ ] At least 6 meaningful tests cover key flows and edge cases.
- [ ] Feature-based structure is used where it makes the code clearer.
- [ ] README explains data source, environment setup, and demo limitations.
