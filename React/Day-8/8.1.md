## 3. Client-Side vs Server-Side

Where should the work of searching, sorting and paginating happen?

| | Client-side | Server-side |
|---|---|---|
| How | Fetch **all** data once, then process it in the browser | Send search/sort/page to the API; fetch only the needed part |
| Good for | Small data (up to a few hundred items) | Large data (thousands+) |
| Pros | Instant filtering, simple | Fast first load, small responses |
| Cons | Slow first load for big data | Every change needs a request (loading states, race conditions) |

DummyJSON has **194 products**. That is small, so we will use **client-side processing**: fetch everything once with `limit=0`, then calculate the visible products. Later, when you build your own backend (Week 7+), you will learn the server-side approach (`?page=2&limit=10&search=phone`).

```js
// Fetch all products once
GET https://dummyjson.com/products?limit=0
// Fetch category names
GET https://dummyjson.com/products/category-list
```

## 4. The Data Pipeline Idea

Think of the list page as a pipeline. The output of each step is the input of the next:

```text
all products
   │  1. search     (title contains text)
   ▼
   │  2. category   (category equals selected)
   ▼
   │  3. sort       (price, rating, title)
   ▼
   │  4. paginate   (slice for current page)
   ▼
visible products
```

All steps are **derived data** (Day 5): we store only the **controls** (search, category, sort, page) and the **raw data**. We calculate everything else while rendering.

### 4.1 Search

```js
const normalized = search.trim().toLowerCase();

const searched = normalized
  ? products.filter((product) =>
      product.title.toLowerCase().includes(normalized)
    )
  : products;
```

Extra: search in several fields.

```js
products.filter((p) =>
  [p.title, p.brand, p.category].join(" ").toLowerCase().includes(normalized)
);
```

*Note: some products have no `brand`. `[undefined].join(" ")` gives an empty string, so it is safe. Writing `p.brand.toLowerCase()` would crash.*

### 4.2 Category filter

```js
const filtered = category
  ? searched.filter((product) => product.category === category)
  : searched;
```

### 4.3 Sorting

Never call `.sort()` directly on state or props, because it **mutates** the array. Copy first.

```js
function sortProducts(list, sort) {
  const copy = [...list];

  switch (sort) {
    case "price-asc":
      return copy.sort((a, b) => a.price - b.price);
    case "price-desc":
      return copy.sort((a, b) => b.price - a.price);
    case "rating-desc":
      return copy.sort((a, b) => b.rating - a.rating);
    case "title-asc":
      return copy.sort((a, b) => a.title.localeCompare(b.title));
    default:
      return copy;          // original API order
  }
}
```

- Numbers: `a - b` ascending, `b - a` descending.
- Text: `a.localeCompare(b)`.

### 4.4 Pagination

```js
const PAGE_SIZE = 12;

const totalItems = sorted.length;
const totalPages = Math.max(1, Math.ceil(totalItems / PAGE_SIZE));

const currentPage = Math.min(Math.max(page, 1), totalPages);   // clamp

const start = (currentPage - 1) * PAGE_SIZE;
const visible = sorted.slice(start, start + PAGE_SIZE);
```

Example with 30 items and a page size of 12:

| Page | start | `slice(start, start + 12)` |
|---|---|---|
| 1 | 0 | items 0–11 |
| 2 | 12 | items 12–23 |
| 3 | 24 | items 24–29 (6 items) |

`Math.ceil(30 / 12) = 3` pages.

**Clamping** protects against invalid URLs such as `?page=999` or `?page=-4` or `?page=abc`.

## 5. Control State in the URL

We will keep four controls in the URL:

```text
/products?search=phone&category=smartphones&sort=price-asc&page=2
```

### 5.1 A reusable helper

```jsx
import { useSearchParams } from "react-router-dom";

function useListParams() {
  const [searchParams, setSearchParams] = useSearchParams();

  const params = {
    search: searchParams.get("search") ?? "",
    category: searchParams.get("category") ?? "",
    sort: searchParams.get("sort") ?? "",
    page: Number(searchParams.get("page")) || 1
  };

  // update one or more params; empty values are removed
  function updateParams(changes, { resetPage = true } = {}) {
    const next = new URLSearchParams(searchParams);

    Object.entries(changes).forEach(([key, value]) => {
      if (value === "" || value === null || value === undefined) next.delete(key);
      else next.set(key, String(value));
    });

    if (resetPage && !("page" in changes)) next.delete("page");

    setSearchParams(next);
  }

  return [params, updateParams];
}
```

### 5.2 Why reset the page?

If the user is on **page 5** and then types a search that has only 8 results, page 5 does not exist. Every time **search, category or sort** change, go back to page 1. That is what `resetPage` does: it deletes the `page` parameter.

### 5.3 Using it

```jsx
const [{ search, category, sort, page }, updateParams] = useListParams();

updateParams({ category: "smartphones" });   // page resets automatically
updateParams({ page: 3 }, { resetPage: false });
```

> **Note:** `Number("abc")` is `NaN`, and `NaN || 1` is `1`. That is why we wrote `Number(...) || 1`.

## 6. Debouncing

When the user types `smartphone`, the search runs 10 times (once per letter). For client-side filtering this is cheap, but:

- Updating the URL on every keystroke fills the browser history.
- With server-side search, each keystroke would send a request.

**Debounce** = wait until the user **stops typing** for a short time (for example 400 ms), then run the action once.

```text
typing:   s  sm  sma  smar  smart  ...      (pause 400ms)
action:   ✗   ✗   ✗    ✗     ✗                ✓ (only the last value)
```

### 6.1 The `useDebounce` hook

```jsx
// hooks/useDebounce.js
import { useEffect, useState } from "react";

export function useDebounce(value, delay = 400) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);   // cancel if value changes again
  }, [value, delay]);

  return debounced;
}
```

How it works:

1. The user types → `value` changes → effect starts a timer.
2. The user types again before the timer ends → **cleanup** clears the old timer and a new one starts.
3. When the user pauses → the timer finishes → `debounced` updates.

### 6.2 Search box with local draft + debounced URL update

```jsx
function SearchBox({ value, onSearch }) {
  const [draft, setDraft] = useState(value);
  const debounced = useDebounce(draft, 400);

  // push the debounced value to the URL
  useEffect(() => {
    if (debounced !== value) onSearch(debounced);
  }, [debounced]);   // eslint-disable-line react-hooks/exhaustive-deps

  return (
    <input
      type="search"
      value={draft}
      onChange={(event) => setDraft(event.target.value)}
      placeholder="Search products..."
      aria-label="Search products"
    />
  );
}
```

- The input is **controlled by `draft`**, so typing feels instant.
- The URL and the list react only to the **debounced** value.
- The `eslint-disable` comment is acceptable here because we intentionally want the effect to run only when `debounced` changes. Discuss with your trainer why that is safe in this case, and how to avoid the comment (a "key" or event-based approach: see the stretch goal in the task file).

**Simpler alternative (also correct):** keep `draft` in the page and compute filtering from `debounced`; update the URL only on submit or on blur. Choose the version you can explain.

## 7. Reusable `Pagination` Component

```jsx
// components/Pagination.jsx
function Pagination({ page, totalPages, onPageChange }) {
  if (totalPages <= 1) return null;

  const pages = getPageNumbers(page, totalPages);

  return (
    <nav className="pagination" aria-label="Pagination">
      <button onClick={() => onPageChange(page - 1)} disabled={page === 1}>
        ← Previous
      </button>

      {pages.map((item, index) =>
        item === "..." ? (
          <span key={`dots-${index}`} aria-hidden="true">…</span>
        ) : (
          <button
            key={item}
            onClick={() => onPageChange(item)}
            aria-current={item === page ? "page" : undefined}
            className={item === page ? "current" : ""}
          >
            {item}
          </button>
        )
      )}

      <button onClick={() => onPageChange(page + 1)} disabled={page === totalPages}>
        Next →
      </button>
    </nav>
  );
}

// Show: 1 ... 4 5 6 ... 20
function getPageNumbers(page, total) {
  if (total <= 7) return Array.from({ length: total }, (_, i) => i + 1);

  const pages = [1];
  const start = Math.max(2, page - 1);
  const end = Math.min(total - 1, page + 1);

  if (start > 2) pages.push("...");
  for (let i = start; i <= end; i++) pages.push(i);
  if (end < total - 1) pages.push("...");

  pages.push(total);
  return pages;
}

export default Pagination;
```

Points to explain:

- `aria-current="page"` tells screen readers which page is active.
- `Array.from({ length: total }, (_, i) => i + 1)` creates `[1, 2, ..., total]`.
- The component is **presentational**: it does not know about URLs or data. It only receives `page`, `totalPages` and a callback. This makes it reusable in any list.

## 8. Filters UI

```jsx
// components/ProductFilters.jsx
function ProductFilters({ category, sort, categories, onCategoryChange, onSortChange }) {
  return (
    <div className="filters">
      <label>
        Category
        <select value={category} onChange={(e) => onCategoryChange(e.target.value)}>
          <option value="">All categories</option>
          {categories.map((name) => (
            <option key={name} value={name}>
              {formatCategory(name)}
            </option>
          ))}
        </select>
      </label>

      <label>
        Sort by
        <select value={sort} onChange={(e) => onSortChange(e.target.value)}>
          <option value="">Default</option>
          <option value="price-asc">Price: low to high</option>
          <option value="price-desc">Price: high to low</option>
          <option value="rating-desc">Rating: high to low</option>
          <option value="title-asc">Name: A to Z</option>
        </select>
      </label>
    </div>
  );
}

// "mens-shirts" → "Mens Shirts"
function formatCategory(slug) {
  return slug
    .split("-")
    .map((word) => word.charAt(0).toUpperCase() + word.slice(1))
    .join(" ");
}

export default ProductFilters;
```

Notice: the `<select>` is a **controlled** element, exactly like an `<input>`.

## 9. The Complete List Page

### 9.1 Services

```js
// services/productService.js
import { request } from "./apiClient";

export function getAllProducts({ signal } = {}) {
  return request("/products?limit=0", { signal });
}

export function getCategories({ signal } = {}) {
  return request("/products/category-list", { signal });
}
```

### 9.2 A small helper to run two requests

```jsx
useEffect(() => {
  const controller = new AbortController();

  async function load() {
    try {
      setLoading(true);
      setError("");

      // run both requests at the same time
      const [productData, categoryData] = await Promise.all([
        getAllProducts({ signal: controller.signal }),
        getCategories({ signal: controller.signal })
      ]);

      setProducts(productData.products);
      setCategories(categoryData);
    } catch (err) {
      if (err.name !== "AbortError") setError(err.message);
    } finally {
      if (!controller.signal.aborted) setLoading(false);
    }
  }

  load();
  return () => controller.abort();
}, [reloadKey]);
```

`Promise.all([a, b])` waits for **both** requests and runs them **in parallel**, which is faster than awaiting them one after another. If one fails, the whole `Promise.all` fails.

### 9.3 `ProductsPage.jsx`

```jsx
import { useEffect, useState } from "react";
import { getAllProducts, getCategories } from "../services/productService";
import { useListParams } from "../hooks/useListParams";
import SearchBox from "../components/SearchBox";
import ProductFilters from "../components/ProductFilters";
import ProductCard from "../components/ProductCard";
import Pagination from "../components/Pagination";
import Loader from "../components/Loader";
import ErrorMessage from "../components/ErrorMessage";
import EmptyState from "../components/EmptyState";

const PAGE_SIZE = 12;

function ProductsPage() {
  const [{ search, category, sort, page }, updateParams] = useListParams();

  const [products, setProducts] = useState([]);
  const [categories, setCategories] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");
  const [reloadKey, setReloadKey] = useState(0);

  // ... the useEffect from section 9.2 ...

  // ---------- derived data (the pipeline) ----------
  const normalized = search.trim().toLowerCase();

  const searched = normalized
    ? products.filter((p) => p.title.toLowerCase().includes(normalized))
    : products;

  const filtered = category
    ? searched.filter((p) => p.category === category)
    : searched;

  const sorted = sortProducts(filtered, sort);

  const totalPages = Math.max(1, Math.ceil(sorted.length / PAGE_SIZE));
  const currentPage = Math.min(Math.max(page, 1), totalPages);
  const start = (currentPage - 1) * PAGE_SIZE;
  const visible = sorted.slice(start, start + PAGE_SIZE);

  // ---------- rendering ----------
  if (loading) return <Loader text="Loading products..." />;
  if (error) {
    return <ErrorMessage message={error} onRetry={() => setReloadKey((k) => k + 1)} />;
  }

  return (
    <section>
      <h1>Products</h1>

      <SearchBox value={search} onSearch={(value) => updateParams({ search: value })} />

      <ProductFilters
        category={category}
        sort={sort}
        categories={categories}
        onCategoryChange={(value) => updateParams({ category: value })}
        onSortChange={(value) => updateParams({ sort: value })}
      />

      <p aria-live="polite">
        Showing {visible.length} of {sorted.length} products
      </p>

      {visible.length === 0 ? (
        <EmptyState message="No products match your filters." />
      ) : (
        <div className="grid">
          {visible.map((product) => (
            <ProductCard key={product.id} product={product} />
          ))}
        </div>
      )}

      <Pagination
        page={currentPage}
        totalPages={totalPages}
        onPageChange={(next) => updateParams({ page: next }, { resetPage: false })}
      />
    </section>
  );
}

export default ProductsPage;
```

Observe:

- **State:** `products`, `categories`, `loading`, `error` (raw data and status) plus the URL (controls).
- **Derived:** `searched`, `filtered`, `sorted`, `visible`, `totalPages`.
- No `useEffect` is needed for filtering. Filtering is **calculation**, not a side effect (Day 2: "Mistake 3: Using `useEffect` for simple calculations").

### 9.4 Clear filters button

```jsx
const hasFilters = search || category || sort;

{hasFilters && (
  <button onClick={() => updateParams({ search: "", category: "", sort: "" })}>
    Clear filters
  </button>
)}
```

(Remember that the `SearchBox` keeps its own `draft`. To make **Clear** also empty the box, give it a `key`: `<SearchBox key={search} ... />`. When `key` changes, React re-creates the component and its `draft` state is initialised from the new `value`.)

## 10. Responsive Layout and CSS Modules

### 10.1 Responsive grid with CSS Grid

```css
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 16px;
}
```

- `auto-fill` creates as many columns as fit.
- `minmax(220px, 1fr)` means each card is at least 220px and shares the leftover space.
- No media queries are needed. The columns adapt automatically.

### 10.2 Media queries for the rest

```css
.filters { display: flex; gap: 16px; flex-wrap: wrap; }

@media (max-width: 600px) {
  .filters { flex-direction: column; }
  .pagination button { padding: 6px 8px; }
}
```

Use a **mobile-first** approach: write the small-screen styles first, then add `@media (min-width: ...)` for larger screens.

### 10.3 CSS Modules

Global CSS (`index.css`) has a problem: class names are shared. `.card` in one file can accidentally change `.card` somewhere else.

**CSS Modules** make class names **local to the component**. Name the file `*.module.css`:

```css
/* ProductCard.module.css */
.card {
  border: 1px solid #e5e7eb;
  border-radius: 12px;
  padding: 12px;
  background: #fff;
}

.price {
  font-weight: 700;
  color: #16a34a;
}
```

```jsx
// ProductCard.jsx
import styles from "./ProductCard.module.css";

function ProductCard({ product }) {
  return (
    <article className={styles.card}>
      <h3>{product.title}</h3>
      <p className={styles.price}>${product.price}</p>
    </article>
  );
}
```

Vite renames the class to something unique, for example `_card_x7a2k_1`. Two components can both have `.card` without conflict.

Combine classes:

```jsx
<button className={`${styles.button} ${isActive ? styles.active : ""}`}>
```

Vite supports CSS Modules out of the box. You may also use **Tailwind CSS** (the curriculum allows either). If your team already knows Tailwind, use it, but keep one styling approach per project.

## 11. Performance Note (preview for Day 10)

Sorting and filtering 194 items on every render is cheap. When the list becomes very large (thousands), we use `useMemo` to cache the result. We will learn this on **Day 10**. Do not use `useMemo` today: first understand the problem it solves.

## 12. Common Mistakes

| Mistake | Problem | Fix |
|---|---|---|
| `products.sort(...)` | Mutates state/props | `[...products].sort(...)` |
| Not resetting `page` | Empty page after a filter | Delete `page` when other controls change |
| Storing `filteredProducts` in state | Out-of-sync data | Derive it |
| `p.brand.toLowerCase()` for missing fields | Crash | Guard (`p.brand?.toLowerCase()`) |
| No clamping of `page` | `?page=999` shows empty page | `Math.min/Math.max` |
| Debounce without cleanup | Many timers, wrong value | `return () => clearTimeout(timer)` |
| Comparing strings with `-` | `NaN` | Use `localeCompare` |
| Trusting `Number(page)` | `NaN` | `Number(x) || 1` |
| Forgetting the `key` in list items | Warning and bugs | `key={product.id}` |
| Fixed pixel widths | Layout breaks on mobile | `minmax`, `flex-wrap`, `%` |
