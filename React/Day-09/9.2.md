### Section B — Expected Points

1. Passing props through components that do not use them, only to reach a deeper component. For example, `App` passes `cartCount` to `Layout`, `Navbar` and finally `CartBadge`.
2. Create (`createContext`), provide (`<Context.Provider value={...}>`), consume (`useContext(Context)`).
3. `useState` suits simple, independent values; `useReducer` suits complex state with many related updates and centralised logic. A reducer is also easier to test.
4. Pure functions return the same output for the same input and have no side effects. Benefits: predictable, easy to test, safe with React StrictMode (which may call reducers twice).
5. Any change re-renders every consumer; unrelated parts of the app update unnecessarily. It also couples unrelated features. Use several small contexts.

Sample reducer for Exercise 2:

```js
export function todoReducer(state, action) {
  switch (action.type) {
    case "ADD":
      return [...state, action.payload];                 // payload: { id, title, done:false }
    case "TOGGLE":
      return state.map((t) => (t.id === action.payload ? { ...t, done: !t.done } : t));
    case "DELETE":
      return state.filter((t) => t.id !== action.payload);
    case "CLEAR_COMPLETED":
      return state.filter((t) => !t.done);
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}
```

### Section E — Problems and Fix

Problems:

1. `createContext()` with no default and no guard; consumers receive `undefined` without a Provider.
2. `state.items.push` mutates the state.
3. Returning the same `state` object means React sees no change.
4. `localStorage.setItem` is a side effect inside a reducer.
5. The `"REMOVE"` case returns an array, not the state object (`{ items }`), breaking the state shape.
6. No `default` case; unknown actions return `undefined`.
7. `value={state, dispatch}` is invalid JSX/JS (comma operator); pass an object `value={{ ... }}`.
8. `total` is stored in state (derived data).
9. `onClick={dispatch({...})}` runs during render and `dispatch` is not in scope there; it must come from `useCart()` and be wrapped in an arrow function.
10. `useCart` does not validate the Provider.

Corrected version:

```jsx
import { createContext, useContext, useEffect, useReducer } from "react";

const CartContext = createContext(null);

function cartReducer(state, action) {
  switch (action.type) {
    case "ADD":
      return { ...state, items: [...state.items, action.payload] };
    case "REMOVE":
      return { ...state, items: state.items.filter((i) => i.id !== action.payload) };
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}

function init() {
  try {
    return JSON.parse(localStorage.getItem("cart")) ?? { items: [] };
  } catch {
    return { items: [] };
  }
}

export function CartProvider({ children }) {
  const [state, dispatch] = useReducer(cartReducer, undefined, init);

  useEffect(() => {
    localStorage.setItem("cart", JSON.stringify(state));
  }, [state]);

  const total = state.items.reduce((sum, i) => sum + i.price, 0);

  return (
    <CartContext.Provider value={{ items: state.items, total, dispatch }}>
      {children}
    </CartContext.Provider>
  );
}

export function useCart() {
  const context = useContext(CartContext);
  if (!context) throw new Error("useCart must be used inside <CartProvider>");
  return context;
}

// Somewhere else
function AddButton({ product }) {
  const { dispatch } = useCart();
  return (
    <button onClick={() => dispatch({ type: "ADD", payload: product })}>Add</button>
  );
}
```
