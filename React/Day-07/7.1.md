## 3. What Is a Single Page Application?

In a traditional website, every link loads a **new HTML file** from the server and the browser reloads.

In a React **SPA**:

1. The browser loads **one** `index.html` and your JavaScript bundle once.
2. When the user clicks a link, React Router **changes the URL** without reloading the page.
3. React renders the **component** that matches the new URL.

```text
URL:  /products/5
        │
        ▼
  React Router looks at the route table
        │
        ▼
  Renders <ProductDetailsPage /> with id = 5
```

Benefits: fast navigation, state is not lost between pages (for example, a cart in a parent), and a smooth, app-like experience.

## 4. Installing React Router

In your Vite project:

```bash
npm install react-router-dom
```

Check `package.json` to see the installed version. The examples in this file work with React Router v6 and v7 (`react-router-dom` still works in v7).

### Set up the router in `main.jsx`

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter } from "react-router-dom";
import App from "./App.jsx";
import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>
);
```

`BrowserRouter` gives the whole app access to the browser's URL. Hooks and components from React Router only work **inside** it.

## 5. Your First Routes

```jsx
// App.jsx
import { Routes, Route } from "react-router-dom";
import HomePage from "./pages/HomePage";
import AboutPage from "./pages/AboutPage";
import ProductsPage from "./pages/ProductsPage";

function App() {
  return (
    <Routes>
      <Route path="/" element={<HomePage />} />
      <Route path="/about" element={<AboutPage />} />
      <Route path="/products" element={<ProductsPage />} />
    </Routes>
  );
}

export default App;
```

```jsx
// pages/HomePage.jsx
function HomePage() {
  return <h1>Welcome to My Shop</h1>;
}
export default HomePage;
```

Try it: open `http://localhost:5173/about`.

### Pages vs components

- A **page** is a component connected to a route (`ProductsPage`).
- A **component** is a smaller reusable piece (`ProductCard`).
- Keep pages in `src/pages` and reusable pieces in `src/components`.

## 6. Navigation

### 6.1 Never use `<a href>` for internal links

```jsx
<a href="/about">About</a>   // ❌ full page reload, all state lost
```

### 6.2 `Link`

```jsx
import { Link } from "react-router-dom";

<Link to="/about">About</Link>   // ✅ no reload
```

### 6.3 `NavLink` (for menus)

`NavLink` knows whether it is the current page and adds the class `active` automatically.

```jsx
import { NavLink } from "react-router-dom";

function Navbar() {
  return (
    <nav className="navbar">
      <NavLink to="/" end>Home</NavLink>
      <NavLink to="/products">Products</NavLink>
      <NavLink to="/about">About</NavLink>
    </nav>
  );
}
```

```css
.navbar a { padding: 8px 12px; text-decoration: none; color: #333; }
.navbar a.active { font-weight: 700; color: #2563eb; border-bottom: 2px solid #2563eb; }
```

The `end` prop on the Home link prevents `/` from being "active" on every page (because every path starts with `/`).

### 6.4 Programmatic navigation: `useNavigate`

Use it when you need to navigate from code (after a form submit, after login).

```jsx
import { useNavigate } from "react-router-dom";

function AddProductForm() {
  const navigate = useNavigate();

  async function handleSubmit(event) {
    event.preventDefault();
    // ... save the product ...
    navigate("/products");        // go to a page
  }

  return (
    <form onSubmit={handleSubmit}>
      {/* fields */}
      <button type="submit">Save</button>
      <button type="button" onClick={() => navigate(-1)}>Back</button>
    </form>
  );
}
```

- `navigate("/path")` pushes a new page.
- `navigate("/path", { replace: true })` replaces the current history entry (the Back button will not return to this page; useful after login).
- `navigate(-1)` goes back.

### 6.5 Redirect in JSX: `<Navigate>`

```jsx
import { Navigate } from "react-router-dom";

<Route path="/home" element={<Navigate to="/" replace />} />
```

## 7. Layout Routes and `Outlet`

Most pages share a navbar and footer. Do not repeat them on every page. Create a **layout route**.

```jsx
// layouts/MainLayout.jsx
import { Outlet } from "react-router-dom";
import Navbar from "../components/Navbar";
import Footer from "../components/Footer";

function MainLayout() {
  return (
    <>
      <Navbar />
      <main className="container">
        <Outlet />     {/* the matched child page appears here */}
      </main>
      <Footer />
    </>
  );
}

export default MainLayout;
```

```jsx
// App.jsx
function App() {
  return (
    <Routes>
      <Route element={<MainLayout />}>
        <Route index element={<HomePage />} />
        <Route path="products" element={<ProductsPage />} />
        <Route path="products/:productId" element={<ProductDetailsPage />} />
        <Route path="about" element={<AboutPage />} />
        <Route path="*" element={<NotFoundPage />} />
      </Route>
    </Routes>
  );
}
```

Explanation:

- A `<Route>` **without** a `path` that has an `element` is a **layout route**. It wraps all its children.
- `<Outlet />` is the "hole" where the matched child route renders.
- `index` means "the default child when the URL matches the parent exactly" (here `/`).
- Child paths are written **relative** (`products`, not `/products`) when nested.

```text
URL /products/5
   MainLayout
   ├── Navbar
   ├── <Outlet/>  →  ProductDetailsPage
   └── Footer
```

You can have more than one layout, for example `AuthLayout` for login/register (no navbar) and `DashboardLayout` for admin pages.

## 8. Dynamic Routes and `useParams`

Define a variable part of the URL with a colon:

```jsx
<Route path="products/:productId" element={<ProductDetailsPage />} />
```

The URL `/products/5` matches, and `productId` is `"5"`.

```jsx
// pages/ProductDetailsPage.jsx
import { useParams } from "react-router-dom";

function ProductDetailsPage() {
  const { productId } = useParams();

  return <h1>Product #{productId}</h1>;
}
```

**Important:** URL params are always **strings**. Use `Number(productId)` if you need a number (the API accepts the string in the URL anyway).

### Complete details page with fetching

```jsx
import { useEffect, useState } from "react";
import { Link, useParams } from "react-router-dom";
import { getProductById } from "../services/productService";
import Loader from "../components/Loader";
import ErrorMessage from "../components/ErrorMessage";

function ProductDetailsPage() {
  const { productId } = useParams();
  const [product, setProduct] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        setLoading(true);
        setError("");
        const data = await getProductById(productId, { signal: controller.signal });
        setProduct(data);
      } catch (err) {
        if (err.name !== "AbortError") setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }

    load();
    return () => controller.abort();
  }, [productId]);   // URL changes → fetch again

  if (loading) return <Loader />;
  if (error) return <ErrorMessage message={error} />;

  return (
    <article className="details">
      <Link to="/products">← Back to products</Link>
      <h1>{product.title}</h1>
      <img src={product.thumbnail} alt={product.title} width="240" />
      <p>{product.description}</p>
      <p><strong>${product.price}</strong> · ⭐ {product.rating}</p>
    </article>
  );
}

export default ProductDetailsPage;
```

## 9. Query Parameters with `useSearchParams`

URL: `/products?search=phone&category=smartphones&page=2`

The part after `?` is the **query string**. It is perfect for **search, filters, sorting and pagination**, because:

- The user can **bookmark and share** the exact view.
- **Refresh** keeps the filter.
- The **Back button** works as expected.

```jsx
import { useSearchParams } from "react-router-dom";

function ProductsPage() {
  const [searchParams, setSearchParams] = useSearchParams();

  const search = searchParams.get("search") ?? "";
  const page = Number(searchParams.get("page") ?? 1);

  function handleSearchChange(event) {
    setSearchParams({ search: event.target.value, page: 1 });
  }

  return (
    <div>
      <input value={search} onChange={handleSearchChange} placeholder="Search..." />
      <p>Searching for "{search}", page {page}</p>
    </div>
  );
}
```

### Rules

- `searchParams.get("name")` returns `null` if missing. Use `?? ""` or a default.
- Values are strings. Convert numbers.
- `setSearchParams({ ... })` **replaces** all parameters. To keep existing ones, copy them first:

```jsx
function updateParam(key, value) {
  const next = new URLSearchParams(searchParams);
  if (value) next.set(key, value);
  else next.delete(key);       // keep URL clean
  setSearchParams(next);
}
```

### URL state vs component state

| Use URL (query/params) when | Use `useState` when |
|---|---|
| The state defines **which view** is shown (page, filter, id) | The state is temporary UI (modal open, hover, draft text) |
| It should survive refresh and be shareable | Nobody needs to share it |

## 10. The 404 Page

```jsx
// pages/NotFoundPage.jsx
import { Link } from "react-router-dom";

function NotFoundPage() {
  return (
    <section>
      <h1>404 — Page not found</h1>
      <p>The page you are looking for does not exist.</p>
      <Link to="/">Go to the home page</Link>
    </section>
  );
}
export default NotFoundPage;
```

```jsx
<Route path="*" element={<NotFoundPage />} />
```

`*` matches anything that no other route matched. Also show a "not found" message **inside** the details page when the API returns a 404 for an unknown product id.

## 11. Passing Data Between Pages

| Method | Example | Use for |
|---|---|---|
| URL params | `/products/5` | Identifying a resource |
| Query string | `?page=2&sort=price` | Filters, search, pagination |
| Fetching by id | `getProductById(id)` | Loading details (**recommended**) |
| Route `state` | `navigate("/x", { state: { from: "/cart" } })` | Small temporary info (such as "where did I come from") |

Do not send large objects through route state; refresh would lose them. Prefer reading the id from the URL and fetching.

## 12. Scroll to Top on Navigation (Small Utility)

React Router does not reset the scroll position automatically.

```jsx
// components/ScrollToTop.jsx
import { useEffect } from "react";
import { useLocation } from "react-router-dom";

function ScrollToTop() {
  const { pathname } = useLocation();

  useEffect(() => {
    window.scrollTo(0, 0);
  }, [pathname]);

  return null;
}
export default ScrollToTop;
```

Place `<ScrollToTop />` once, inside `BrowserRouter` (for example inside `MainLayout`).

### `ProductsPage.jsx` (URL-driven search)

```jsx
import { useEffect, useState } from "react";
import { useSearchParams } from "react-router-dom";
import { getProducts, searchProducts } from "../services/productService";
import ProductCard from "../components/ProductCard";
import Loader from "../components/Loader";
import ErrorMessage from "../components/ErrorMessage";

function ProductsPage() {
  const [searchParams, setSearchParams] = useSearchParams();
  const search = searchParams.get("search") ?? "";

  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        setLoading(true);
        setError("");

        const data = search.trim()
          ? await searchProducts(search.trim(), { signal: controller.signal })
          : await getProducts({ limit: 20, signal: controller.signal });

        setProducts(data.products);
      } catch (err) {
        if (err.name !== "AbortError") setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }

    load();
    return () => controller.abort();
  }, [search]);

  function handleChange(event) {
    const value = event.target.value;
    setSearchParams(value ? { search: value } : {});
  }

  return (
    <section>
      <h1>Products</h1>

      <input
        type="search"
        value={search}
        onChange={handleChange}
        placeholder="Search products..."
        aria-label="Search products"
      />

      {loading && <Loader />}
      {error && <ErrorMessage message={error} />}
      {!loading && !error && products.length === 0 && <p>No products found.</p>}

      <div className="grid">
        {products.map((product) => (
          <ProductCard key={product.id} product={product} />
        ))}
      </div>
    </section>
  );
}

export default ProductsPage;
```

Try this: search for `phone`, then press the browser's **Back** button, then **refresh**. The search is restored from the URL.

## 14. Deployment Warning (we will use this on Day 11)

SPA routes like `/products/5` do not exist as real files. If the user refreshes on that URL, the **hosting server** must serve `index.html` for every path. Vite's dev server does it automatically. Production hosts need a rewrite rule (Netlify `_redirects`, Vercel `vercel.json`). We will configure this on Day 11.

## 15. Common Mistakes

| Mistake | Problem | Fix |
|---|---|---|
| Using `<a href="/about">` | Full reload, state lost | Use `<Link>` |
| Forgetting `BrowserRouter` | "useRoutes() may be used only in the context of a `<Router>`" | Wrap in `main.jsx` |
| Missing `<Outlet />` in layout | Child pages never appear | Add `<Outlet />` |
| Absolute path in nested child (`/products` under a parent) | Wrong route | Use relative paths |
| Treating `useParams` values as numbers | `"5" === 5` is false | Convert with `Number()` |
| `useEffect` without `[productId]` | Same product after URL change | Put param in dependencies |
| `NavLink` to `/` always active | Home highlighted everywhere | Add `end` |
| `setSearchParams` drops other params | Filters disappear | Copy `searchParams` first |
| No `*` route | Blank page on unknown URL | Add 404 route |
