# 17.1 — UI Libraries and Ant Design

**Goal:** Understand what a React UI library provides, decide when to use one, and build a small data table with Ant Design.

## 1. What Is a UI Library?

A UI library is a collection of reusable interface components and conventions. Instead of building every button, menu, dialog, or date picker from scratch, you install a package and compose its components in your React app.

A component library may provide:

- **Components:** buttons, inputs, tables, dialogs, navigation, and more.
- **Interaction behavior:** keyboard navigation, focus handling, open/close state, and validation.
- **Styling and design tokens:** colors, spacing, typography, and component sizes.
- **Accessibility support:** semantic roles and keyboard behavior, though you still need to use components correctly.

A library does not build your whole product. You still decide the page layout, content, responsive behavior, and how components fit your users' workflow.

## 2. UI Library, CSS Framework, or Headless Primitive?

These tools solve related but different problems:

| Approach | What it provides | Example |
| --- | --- | --- |
| CSS framework | CSS classes and sometimes ready-made patterns | Bootstrap |
| Styled component library | React components with a visual design system | Ant Design, MUI |
| Headless primitive library | Behavior and accessibility without finished visual styling | Radix Primitives |
| Copy-into-your-project components | Source components that you own and customize | shadcn/ui |

Using more than one styled component system in the same product can create inconsistent controls and larger bundles. Choose one primary approach, then add a small focused tool only when it solves a real need.

## 3. When Is Ant Design a Good Fit?

Ant Design (AntD) is a React component system with a broad set of polished controls. It is especially useful for data-heavy products such as admin tools, internal dashboards, and business applications. It includes tables, forms, date pickers, menus, notifications, and layout primitives.

It may be less suitable when:

- The product needs a highly distinctive visual identity and the team does not want to customize a design system.
- The application only needs a few simple controls and adding a large dependency is not justified.
- Your team has standardized on another component system already.

Before choosing, check the package's current React compatibility, component APIs, accessibility notes, theming approach, and bundle impact.

## 4. Install Ant Design in a Vite React App

From the React project directory:

```bash
npm install antd
```

In the application's entry file (`src/main.jsx` or `src/main.tsx`), import Ant Design's reset stylesheet once, before rendering the app:

```jsx
import 'antd/dist/reset.css';
```

Do not import the reset in every component. It establishes a consistent baseline for Ant Design controls.

## 5. Build a Small Table

Create `src/features/users/UsersTable.jsx`:

```jsx
import { Table, Tag } from 'antd';

const users = [
  { id: 'u-101', name: 'Amina Yusuf', email: 'amina@example.com', status: 'Active' },
  { id: 'u-102', name: 'Leo Park', email: 'leo@example.com', status: 'Invited' },
  { id: 'u-103', name: 'Nora Chen', email: 'nora@example.com', status: 'Active' },
];

const columns = [
  { title: 'Name', dataIndex: 'name', key: 'name' },
  { title: 'Email', dataIndex: 'email', key: 'email' },
  {
    title: 'Status',
    dataIndex: 'status',
    key: 'status',
    render: (status) => <Tag color={status === 'Active' ? 'green' : 'blue'}>{status}</Tag>,
  },
];

export function UsersTable() {
  return (
    <Table
      rowKey="id"
      columns={columns}
      dataSource={users}
      pagination={{ pageSize: 5 }}
      scroll={{ x: true }}
    />
  );
}
```

Use it from a page:

```jsx
import { Typography } from 'antd';
import { UsersTable } from './features/users/UsersTable';

export default function UsersPage() {
  return (
    <main style={{ maxWidth: 960, margin: '32px auto', padding: 16 }}>
      <Typography.Title level={1}>Users</Typography.Title>
      <UsersTable />
    </main>
  );
}
```

### Read the Example

- `Table`, `Tag`, and `Typography` are imported React components from Ant Design.
- `columns` describes how each field appears. `dataIndex` points to a property on each user.
- `render` customizes one cell while keeping the source data as plain values.
- `rowKey="id"` gives each row a stable identity. Do not use the array index when records can be reordered, inserted, or removed.
- `pagination` and `scroll` configure behavior; they do not replace responsive page design.

## 6. Forms and User Feedback

Ant Design's `Form` can own field values and validation. A basic form looks like this:

```jsx
import { Button, Form, Input, message } from 'antd';

export function InviteForm() {
  const [form] = Form.useForm();

  function handleFinish(values) {
    message.success(`Invitation prepared for ${values.email}`);
    form.resetFields();
  }

  return (
    <Form form={form} layout="vertical" onFinish={handleFinish}>
      <Form.Item
        label="Email address"
        name="email"
        rules={[
          { required: true, message: 'Enter an email address.' },
          { type: 'email', message: 'Enter a valid email address.' },
        ]}
      >
        <Input autoComplete="email" />
      </Form.Item>
      <Button type="primary" htmlType="submit">Send invitation</Button>
    </Form>
  );
}
```

The `onFinish` callback runs only after Ant Design's rules pass. In a real application, it should call an API and show a useful success or error state; client-side validation does not replace server-side validation.

## 7. Make the Design Fit Your Product

Ant Design supports theming with design tokens and `ConfigProvider`. Prefer a small set of intentional theme overrides over scattered one-off CSS overrides. Keep the product's typography, colors, spacing, and focus states consistent, and verify that custom colors still have sufficient contrast.

Do not reach immediately for `!important` or deeply nested selectors targeting Ant Design's internal class names. Those selectors are brittle and may break when the package changes.

## 8. Practical Checklist

- [ ] Install the library once in the application that uses it.
- [ ] Import global/reset CSS once at the entry point when required.
- [ ] Use documented props instead of editing library internals.
- [ ] Provide stable keys for data-driven rows and lists.
- [ ] Label form fields and explain validation errors.
- [ ] Check keyboard operation, narrow screens, loading, empty, and error states.
- [ ] Keep API calls and business rules outside presentation-only components when practical.

## Key Terms

- **Design system:** shared rules, tokens, and components that make a product's UI consistent.
- **Design token:** a named value such as a color, spacing step, or border radius.
- **Data grid:** a component for presenting and interacting with tabular records.
- **Row key:** a stable identifier React or a table uses to track a record between renders.
