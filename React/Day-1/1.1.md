# 1. Introduction to React

## 1.1 What is React?

React is a JavaScript library used to build user interfaces (UIs).

A user interface is the part of an application that users see and interact with, including:

- Navigation bars
- Buttons
- Forms
- Product cards
- Dashboards
- Tables
- Search boxes
- Notifications
- User profiles

React helps developers build these interfaces using reusable components and update them efficiently when application data changes.

### Real-life example: an e-commerce website

Imagine building an online shopping website.

The website may contain:

- A header with a logo and search bar
- A navigation menu
- A list of products
- Product cards
- A shopping cart
- A footer

Instead of creating the entire page as one large block, React allows us to divide it into smaller components.

For example:

```text
E-commerce Website
├── Header
│   ├── Logo
│   ├── SearchBar
│   └── CartButton
├── Navigation
├── ProductList
│   └── ProductCard
├── CartSummary
└── Footer
```

Each component has a specific responsibility and can be reused wherever needed.

## 1.2 Why do we use React?

Consider a task management application containing 50 tasks.

When a user marks one task as completed, several things might need to change:

- The task's status
- Its appearance
- The completed-task count
- The remaining-task count

In a traditional JavaScript approach, a developer might manually find and update different DOM elements. As an application grows, managing these updates can become complicated.

React lets developers describe what the interface should look like based on the current data. When the data changes, React updates the relevant parts of the UI.

### Main benefits of React

**1. Reusability**

Create a component once and use it in multiple places.

**2. Maintainability**

A well-organized component structure makes an application easier to update.

**3. Declarative UI**

Describe the UI for the current data instead of manually specifying every DOM update.

**4. Component-based development**

Divide a large interface into smaller, understandable pieces.

**5. Ecosystem**

React can be used with libraries and tools for routing, forms, data fetching, testing, and many other application requirements.

**6. Industry adoption**

React is widely used for interactive web applications, dashboards, e-commerce websites, and admin panels.

# 2. Understanding Traditional JavaScript and React

Before using React, understand the difference between imperative and declarative UI updates.

## 2.1 Traditional JavaScript approach

Consider a button that changes a message.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <title>JavaScript Example</title>
</head>
<body>
  <p id="message">Task is pending.</p>

  <button id="completeButton">
    Complete Task
  </button>

  <script>
    const button = document.querySelector("#completeButton");
    const message = document.querySelector("#message");

    button.addEventListener("click", () => {
      message.textContent = "Task completed!";
    });
  </script>
</body>
</html>
```

### How it works

1. JavaScript finds the button using `querySelector()`.
2. It finds the paragraph.
3. It registers a click handler.
4. When the button is clicked, it manually changes the paragraph's text.

This approach is valid and useful for many situations. However, manually coordinating numerous UI updates can become harder as an application grows.

## 2.2 React approach

The same behavior can be implemented using React state.

```jsx
import { useState } from "react";

function TaskStatus() {
  const [completed, setCompleted] = useState(false);

  return (
    <section>
      <p>
        {completed ? "Task completed!" : "Task is pending."}
      </p>

      <button
        type="button"
        onClick={() => setCompleted(true)}
      >
        Complete Task
      </button>
    </section>
  );
}

export default TaskStatus;
```

### How it works

1. `completed` stores the current status.
2. Initially, its value is `false`.
3. The JSX displays the message corresponding to that value.
4. Clicking the button updates the state to `true`.
5. React renders the updated message.

We will study `useState` and event handling in detail on Day 2. For now, focus on the idea that the UI is described using data.

### Important terminology

- **Imperative:** Describe the steps required to make a change.
- **Declarative:** Describe what the UI should look like for the current data.
- **DOM:** The browser's object representation of the HTML document.
- **Component:** A reusable part of a user interface.

React does not eliminate the need to understand HTML, CSS, JavaScript, or the DOM. It provides a structured approach to building and updating interfaces.

# 3. Understanding Components

## 3.1 What is a component?

A React component is a reusable piece of UI.

Components are commonly written as JavaScript functions that return JSX.

```jsx
function WelcomeMessage() {
  return <h1>Welcome to React!</h1>;
}

export default WelcomeMessage;
```

The component can be used inside another component:

```jsx
import WelcomeMessage from "./WelcomeMessage.jsx";

function App() {
  return (
    <main>
      <WelcomeMessage />
      <p>Start learning React today.</p>
    </main>
  );
}

export default App;
```

Here, `WelcomeMessage` is a component used inside `App`.

## 3.2 Real-life analogy: building a car

A car is made from smaller systems:

- Engine
- Wheels
- Seats
- Lights
- Dashboard

Each system has its own responsibility, and the systems are assembled into the final product.

React components follow a similar principle. A complete page can be assembled from smaller, reusable UI elements.

## 3.3 Examples of reusable components

| Component | Possible use |
|---|---|
| `Header` | Top section of a website |
| `Button` | Reusable action button |
| `ProductCard` | Product information |
| `StudentCard` | Student information |
| `TaskItem` | Individual task |
| `NavigationBar` | Application navigation |
| `Footer` | Bottom section of a page |

On Day 1.3, we will explore component creation, props, and composition in greater depth.

# 4. Understanding the React Ecosystem

React projects use several tools that serve different purposes.

## 4.1 What is JavaScript?

JavaScript is a programming language used to add logic and interactivity to web applications.

It can handle:

- Calculations
- Conditions
- Loops
- Event handling
- API requests
- Data transformations
- UI behavior

React is a JavaScript library, so students need a foundation in JavaScript before learning React.

## 4.2 What is Node.js?

Node.js is a JavaScript runtime that allows JavaScript to execute outside the browser.

In this internship, we use Node.js to run tools such as npm and Vite.

Node.js is not the same as React.

## 4.3 What is npm?

npm is the package manager commonly used with Node.js.

It helps developers:

- Install dependencies
- Manage project packages
- Run project scripts
- Track package versions

For example:

```bash
npm install
```

This command installs the dependencies defined in the project's package configuration.

## 4.4 What is Vite?

Vite is a frontend development and build tool.

It helps us:

- Create a starter project
- Run a local development server
- See code changes during development
- Build optimized files for deployment

Vite is not React itself. It is one of the tools that can be used to develop React applications.

## 4.5 How do these technologies work together?

```text
Developer
   |
   v
Writes React components and JSX
   |
   v
Vite processes the application during development
   |
   v
Browser displays the React UI
```

Node.js runs the development tooling, and npm manages the packages.

### Quick comparison

| Technology | Main purpose |
|---|---|
| JavaScript | Programming language |
| React | Building user interfaces |
| Node.js | Running JavaScript outside the browser |
| npm | Installing packages and running scripts |
| Vite | Development server and build tooling |

# 6. Creating a React Project with Vite

We will create a project named `task-manager`. This will become the starting point for our React exercises.

## Step 1 — Open the terminal

Navigate to the folder where you want to keep your internship projects.

For example:

```bash
cd Desktop
```

Use the appropriate directory for your own system.

## Step 2 — Create the project

Run:

```bash
npm create vite@latest task-manager -- --template react
```

### Explanation

- `npm create` runs a project scaffolding tool.
- `vite@latest` requests the latest Vite scaffolding package.
- `task-manager` is the project directory name.
- `--template react` selects the React JavaScript template.

Vite may ask for confirmation or display additional prompts depending on its version.

## Step 3 — Enter the project directory

```bash
cd task-manager
```

You must run the following commands from the project directory.

## Step 4 — Install dependencies

```bash
npm install
```

This installs the packages required by the starter project.

The installation creates or updates `node_modules` and the package lock file.

## Step 5 — Start the development server

```bash
npm run dev
```

The terminal should display a local URL, often similar to:

```text
http://localhost:5173/
```

Open the exact URL shown in your terminal.

You should see the starter React application.

### What is localhost?

`localhost` refers to your own computer.

The development server lets you preview your application locally while you write code.

The port number, such as `5173`, identifies the local network port used by the server. If that port is already occupied, Vite may choose another one.

## Step 6 — Stop the development server

When you want to stop the server, return to the terminal and press:

```text
Ctrl + C
```

To start it again, run:

```bash
npm run dev
```

# 7. Understanding the Project Structure

A newly generated Vite React project may have a structure similar to this:

```text
task-manager/
├── node_modules/
├── public/
├── src/
│   ├── assets/
│   ├── App.css
│   ├── App.jsx
│   ├── index.css
│   └── main.jsx
├── index.html
├── package.json
├── package-lock.json
└── vite.config.js
```

The exact files can vary depending on the Vite template version.

## 7.1 The `src` folder

The `src` directory contains the main application source code.

You will usually write React components, JavaScript logic, and application styles here.

## 7.2 The `App.jsx` file

`App.jsx` commonly contains the main application component in the Vite React starter project.

Example:

```jsx
function App() {
  return (
    <main>
      <h1>My React Application</h1>
      <p>Welcome to the internship.</p>
    </main>
  );
}

export default App;
```

We will modify this file frequently during the internship.

## 7.3 The `main.jsx` file

This file connects the React application to the browser's HTML document.

A typical version looks like this:

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./index.css";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

### Explanation

**`import { StrictMode } from "react"`**

Imports a development helper that can reveal certain problems.

**`import { createRoot } from "react-dom/client"`**

Imports the API used to mount the React application.

**`import "./index.css"`**

Loads global styles.

**`import App from "./App.jsx"`**

Imports the main application component.

**`document.getElementById("root")`**

Finds the HTML element where React will render the application.

**`createRoot(...).render(...)`**

Mounts the React component tree into that element.

In development, `StrictMode` may intentionally repeat certain checks or executions to help reveal bugs. This is expected behavior in supported cases and does not necessarily indicate a production issue.

## 7.4 The `index.html` file

The HTML file contains the document that the browser initially loads.

A simplified version looks like this:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Task Manager</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```

The `root` element is where React mounts the UI.

## 7.5 The `index.css` file

This file usually contains global styles that apply across the application.

Example:

```css
body {
  margin: 0;
  font-family: Arial, sans-serif;
}
```

## 7.6 The `App.css` file

This file commonly contains styles associated with the starter `App` component.

You can keep using it, organize styles differently, or remove unused starter styles as the project develops.

## 7.7 The `public` folder

This folder is used for static assets that should be served directly, such as certain images, icons, or files.

## 7.8 The `package.json` file

This file contains project metadata, scripts, and dependency declarations.

A simplified example:

```json
{
  "name": "task-manager",
  "version": "1.0.0",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "react": "...",
    "react-dom": "..."
  },
  "devDependencies": {
    "vite": "..."
  }
}
```

The actual versions and dependencies depend on the generated project. Do not replace your generated `package.json` with this illustrative example.

### Important scripts

| Command | Purpose |
|---|---|
| `npm run dev` | Starts the development server |
| `npm run build` | Builds the production application |
| `npm run preview` | Previews the production build locally |

## 7.9 The `node_modules` folder

This folder contains installed packages.

It can become large and is normally excluded from version control because dependencies can be installed again from the package configuration.

## 7.10 The `package-lock.json` file

This file records the resolved dependency tree so installations can be more consistent across machines.

When using npm, normally keep the lock file in version control.

# 9. Adding Basic CSS

Open `src/index.css`.

You can replace the starter global styles with:

```css
* {
  box-sizing: border-box;
}

body {
  margin: 0;
  padding: 32px;
  font-family: Arial, sans-serif;
  background: #f4f6f8;
  color: #17202a;
}

main {
  max-width: 720px;
  margin: 0 auto;
  padding: 24px;
  background: white;
  border-radius: 12px;
}

h1 {
  margin-top: 0;
}

button {
  padding: 10px 16px;
  border: none;
  border-radius: 6px;
  cursor: pointer;
}
```

### Explanation

**`box-sizing: border-box`**

Makes width calculations more predictable by including padding and borders in the specified dimensions.

**`margin: 0`**

Removes the browser's default body margin.

**`max-width: 720px`**

Prevents the content from becoming excessively wide.

**`margin: 0 auto`**

Centers the content horizontally when there is available space.

**`border-radius: 12px`**

Rounds the corners of the content container.

**`cursor: pointer`**

Displays a pointer cursor when hovering over the button.

# 11. Common Setup Problems and Solutions

## Problem 1 — `node` or `npm` is not recognized

**Possible cause:** Node.js is not installed or the terminal cannot find it.

**Solution:**

1. Install a supported Node.js LTS release.
2. Reopen the terminal.
3. Run `node --version`.
4. Run `npm --version`.

## Problem 2 — `npm install` fails

Possible causes include:

- Network connectivity issues
- Unsupported Node.js version
- Incorrect project directory
- Package registry problems

Try:

```bash
npm install
```

from the folder containing `package.json`.

Read the error message before attempting more complex fixes.

## Problem 3 — The browser cannot open the application

Check that the development server is running.

```bash
npm run dev
```

Use the exact local URL shown in the terminal.

## Problem 4 — Port already in use

If the default port is occupied, Vite may choose another port.

Open the URL displayed in the terminal instead of assuming the application always uses port `5173`.

## Problem 5 — Blank page

Check:

- The terminal output
- The browser console
- JSX syntax
- Import paths
- Component exports
- Whether `App` is imported and rendered correctly

## Problem 6 — Component is not found

Check that:

- The file exists.
- The import path is correct.
- The filename capitalization matches.
- The component is exported.
- The import style matches the export style.

## Problem 7 — Changes do not appear

Try:

1. Saving the file.
2. Checking for syntax errors.
3. Confirming that the correct project is running.
4. Checking the terminal for compilation errors.
5. Refreshing the browser if necessary.
