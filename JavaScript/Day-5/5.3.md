# Day 5.3 — Browser Storage and Practical JavaScript

## Learning Objectives

Learn how browser storage works, persist simple application data, understand the difference between `localStorage` and `sessionStorage`, and build a small persistent task list.

## 1. What Is Browser Storage?

Browser storage lets a website save small amounts of data on the user's device.

Two commonly used options are:

- **`localStorage`:** Data generally remains available across browser sessions until it is removed.
- **`sessionStorage`:** Data is associated with the current browsing session and is generally cleared when that tab or window session ends.

Both store values as strings.

## 2. Using `localStorage`

```javascript
localStorage.setItem("username", "Asha");

const username = localStorage.getItem("username");

console.log(username); // Asha
```

Other useful methods:

```javascript
localStorage.removeItem("username");
localStorage.clear();
```

`clear()` removes all keys from the current origin's local storage, so use it carefully.

## 3. Storing Objects and Arrays

Because browser storage stores strings, convert objects and arrays using JSON.

```javascript
const preferences = {
  theme: "dark",
  language: "en"
};

localStorage.setItem(
  "preferences",
  JSON.stringify(preferences)
);

const savedPreferences = JSON.parse(
  localStorage.getItem("preferences")
);

console.log(savedPreferences.theme); // dark
```

### Handle Missing Data

`getItem()` returns `null` when a key does not exist.

```javascript
const saved = localStorage.getItem("tasks");

const tasks = saved ? JSON.parse(saved) : [];

console.log(tasks);
```

In production code, parsing should also be protected with error handling because stored data can be malformed.

## 4. Using `sessionStorage`

The API is similar to `localStorage`.

```javascript
sessionStorage.setItem("currentStep", "2");

console.log(sessionStorage.getItem("currentStep"));
```

Use it for temporary session-specific information, not as a replacement for secure server-side session management.

## 5. Storage Limitations and Security

Students should understand the following rules:

- Browser storage is scoped by origin.
- Storage APIs store strings rather than native JavaScript objects.
- Storage operations can fail in restricted browser environments.
- Data stored in browser storage can be read by JavaScript running on the same origin.
- **Do not store passwords, secret API keys, or sensitive authentication data in browser storage.**
- Browser storage is not a secure database and should not be trusted as the source of truth for permissions or payments.

## 6. Mini Example — Persistent Task List

```javascript
function loadTasks() {
  try {
    const saved = localStorage.getItem("tasks");
    return saved ? JSON.parse(saved) : [];
  } catch (error) {
    console.error("Could not load tasks:", error.message);
    return [];
  }
}

function saveTasks(tasks) {
  localStorage.setItem("tasks", JSON.stringify(tasks));
}

let tasks = loadTasks();

tasks.push({
  id: Date.now(),
  title: "Learn JavaScript",
  completed: false
});

saveTasks(tasks);

console.log(tasks);
```

This example loads saved tasks, adds a task, and saves the updated array. In a larger application, each operation should be wrapped with suitable validation and storage error handling.
