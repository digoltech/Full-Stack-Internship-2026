# 0.3 — How the Browser Works

When you enter a URL, the browser:

1. Finds the server through DNS.
2. Opens an HTTP or HTTPS connection.
3. Downloads HTML, CSS, JavaScript, images, and fonts.
4. Builds internal representations of the page.
5. Runs JavaScript and handles user interactions.
6. Displays the result on the screen.

## Main Rendering Pipeline

```text
HTML bytes
   ↓
HTML parser
   ↓
DOM (document structure)

CSS bytes
   ↓
CSS parser
   ↓
CSSOM (style rules)

DOM + CSSOM
   ↓
Render Tree
   ↓
Layout
   ↓
Paint
   ↓
Composite
   ↓
Pixels on screen
```

## DOM

The DOM is a JavaScript-accessible object model of HTML.

```html
<main>
  <h1>Hello</h1>
</main>
```

It can become a tree-like structure of objects that JavaScript can inspect or modify.

## CSSOM

The CSSOM contains parsed CSS rules, selectors, cascade results, inheritance, and computed styles.

## Render Tree

The render tree combines visible DOM elements with their computed CSS styles. Hidden elements are not normally placed in the visible rendering flow.

## Layout

The browser calculates element position and size.

- Width
- Height
- Margin
- Padding
- Top, left, and containing block

## Paint

The browser converts layout information into pixels, including:

- Text
- Colors
- Borders
- Shadows
- Backgrounds

## Composite

The browser combines prepared layers and draws the final image.

## JavaScript and Rendering

JavaScript runs on the browser's main thread with rendering work.

```text
Call Stack → Microtask Queue → Rendering → Next Task
```

Long JavaScript tasks can block the UI. Use `async/await`, `fetch()`, Web Workers, and debouncing where appropriate.
