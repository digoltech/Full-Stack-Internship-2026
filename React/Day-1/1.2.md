# 1. Introduction to JSX

## 1.1 What is JSX?

JSX stands for **JavaScript XML**. It is a syntax extension commonly used with React to describe what the user interface should look like.

JSX looks similar to HTML, but it is written inside JavaScript files and follows some different rules.

### Example without JSX

React can create elements without JSX using JavaScript functions.

```jsx
import { createElement } from "react";

function App() {
  return createElement(
    "h1",
    null,
    "Hello, React!"
  );
}

export default App;
```

This works, but it becomes difficult to read when the UI contains many nested elements.

### Example with JSX

```jsx
function App() {
  return <h1>Hello, React!</h1>;
}

export default App;
```

The JSX version is easier to understand and maintain.

**Important:** JSX is not HTML. Build tools such as Vite transform JSX into JavaScript that React can use.

## 1.2 Why do we use JSX?

Imagine that you are building an e-commerce website.

A product card might contain:

- Product image
- Product name
- Price
- Discount
- Availability status
- Add-to-cart button

Without a structured way to describe the interface, the code can become difficult to read.

JSX allows us to describe the UI in a structure that resembles the final page.

Example:

```jsx
function ProductCard() {
  return (
    <article>
      <img
        src="https://placehold.co/200x150"
        alt="Sample product"
      />
      <h2>Wireless Headphones</h2>
      <p>Price: ₹1,499</p>
      <button type="button">Add to Cart</button>
    </article>
  );
}

export default ProductCard;
```

This component describes the structure of a product card.

### Benefits of JSX

1. **Readability:** The structure of the UI is easy to understand.
2. **Maintainability:** Developers can modify UI code more easily.
3. **JavaScript integration:** Variables and expressions can be displayed directly.
4. **Component development:** JSX makes reusable components convenient to create.
5. **Dynamic interfaces:** The displayed UI can depend on data and conditions.

# 2. Writing JSX Correctly

JSX resembles HTML, but it has several rules.

## 2.1 Rule 1 — Return one enclosing element

Incorrect:

```jsx
function App() {
  return (
    <h1>Welcome</h1>
    <p>Learn React today.</p>
  );
}

export default App;
```

This is invalid because the component returns two adjacent root elements.

Correct:

```jsx
function App() {
  return (
    <div>
      <h1>Welcome</h1>
      <p>Learn React today.</p>
    </div>
  );
}

export default App;
```

The `<div>` acts as a parent element.

## 2.2 Rule 2 — Use fragments when a wrapper is unnecessary

Sometimes we do not want an extra HTML element in the DOM.

Instead of this:

```jsx
function App() {
  return (
    <div>
      <h1>Welcome</h1>
      <p>Learn React today.</p>
    </div>
  );
}
```

We can use a fragment:

```jsx
function App() {
  return (
    <>
      <h1>Welcome</h1>
      <p>Learn React today.</p>
    </>
  );
}

export default App;
```

The fragment groups the elements without creating an additional DOM wrapper.

### When should you use a fragment?

Use fragments when multiple elements need to be returned together but do not need a shared HTML container.

## 2.3 Rule 3 — Close every JSX element

Incorrect:

```jsx
function App() {
  return (
    <div>
      <h1>React Training</h1>
      <img src="/logo.png">
      <input type="text">
    </div>
  );
}
```

Correct:

```jsx
function App() {
  return (
    <div>
      <h1>React Training</h1>
      <img src="/logo.png" alt="Logo" />
      <input type="text" />
    </div>
  );
}
```

In JSX, elements such as `img` and `input` must be self-closed when they do not have closing tags.

## 2.4 Rule 4 — Use `className` instead of `class`

In HTML:

```html
<div class="card">Hello</div>
```

In JSX:

```jsx
<div className="card">Hello</div>
```

React uses `className` for the CSS class attribute.

## 2.5 Rule 5 — Use `htmlFor` instead of `for`

In HTML:

```html
<label for="email">Email</label>
```

In JSX:

```jsx
<label htmlFor="email">Email</label>
```

This is particularly useful when creating accessible forms.

### Common JSX attribute differences

| HTML | JSX |
|---|---|
| `class` | `className` |
| `for` | `htmlFor` |
| `onclick` | `onClick` |
| `onchange` | `onChange` |
| `tabindex` | `tabIndex` |

Many JSX attributes use camelCase.

# 3. Embedding JavaScript in JSX

One of the most useful features of JSX is that we can insert JavaScript expressions using curly braces `{}`.

## 3.1 Displaying variables

```jsx
function App() {
  const studentName = "Rahil";
  const course = "MERN Stack Internship";

  return (
    <main>
      <h1>Welcome, {studentName}!</h1>
      <p>Course: {course}</p>
    </main>
  );
}

export default App;
```

Output:

```text
Welcome, Rahil!
Course: MERN Stack Internship
```

React evaluates the expressions inside curly braces and displays their results.

## 3.2 Displaying calculations

```jsx
function App() {
  const price = 500;
  const quantity = 3;
  const total = price * quantity;

  return (
    <main>
      <p>Price: ₹{price}</p>
      <p>Quantity: {quantity}</p>
      <p>Total: ₹{total}</p>
    </main>
  );
}

export default App;
```

Output:

```text
Price: ₹500
Quantity: 3
Total: ₹1500
```

### Real-life example: shopping cart

An online shopping cart needs to calculate the total cost of products.

Instead of hardcoding the total price, we calculate it using JavaScript and display it through JSX.

This same approach is useful for:

- Shopping cart totals
- Invoice amounts
- Employee salary summaries
- Student marks
- Product discounts
- Dashboard statistics

## 3.3 Using JavaScript expressions

You can use many JavaScript expressions inside JSX.

```jsx
function App() {
  const firstName = "Rahil";
  const lastName = "Vahora";
  const marks = 85;

  return (
    <main>
      <h1>{firstName + " " + lastName}</h1>

      <p>Marks: {marks}</p>

      <p>Next score target: {marks + 10}</p>

      <p>Passed: {marks >= 40 ? "Yes" : "No"}</p>
    </main>
  );
}

export default App;
```

Expressions that produce values can be embedded inside JSX.

Examples:

```jsx
<p>{10 + 20}</p>

<p>{userName}</p>

<p>{items.length}</p>

<p>{isActive ? "Active" : "Inactive"}</p>
```

## 3.4 Expressions versus statements

An **expression** produces a value.

Examples:

```js
10 + 20
studentName
marks >= 40
isLoggedIn ? "Welcome" : "Login"
```

A **statement** performs an action or controls execution.

Examples:

```js
const total = 100;

if (total > 50) {
  console.log("Large total");
}
```

You cannot place a normal `if` statement directly inside JSX curly braces.

Incorrect:

```jsx
return (
  <p>
    {if (isLoggedIn) "Welcome"}
  </p>
);
```

Instead, use a ternary expression:

```jsx
return (
  <p>
    {isLoggedIn ? "Welcome" : "Please log in"}
  </p>
);
```

For more complex logic, calculate the result before the `return` statement.

# 4. JSX Attributes and Dynamic Values

JSX attributes can contain strings or JavaScript expressions.

## 4.1 Static attribute values

```jsx
function App() {
  return (
    <img
      src="/profile.png"
      alt="Student profile"
    />
  );
}
```

The values are written as strings.

## 4.2 Dynamic attribute values

```jsx
function App() {
  const imageUrl = "/profile.png";
  const imageDescription = "Student profile";

  return (
    <img
      src={imageUrl}
      alt={imageDescription}
    />
  );
}

export default App;
```

Curly braces allow the attribute values to come from JavaScript variables.

## 4.3 Dynamic CSS classes

```jsx
function App() {
  const status = "success";

  return (
    <div className={status === "success" ? "success" : "error"}>
      Operation completed.
    </div>
  );
}

export default App;
```

CSS:

```css
.success {
  color: green;
}

.error {
  color: red;
}
```

The class is selected based on the value of `status`.

### Practical uses

Dynamic classes are useful for:

- Success and error messages
- Completed and pending tasks
- Active navigation links
- Available and unavailable products
- Warning and information banners

# 5. Conditional Rendering in React

Conditional rendering means displaying different UI depending on a condition.

Real applications use conditional rendering frequently.

Examples:

- Show a login button when the user is logged out.
- Show a dashboard when the user is logged in.
- Display an error when form data is invalid.
- Show a success message after saving.
- Display a badge when a task is completed.

## 5.1 Using the ternary operator

Syntax:

```jsx
condition ? valueIfTrue : valueIfFalse
```

Example:

```jsx
function App() {
  const isLoggedIn = true;

  return (
    <main>
      <h1>
        {isLoggedIn ? "Welcome Back!" : "Please Log In"}
      </h1>
    </main>
  );
}

export default App;
```

If `isLoggedIn` is `true`, the heading displays `Welcome Back!`.

If it is `false`, the heading displays `Please Log In`.

## 5.2 Real-life example: task status

```jsx
function TaskStatus() {
  const completed = true;

  return (
    <div>
      <h2>Learn JSX</h2>

      <p>
        Status: {completed ? "Completed" : "Pending"}
      </p>
    </div>
  );
}

export default TaskStatus;
```

If the task is completed, the page displays `Completed`; otherwise, it displays `Pending`.

## 5.3 Using logical AND (`&&`)

Use `&&` when you want to show something only when a condition is true.

```jsx
function App() {
  const hasNotifications = true;

  return (
    <main>
      <h1>Dashboard</h1>

      {hasNotifications && (
        <p>You have new notifications.</p>
      )}
    </main>
  );
}

export default App;
```

If `hasNotifications` is true, the message is displayed.

If it is false, the message is not displayed.

### Important: avoid accidentally displaying zero

Consider:

```jsx
{items.length && <p>Items available</p>}
```

When `items.length` is `0`, React can render the number `0`.

Prefer this:

```jsx
{items.length > 0 && <p>Items available</p>}
```

The comparison produces a boolean and avoids the numeric-zero issue.

## 5.4 Using conditions before the return

When the logic becomes more complex, calculate what to display before returning JSX.

```jsx
function Result() {
  const marks = 75;

  let message;

  if (marks >= 80) {
    message = "Excellent";
  } else if (marks >= 60) {
    message = "Good";
  } else if (marks >= 40) {
    message = "Passed";
  } else {
    message = "Needs improvement";
  }

  return <h2>{message}</h2>;
}

export default Result;
```

This approach is easier to read than nesting many ternary expressions inside JSX.

# 6. Rendering Lists Using `map()`

Many applications display collections of data.

Examples:

- Products in an e-commerce application
- Tasks in a task manager
- Employees in an admin dashboard
- Courses in a learning portal
- Messages in a chat application

Instead of writing every item manually, we can use JavaScript's `map()` method.

## 6.1 Understanding `map()`

`map()` creates a new array by applying a function to each item of an existing array.

Example in JavaScript:

```js
const numbers = [1, 2, 3];

const doubledNumbers = numbers.map((number) => {
  return number * 2;
});

console.log(doubledNumbers);
```

Output:

```text
[2, 4, 6]
```

In React, we often use `map()` to convert an array of data into JSX elements.

## 6.2 Rendering a simple list

```jsx
function App() {
  const topics = [
    "HTML",
    "CSS",
    "JavaScript",
    "React",
  ];

  return (
    <main>
      <h1>Learning Topics</h1>

      <ul>
        {topics.map((topic) => (
          <li key={topic}>{topic}</li>
        ))}
      </ul>
    </main>
  );
}

export default App;
```

React renders one `<li>` for every item in the array.

## 6.3 Rendering an array of objects

In real projects, data is often stored as objects.

```jsx
function App() {
  const students = [
    {
      id: 1,
      name: "Aarav",
      role: "Frontend Intern",
    },
    {
      id: 2,
      name: "Diya",
      role: "Full Stack Intern",
    },
    {
      id: 3,
      name: "Kabir",
      role: "Frontend Intern",
    },
  ];

  return (
    <main>
      <h1>Internship Students</h1>

      {students.map((student) => (
        <article key={student.id}>
          <h2>{student.name}</h2>
          <p>{student.role}</p>
        </article>
      ))}
    </main>
  );
}

export default App;
```

### What happens here?

1. `students` stores the student data.
2. `map()` processes each student.
3. JSX creates an article for each student.
4. Each article displays the student's name and role.
5. The ID is used as a key.

## 6.4 Why does React need keys?

A key helps React identify which item corresponds to which rendered element when a list changes.

Imagine a task list:

```text
1. Learn JSX
2. Learn Props
3. Learn Components
```

If the second task is deleted, React needs a reliable way to identify the remaining tasks.

A stable key helps React track the items correctly.

Good:

```jsx
<li key={task.id}>{task.title}</li>
```

Avoid using an array index as a key when items may be inserted, removed, or reordered.

For static lists that never change, an index can sometimes work, but stable IDs are the preferred habit for application development.

**Note:** React uses `key` internally. A component does not automatically receive `key` as a normal prop. If the child needs the ID, pass it separately.

## 6.5 Rendering an empty state

A list might contain no data. A good interface should explain what happened.

```jsx
function App() {
  const tasks = [];

  return (
    <main>
      <h1>My Tasks</h1>

      {tasks.length === 0 ? (
        <p>No tasks available. Add your first task!</p>
      ) : (
        <ul>
          {tasks.map((task) => (
            <li key={task.id}>{task.title}</li>
          ))}
        </ul>
      )}
    </main>
  );
}

export default App;
```

This is useful for dashboards, search results, shopping carts, and task management applications.

# 8. Common JSX Mistakes and Debugging

## Mistake 1 — Printing a variable name instead of its value

Incorrect:

```jsx
const name = "Aarav";

return <h1>name</h1>;
```

Output:

```text
name
```

Correct:

```jsx
const name = "Aarav";

return <h1>{name}</h1>;
```

## Mistake 2 — Using `class` instead of `className`

Incorrect:

```jsx
<div class="card">Product</div>
```

Correct:

```jsx
<div className="card">Product</div>
```

## Mistake 3 — Forgetting the `key` in a list

Incorrect:

```jsx
{students.map((student) => (
  <p>{student.name}</p>
))}
```

Correct:

```jsx
{students.map((student) => (
  <p key={student.id}>{student.name}</p>
))}
```

## Mistake 4 — Writing an `if` statement directly inside JSX

Incorrect:

```jsx
<p>{if (active) "Active"}</p>
```

Correct:

```jsx
<p>{active ? "Active" : "Inactive"}</p>
```

## Mistake 5 — Forgetting to close elements

Incorrect:

```jsx
<img src="/logo.png">
```

Correct:

```jsx
<img src="/logo.png" alt="Logo" />
```

## Mistake 6 — Rendering zero accidentally

Potential issue:

```jsx
{items.length && <p>Items found</p>}
```

Safer:

```jsx
{items.length > 0 && <p>Items found</p>}
```

## Debugging checklist

When your React page shows an error or renders incorrectly:

1. Read the terminal error message.
2. Check the browser console.
3. Look for missing closing tags.
4. Check JSX attributes such as `className`.
5. Verify that variables exist in the current scope.
6. Check that expressions are enclosed in curly braces.
7. Check component names and imports.
8. Check that arrays contain the properties your JSX expects.
9. Check that mapped elements have stable keys.
10. Save the file and confirm the error is resolved.
