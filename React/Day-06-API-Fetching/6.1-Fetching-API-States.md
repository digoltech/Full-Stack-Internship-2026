#  — Day 6.1: Fetching Data from APIs in React

## 1. Learning Objectives

By the end of this session, students should be able to:

- Explain what an API, HTTP, JSON and a REST endpoint are.
- Use `fetch()` with `async/await` and handle errors correctly.
- Understand why `fetch` belongs inside `useEffect` (not in the component body).
- Model the four UI states of a request: **loading, error, empty, success**.
- Re-fetch data when a value (such as a product id or a search word) changes.
- Cancel outdated requests with `AbortController` and explain race conditions.
- Explain why `useEffect` runs twice in development with React StrictMode.
- Move API code into a separate service file.
- Store configuration (base URL) in a `.env` file using Vite.
- Send data to an API using `POST`.

## 2. Recap

On Day 5 we managed data that lived **inside** the browser. Most real applications also need data that lives on a **server**: products, users, posts, orders. Today our React app learns to talk to a server.

## 3. Key Terms

| Term | Meaning |
|---|---|
| **API** | A set of URLs a program can call to get or change data |
| **HTTP** | The protocol browsers and servers use to talk |
| **Endpoint** | One specific URL, for example `https://dummyjson.com/products` |
| **Request** | What the client sends (method, URL, headers, body) |
| **Response** | What the server sends back (status, headers, body) |
| **JSON** | Text format for data: `{ "id": 1, "title": "Phone" }` |
| **REST** | A common style of API: URLs are nouns, HTTP methods are verbs |

### HTTP methods

| Method | Typical use | Example |
|---|---|---|
| `GET` | Read data | `GET /products` |
| `POST` | Create data | `POST /products/add` |
| `PUT` / `PATCH` | Update data | `PATCH /products/1` |
| `DELETE` | Delete data | `DELETE /products/1` |

### Important status codes

| Code | Meaning |
|---|---|
| `200` | OK |
| `201` | Created |
| `400` | Bad request (you sent something wrong) |
| `401` / `403` | Not logged in / not allowed |
| `404` | Not found |
| `500` | Server error |

## 4. The Practice API

We will use **DummyJSON** (`https://dummyjson.com`), a free fake API made for learning.

| Endpoint | Returns |
|---|---|
| `GET /products?limit=12` | `{ products: [...], total, skip, limit }` |
| `GET /products/1` | One product object |
| `GET /products/search?q=phone` | Products matching the text |
| `GET /products/category-list` | Array of category names |

A product looks like this (shortened):

## 5. Using `fetch()`

`fetch(url)` returns a **Promise** of a `Response`.

```js
fetch("https://dummyjson.com/products/1")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.error(error));
```

The same with `async/await` (easier to read):

```js
async function getProduct() {
  const response = await fetch("https://dummyjson.com/products/1");
  const data = await response.json();
  console.log(data);
}
```

### 5.1 The most common mistake: `fetch` does not throw on 404 or 500

`fetch` only rejects when the **network fails**. A `404` or `500` still "succeeds". You must check `response.ok`:

```js
async function getProduct(id) {
  const response = await fetch(`https://dummyjson.com/products/${id}`);

  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}`);
  }

  return response.json();
}
```

### 5.2 `try / catch / finally`

```js
try {
  const data = await getProduct(1);
  console.log(data);
} catch (error) {
  console.error("Something went wrong:", error.message);
} finally {
  console.log("Runs always (success or error)");
}
```

## 6. Where Do We Call `fetch` in React?

### ❌ Wrong: in the component body

```jsx
function Products() {
  const [products, setProducts] = useState([]);

  fetch("https://dummyjson.com/products")          // runs on EVERY render
    .then((res) => res.json())
    .then((data) => setProducts(data.products));   // changes state → render → fetch → ...
  // infinite loop!
}
```

Rendering must be **pure**: no network calls, no timers, no side effects. Side effects belong in `useEffect` (or in event handlers).

### ✅ Correct: in `useEffect`

```jsx
import { useEffect, useState } from "react";

function Products() {
  const [products, setProducts] = useState([]);

  useEffect(() => {
    async function loadProducts() {
      const response = await fetch("https://dummyjson.com/products?limit=12");
      const data = await response.json();
      setProducts(data.products);
    }

    loadProducts();
  }, []);   // empty array → run once after the first render

  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>{product.title}</li>
      ))}
    </ul>
  );
}
```

### Why a separate inner `async` function?

The function you give to `useEffect` must return either nothing or a **cleanup function**. An `async` function always returns a Promise, so this is **wrong**:

```jsx
useEffect(async () => { ... }, []);   // ❌
```

Define an async function inside the effect and call it.

## 7. The Four UI States

A request is never just "data". The user must always know what is happening.

| State | When | What to show |
|---|---|---|
| **Loading** | Request in progress | Spinner or "Loading..." or skeleton |
| **Error** | Request failed | Friendly message and a **Retry** button |
| **Empty** | Request worked, but no items | "No products found" |
| **Success** | Request worked and has data | The list |

Three pieces of state are enough:

```jsx
const [products, setProducts] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState("");
```

### Complete example

```jsx
import { useEffect, useState } from "react";

function Products() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    async function loadProducts() {
      try {
        setLoading(true);
        setError("");

        const response = await fetch("https://dummyjson.com/products?limit=12");
        if (!response.ok) throw new Error(`Server returned ${response.status}`);

        const data = await response.json();
        setProducts(data.products);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }

    loadProducts();
  }, []);

  if (loading) return <p>Loading products...</p>;
  if (error) return <p className="error">Could not load products: {error}</p>;
  if (products.length === 0) return <p>No products found.</p>;

  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>
          {product.title} — ${product.price}
        </li>
      ))}
    </ul>
  );
}

export default Products;
```

Notice the **early returns** (`if (loading) return ...`). They keep the JSX simple and handle each state in order: loading → error → empty → success.

### Retry button

```jsx
const [reloadKey, setReloadKey] = useState(0);

useEffect(() => { /* fetch */ }, [reloadKey]);

if (error) {
  return (
    <div>
      <p>{error}</p>
      <button onClick={() => setReloadKey((k) => k + 1)}>Try again</button>
    </div>
  );
}
```

Changing `reloadKey` changes the dependency array, so the effect runs again.

## 8. Re-fetching When Something Changes

The dependency array lists the values the effect **uses**. When one changes, the effect runs again.

```jsx
function ProductDetails({ productId }) {
  const [product, setProduct] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    async function loadProduct() {
      try {
        setLoading(true);
        setError("");
        const response = await fetch(`https://dummyjson.com/products/${productId}`);
        if (!response.ok) throw new Error(`Status ${response.status}`);
        setProduct(await response.json());
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }

    loadProduct();
  }, [productId]);   // run again when productId changes

  if (loading) return <p>Loading...</p>;
  if (error) return <p>{error}</p>;

  return (
    <article>
      <h2>{product.title}</h2>
      <img src={product.thumbnail} alt={product.title} width="200" />
      <p>{product.description}</p>
      <strong>${product.price}</strong>
    </article>
  );
}
```

## 9. Race Conditions and `AbortController`

Imagine a search box. The user types `p`, then `ph`, then `pho`. Three requests are sent. Responses may arrive **out of order**: the response for `p` (slow) may arrive **after** the response for `pho` (fast), and overwrite the correct result.

```text
type "p"    ──────────── request A (slow) ───────────────▶ arrives last ❌
type "pho"  ──── request C (fast) ──▶ arrives first ✅
```

This is a **race condition**. The fix is to cancel the old request when the effect re-runs. React gives us the **cleanup function** for exactly this.

```jsx
useEffect(() => {
  const controller = new AbortController();

  async function search() {
    try {
      setLoading(true);
      setError("");

      const response = await fetch(
        `https://dummyjson.com/products/search?q=${encodeURIComponent(query)}`,
        { signal: controller.signal }
      );
      if (!response.ok) throw new Error(`Status ${response.status}`);

      const data = await response.json();
      setProducts(data.products);
    } catch (err) {
      if (err.name === "AbortError") return;   // cancelled on purpose, not an error
      setError(err.message);
    } finally {
      // Do not touch state if this request was cancelled
      if (!controller.signal.aborted) setLoading(false);
    }
  }

  search();

  return () => controller.abort();   // cleanup: cancel the old request
}, [query]);
```

### How it works

1. `query` changes → React runs the **cleanup** of the previous effect → previous request is aborted.
2. A new effect runs with a new `AbortController` and a new request.
3. Only the latest request can update state.

### `encodeURIComponent`

User text can contain spaces and symbols (`&`, `?`, `#`). `encodeURIComponent("red shoes & bags")` makes it safe to put inside a URL.

## 10. Why Does My Effect Run Twice?

In **development** with `<React.StrictMode>` (included in `main.jsx` by Vite), React mounts every component, unmounts it, and mounts it again. This reveals effects that are missing cleanup. You will see **two requests** in the Network tab.

- It happens **only in development**.
- It does not happen in the production build.
- Do **not** remove StrictMode to "fix" it. Instead, make sure your effect can run twice safely (that is what the `AbortController` does).

## 11. Separating API Code: the Service Layer

Putting `fetch` calls inside components makes them long and hard to test. Create a `services` folder.

```text
src/
├── services/
│   └── productService.js
├── components/
│   └── ...
└── App.jsx
```

### 11.1 Environment variables with Vite

Create a file named `.env` in the **project root** (next to `package.json`):

```text
VITE_API_URL=https://dummyjson.com
```

Rules:

- Variables must start with `VITE_` to be available in the browser.
- Read it with `import.meta.env.VITE_API_URL`.
- **Restart** `npm run dev` after editing `.env`.
- Add `.env` to `.gitignore` if it contains anything private. Because this is browser code, **never put secrets (passwords, private keys) in frontend env variables**: they are visible to everyone.
- Create `.env.example` (committed) listing the variable names without private values.

### 11.2 `services/apiClient.js`

```js
const BASE_URL = import.meta.env.VITE_API_URL;

export async function request(path, options = {}) {
  const response = await fetch(`${BASE_URL}${path}`, options);

  if (!response.ok) {
    throw new Error(`Request failed (${response.status})`);
  }

  return response.json();
}
```

### 11.3 `services/productService.js`

```js
import { request } from "./apiClient";

export function getProducts({ limit = 12, signal } = {}) {
  return request(`/products?limit=${limit}`, { signal });
}

export function getProductById(id, { signal } = {}) {
  return request(`/products/${id}`, { signal });
}

export function searchProducts(query, { signal } = {}) {
  return request(`/products/search?q=${encodeURIComponent(query)}`, { signal });
}
```

### 11.4 Using the service in a component

```jsx
import { useEffect, useState } from "react";
import { getProducts } from "../services/productService";

function Products() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        setLoading(true);
        setError("");
        const data = await getProducts({ limit: 12, signal: controller.signal });
        setProducts(data.products);
      } catch (err) {
        if (err.name !== "AbortError") setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }

    load();
    return () => controller.abort();
  }, []);

  /* loading / error / empty / success rendering as before */
}
```

The component now only worries about **state and UI**. The service worries about **URLs and HTTP**.

## 12. Sending Data: `POST`

```js
// services/productService.js
export function addProduct(product) {
  return request("/products/add", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(product)
  });
}
```

```jsx
async function handleSubmit(event) {
  event.preventDefault();

  try {
    setSubmitting(true);
    const created = await addProduct({ title, price: Number(price) });
    setMessage(`Created product with id ${created.id}`);
  } catch (err) {
    setMessage(err.message);
  } finally {
    setSubmitting(false);
  }
}
```

Notes:

- `headers: { "Content-Type": "application/json" }` tells the server the body is JSON.
- The body must be a **string** → `JSON.stringify(...)`.
- Disable the submit button while `submitting` is true to prevent double submissions.
- DummyJSON only **simulates** the creation. The new product is not really saved.

## 13. Reusable Building Blocks for UI States

Instead of repeating `<p>Loading...</p>` everywhere, create small components:

```jsx
// components/Loader.jsx
function Loader({ text = "Loading..." }) {
  return <p role="status" className="loader">{text}</p>;
}

```

```jsx
// components/ErrorMessage.jsx
function ErrorMessage({ message, onRetry }) {
  return (
    <div role="alert" className="error-box">
      <p>{message}</p>
      {onRetry && <button onClick={onRetry}>Try again</button>}
    </div>
  );
}
export default ErrorMessage;
```

```jsx
// components/EmptyState.jsx
function EmptyState({ message = "Nothing to show." }) {
  return <p className="empty">{message}</p>;
}
export default EmptyState;
```

`role="status"` and `role="alert"` help screen readers announce changes.

```jsx
// App.jsx
import { useEffect, useState } from "react";
import { getProducts, searchProducts } from "./services/productService";
import Loader from "./components/Loader";
import ErrorMessage from "./components/ErrorMessage";
import EmptyState from "./components/EmptyState";
import ProductList from "./components/ProductList";

function App() {
  const [query, setQuery] = useState("");
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");
  const [reloadKey, setReloadKey] = useState(0);

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        setLoading(true);
        setError("");

        const data = query.trim()
          ? await searchProducts(query.trim(), { signal: controller.signal })
          : await getProducts({ limit: 12, signal: controller.signal });

        setProducts(data.products);
      } catch (err) {
        if (err.name !== "AbortError") setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }

    load();
    return () => controller.abort();
  }, [query, reloadKey]);

  return (
    <main className="container">
      <h1>Product Explorer</h1>

      <input
        type="search"
        value={query}
        onChange={(event) => setQuery(event.target.value)}
        placeholder="Search products..."
        aria-label="Search products"
      />

      {loading && <Loader />}
      {!loading && error && (
        <ErrorMessage message={error} onRetry={() => setReloadKey((k) => k + 1)} />
      )}
      {!loading && !error && products.length === 0 && (
        <EmptyState message={`No products match "${query}".`} />
      )}
      {!loading && !error && products.length > 0 && (
        <ProductList products={products} />
      )}
    </main>
  );
}

export default App;
```

## 15. Centralized API Clients and REST Payloads

An API client keeps base URLs, headers, JSON parsing, cancellation, and error handling in one place.

```js
export async function apiRequest(path, options = {}) {
  const response = await fetch(`${import.meta.env.VITE_API_URL}${path}`, {
    ...options,
    headers: {
      "Content-Type": "application/json",
      ...options.headers,
    },
    signal: options.signal,
  });

  const text = await response.text();
  const data = text ? JSON.parse(text) : null;

  if (!response.ok) {
    throw new Error(data?.message || `Request failed (${response.status})`);
  }

  return data;
}
```

- Use the correct HTTP method: `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`.
- Send JSON data by serializing an object with `JSON.stringify()`.
- Never place secrets in `VITE_*` variables because browser bundles are public.
- Convert status codes and server response messages into user-facing UI states.
- Centralize repeated authorization headers or logout behavior in the API client.

## 16. Debugging API Problems: a Checklist

1. Open **DevTools → Network → Fetch/XHR**. Is the request sent? What is the status code?
2. Click the request → **Response** tab. What does the JSON look like? Is the data in `data.products` or directly in `data`?
3. Open the **Console**. Any red errors?
4. `console.log(data)` right after `response.json()`.
5. Did you forget `response.ok`?
6. Is the URL correct (template string with backticks, no typos)?
7. Did you restart Vite after changing `.env`?
8. `undefined` errors on first render: the data is not there yet. Use a loading state or optional chaining (`product?.title`).

## 16. Common Mistakes

| Mistake | Why it is wrong | Fix |
|---|---|---|
| `fetch` in the component body | Infinite loop of renders | Use `useEffect` |
| `useEffect(async () => ...)` | Effect cannot return a Promise | Inner async function |
| No `response.ok` check | 404 treated as success | `if (!response.ok) throw ...` |
| Missing dependency | Stale data | Add the value to the dependency array |
| Forgetting `setLoading(false)` in `catch` | Spinner forever | Use `finally` |
| Using `products.map` before data exists | `undefined` crash | Start with `[]` and handle loading |
| Hard-coded URL in every component | Hard to change | Service file + `.env` |
| Secret keys in `VITE_` variables | Visible to everyone | Keep secrets on a backend |
| Ignoring `AbortError` | Fake error messages | Check `err.name` |
