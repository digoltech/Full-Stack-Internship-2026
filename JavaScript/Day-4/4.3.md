# Day 4.3 — Asynchronous JavaScript in Depth

## Learning Objectives

By the end of this session, students should understand callbacks, callback hell, Promises, Promise chaining, `async/await`, asynchronous error handling, timers, API requests, and concurrent execution.

The objective is not simply to memorize syntax. Students should understand how asynchronous operations behave and choose the appropriate approach for real applications.

## 1. Why Do We Need Asynchronous JavaScript?

Applications frequently perform operations that take time, such as:

- Fetching data from an API.
- Reading files in Node.js.
- Querying a database.
- Waiting for a timer.
- Receiving network responses.

If JavaScript waited synchronously for every slow operation on the main thread, browser applications could become unresponsive.

Asynchronous programming allows the application to initiate an operation and continue executing other work while waiting for its result.

```javascript
console.log("Request started");

setTimeout(() => {
  console.log("Response received");
}, 1000);

console.log("Other work continues");
```

**Output:**

```text
Request started
Other work continues
Response received
```

The timer is used here to demonstrate asynchronous scheduling. Real network and database operations use their respective runtime APIs.

## 2. Callbacks

A callback is a function passed to another function to be executed later or at a particular point in its operation.

### Basic Callback

```javascript
function processUser(name, callback) {
  console.log(`Processing ${name}`);
  callback();
}

function completed() {
  console.log("Processing completed");
}

processUser("Asha", completed);
```

**Output:**

```text
Processing Asha
Processing completed
```

Callbacks are not necessarily asynchronous. In this example, the callback executes synchronously.

### Asynchronous Callback

```javascript
function getUser(callback) {
  setTimeout(() => {
    callback({ id: 1, name: "Asha" });
  }, 1000);
}

getUser(user => {
  console.log(user.name);
});

console.log("Request scheduled");
```

The message `Request scheduled` appears before `Asha` because the callback runs after the timer delay.

## 3. Callback Hell

When several asynchronous operations depend on the results of previous operations, nested callbacks can become difficult to read.

```javascript
getUser(userId => {
  getOrders(userId, orders => {
    getOrderDetails(orders[0].id, details => {
      sendConfirmation(details, result => {
        console.log(result);
      });
    });
  });
});
```

This structure is often called **callback hell** when nesting becomes deep and difficult to maintain.

Problems can include:

- Difficult-to-follow control flow.
- Repeated error-handling logic.
- Harder debugging and testing.
- Tightly coupled operations.

Callbacks are still useful, but Promises and `async/await` often provide a clearer approach to dependent asynchronous operations.

## 4. What Is a Promise?

A Promise is an object representing the eventual success or failure of an asynchronous operation.

A Promise has three states:

- **Pending:** The operation has not settled.
- **Fulfilled:** The operation completed successfully.
- **Rejected:** The operation failed.

Once a Promise is fulfilled or rejected, it is settled and does not transition to the other state.

### Creating a Promise

```javascript
const task = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Task completed");
  } else {
    reject(new Error("Task failed"));
  }
});

task
  .then(result => console.log(result))
  .catch(error => console.error(error.message));
```

`resolve()` fulfills the Promise with a value in this example. `reject()` rejects it with an error.

The Promise executor runs immediately when the Promise is constructed. Promise reactions registered with `.then()` and `.catch()` execute asynchronously as microtasks.

## 5. Consuming Promises with `.then()`, `.catch()`, and `.finally()`

### `.then()`

Handles a fulfilled Promise and can transform its result.

```javascript
Promise.resolve(10)
  .then(value => value * 2)
  .then(value => console.log(value));
```

Output: `20`.

### `.catch()`

Handles a rejection that reaches the catch handler.

```javascript
Promise.reject(new Error("Something failed"))
  .catch(error => {
    console.log(error.message);
  });
```

Output: `Something failed`.

### `.finally()`

Runs after the Promise settles, regardless of whether it was fulfilled or rejected.

```javascript
Promise.resolve("Success")
  .then(result => console.log(result))
  .finally(() => console.log("Finished"));
```

Output:

```text
Success
Finished
```

`finally()` is useful for cleanup actions, such as resetting a loading indicator. Its callback normally does not receive the original result or rejection reason.

## 6. Promise Chaining

Promise chaining allows one asynchronous operation to follow another.

```javascript
function getPrice() {
  return Promise.resolve(100);
}

getPrice()
  .then(price => price * 2)
  .then(total => total + 50)
  .then(result => {
    console.log(result);
  })
  .catch(error => {
    console.error(error.message);
  });
```

Output: `250`.

Each `.then()` returns a new Promise. The next handler receives the value returned by the previous handler.

### Returning a Promise from `.then()`

```javascript
function getUser() {
  return Promise.resolve({ id: 1, name: "Asha" });
}

function getOrders(userId) {
  return Promise.resolve(["Order A", "Order B"]);
}

getUser()
  .then(user => {
    console.log(user.name);
    return getOrders(user.id);
  })
  .then(orders => {
    console.log(orders);
  })
  .catch(error => console.error(error));
```

The next handler waits for the Promise returned by `getOrders()` to settle.

**Important:** If you forget to return a Promise from a `.then()` handler, the chain will not wait for that unreturned operation.

## 7. Error Propagation in Promise Chains

An error thrown inside a `.then()` handler rejects the Promise returned by that handler.

```javascript
Promise.resolve(10)
  .then(value => {
    if (value < 20) {
      throw new Error("Value is too small");
    }

    return value;
  })
  .then(value => console.log(value))
  .catch(error => console.error(error.message));
```

Output: `Value is too small`.

The second `.then()` does not execute because the previous handler throws an error. The rejection reaches `.catch()`.

A `.catch()` handler can also recover by returning a normal value, allowing the subsequent chain to continue.

## 8. What Is `async/await`?

`async/await` provides a more readable way to work with Promises.

An `async` function always returns a Promise. If it returns a regular value, that value becomes the fulfillment value of the Promise.

```javascript
async function getMessage() {
  return "Hello";
}

getMessage().then(message => console.log(message));
```

Output: `Hello`.

### Using `await`

```javascript
function getNumber() {
  return new Promise(resolve => {
    setTimeout(() => resolve(20), 1000);
  });
}

async function displayNumber() {
  console.log("Waiting");

  const number = await getNumber();

  console.log(number);
}

displayNumber();
```

Output order:

```text
Waiting
20
```

The function suspends at `await` until the Promise settles, then resumes with the result.

## 9. Sequential Asynchronous Operations

Use sequential `await` when the second operation depends on the first operation's result.

```javascript
function getUser() {
  return Promise.resolve({ id: 1, name: "Asha" });
}

function getOrders(userId) {
  return Promise.resolve([
    { id: 101, userId },
    { id: 102, userId }
  ]);
}

async function displayOrders() {
  const user = await getUser();
  const orders = await getOrders(user.id);

  console.log(user.name);
  console.log(orders);
}

displayOrders();
```

The order matters because `getOrders()` needs the user's ID.

## 10. Error Handling with `async/await`

Use `try...catch` around awaited operations that may fail.

```javascript
async function loadProfile() {
  try {
    const profile = await Promise.reject(
      new Error("Unable to load profile")
    );

    console.log(profile);
  } catch (error) {
    console.error("Profile error:", error.message);
  } finally {
    console.log("Loading finished");
  }
}

loadProfile();
```

The error is caught, and the `finally` block executes afterward.

**Important:** A `try...catch` handles errors from operations awaited inside the `try` block. If you start an asynchronous operation without awaiting it or returning its Promise, its rejection may not be caught by that surrounding `try...catch`.

## 11. `fetch()` and HTTP Requests

The browser's `fetch()` API sends HTTP requests and returns a Promise for a `Response` object.

```javascript
async function loadUsers() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users"
    );

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const users = await response.json();

    console.log(users);
  } catch (error) {
    console.error("Unable to load users:", error.message);
  }
}

loadUsers();
```

The request flow is:

1. `fetch()` starts the request.
2. `await` waits for the response Promise.
3. `response.ok` checks whether the HTTP status indicates success.
4. `response.json()` reads and parses the response body asynchronously.
5. The parsed data becomes available for processing.
6. `catch` handles network failures, thrown HTTP errors, and body-parsing errors.

**Important:** A 404 or 500 response does not automatically reject the `fetch()` Promise. Always check `response.ok` when an unsuccessful HTTP response should be treated as an error.

## 12. Promise Combinators

JavaScript provides methods for coordinating multiple Promises.

### `Promise.all()`

Waits for all input Promises to fulfill. Rejects if any input Promise rejects.

```javascript
const results = await Promise.all([
  Promise.resolve("Users"),
  Promise.resolve("Posts")
]);

console.log(results);
```

Output: `["Users", "Posts"]`.

### `Promise.allSettled()`

Waits for all input Promises to settle and returns the outcome of each.

```javascript
const results = await Promise.allSettled([
  Promise.resolve("Success"),
  Promise.reject(new Error("Failed"))
]);

console.log(results);
```

The result contains one fulfilled outcome and one rejected outcome.

### `Promise.race()`

Settles with the outcome of the first input Promise to settle, whether fulfilled or rejected.

```javascript
const result = await Promise.race([
  new Promise(resolve => setTimeout(() => resolve("First"), 100)),
  new Promise(resolve => setTimeout(() => resolve("Second"), 200))
]);

console.log(result); // First
```

### `Promise.any()`

Fulfills with the first fulfilled input Promise. If all inputs reject, it rejects with an `AggregateError`.

```javascript
const result = await Promise.any([
  Promise.reject(new Error("Failed")),
  Promise.resolve("Available")
]);

console.log(result); // Available
```

### Comparison

| Method | Behavior |
|---|---|
| `Promise.all()` | Requires every input to fulfill |
| `Promise.allSettled()` | Reports every input's outcome |
| `Promise.race()` | Uses the first settled outcome |
| `Promise.any()` | Uses the first fulfilled outcome |

These methods coordinate Promises; they do not automatically create extra JavaScript threads.

## 13. Sequential vs Concurrent Execution

Consider two independent operations:

```javascript
async function getUsers() {
  return new Promise(resolve => {
    setTimeout(() => resolve("Users loaded"), 1000);
  });
}

async function getPosts() {
  return new Promise(resolve => {
    setTimeout(() => resolve("Posts loaded"), 1000);
  });
}
```

### Sequential

```javascript
async function sequential() {
  const users = await getUsers();
  const posts = await getPosts();

  console.log(users, posts);
}

sequential();
```

The second operation starts after the first finishes. In this example, total waiting time is approximately two seconds.

### Concurrent

```javascript
async function concurrent() {
  const [users, posts] = await Promise.all([
    getUsers(),
    getPosts()
  ]);

  console.log(users, posts);
}

concurrent();
```

Both operations are started before awaiting their combined result. In this example, total waiting time is approximately one second.

**Rule:** Use sequential `await` when operations depend on each other. Use concurrent execution when independent operations can safely start together.

## 14. Timers and Promise Scheduling

Timers and Promise reactions are scheduled differently.

```javascript
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => console.log("C"));

console.log("D");
```

Output:

```text
A
D
C
B
```

The synchronous code executes first, then the Promise microtask, followed by the eligible timer task in this example.

Do not use `setTimeout(fn, 0)` as a precise timing mechanism. It schedules a callback for a later task; it does not guarantee immediate execution.

## 15. Common Asynchronous Mistakes

### Mistake 1 — Forgetting `await`

```javascript
async function loadData() {
  const data = fetch("/api/users");

  console.log(data);
}
```

Here, `data` is a Promise, not the parsed user data.

A corrected version:

```javascript
async function loadData() {
  const response = await fetch("/api/users");

  if (!response.ok) {
    throw new Error("Request failed");
  }

  const data = await response.json();

  console.log(data);
}
```

The URL is an example endpoint and must be replaced with a valid route for the application.

### Mistake 2 — Not Returning a Promise

```javascript
getUser()
  .then(user => {
    getOrders(user.id);
  })
  .then(orders => {
    console.log(orders);
  });
```

The second handler receives `undefined` because the first handler does not return the `getOrders()` Promise.

Correct version:

```javascript
getUser()
  .then(user => {
    return getOrders(user.id);
  })
  .then(orders => {
    console.log(orders);
  })
  .catch(error => console.error(error));
```

### Mistake 3 — Assuming `try...catch` Catches Every Rejection

```javascript
async function example() {
  try {
    fetch("/api/users");
  } catch (error) {
    console.error(error);
  }
}
```

The request Promise is neither awaited nor returned. A later rejection is not caught by this `try...catch`.

Correct version:

```javascript
async function example() {
  try {
    const response = await fetch("/api/users");

    if (!response.ok) {
      throw new Error("Request failed");
    }
  } catch (error) {
    console.error(error.message);
  }
}
```

### Mistake 4 — Using Sequential `await` for Independent Requests

```javascript
const users = await getUsers();
const posts = await getPosts();
```

If these operations are independent, use `Promise.all()` to allow them to proceed concurrently.
