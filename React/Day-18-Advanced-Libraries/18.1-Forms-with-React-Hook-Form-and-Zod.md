# 18.1 — Forms with React Hook Form and Zod

**Goal:** Build a validated form and understand how form state, validation rules, and submission fit together.

## 1. Why Use a Form Library?

A small form can use React state directly. As a form grows, you need to coordinate field values, touched fields, validation errors, submission state, and focus. Re-implementing those details for every form creates repetitive code and inconsistent behavior.

React Hook Form manages form state and field registration. Zod describes valid data with a schema. The Zod resolver connects the schema to React Hook Form.

## 2. Install the Packages

```bash
npm install react-hook-form zod @hookform/resolvers
```

## 3. Create a Schema

A schema describes the shape and rules for valid data:

```jsx
import { z } from 'zod';

const inviteSchema = z.object({
  name: z.string().trim().min(2, 'Name must contain at least 2 characters.'),
  email: z.string().trim().email('Enter a valid email address.'),
  role: z.enum(['Developer', 'Designer', 'Product Manager']),
});
```

The rules are data constraints, not just visual hints. A real server must validate the submitted request too, because browser-side checks can be bypassed.

## 4. Connect the Schema to the Form

```jsx
import { useState } from 'react';
import { zodResolver } from '@hookform/resolvers/zod';
import { useForm } from 'react-hook-form';
import { z } from 'zod';

const inviteSchema = z.object({
  name: z.string().trim().min(2, 'Name must contain at least 2 characters.'),
  email: z.string().trim().email('Enter a valid email address.'),
  role: z.enum(['Developer', 'Designer', 'Product Manager']),
});

export function InviteMemberForm() {
  const [submittedName, setSubmittedName] = useState('');
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
    reset,
  } = useForm({
    resolver: zodResolver(inviteSchema),
    defaultValues: { name: '', email: '', role: 'Developer' },
  });

  async function onSubmit(values) {
    // Replace this demo with an API request in a real feature.
    await new Promise((resolve) => setTimeout(resolve, 300));
    setSubmittedName(values.name);
    reset();
  }

  return (
    <form noValidate onSubmit={handleSubmit(onSubmit)}>
      <div>
        <label htmlFor="member-name">Name</label>
        <input
          id="member-name"
          autoComplete="name"
          aria-invalid={Boolean(errors.name)}
          aria-describedby={errors.name ? 'member-name-error' : undefined}
          {...register('name')}
        />
        {errors.name && <p id="member-name-error" role="alert">{errors.name.message}</p>}
      </div>

      <div>
        <label htmlFor="member-email">Email</label>
        <input
          id="member-email"
          type="email"
          autoComplete="email"
          aria-invalid={Boolean(errors.email)}
          aria-describedby={errors.email ? 'member-email-error' : undefined}
          {...register('email')}
        />
        {errors.email && <p id="member-email-error" role="alert">{errors.email.message}</p>}
      </div>

      <div>
        <label htmlFor="member-role">Role</label>
        <select id="member-role" {...register('role')}>
          <option value="Developer">Developer</option>
          <option value="Designer">Designer</option>
          <option value="Product Manager">Product Manager</option>
        </select>
      </div>

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Sending…' : 'Invite member'}
      </button>
      {submittedName && <p role="status">Invitation prepared for {submittedName}.</p>}
    </form>
  );
}
```

### Follow the Data Flow

1. `register('name')` connects the input to React Hook Form.
2. Submitting calls `handleSubmit`, which runs the resolver.
3. Invalid data populates `errors`; valid data reaches `onSubmit`.
4. `isSubmitting` helps prevent duplicate submissions and communicate progress.
5. `reset()` returns fields to their configured defaults after success.

`aria-invalid` and `aria-describedby` connect a field to its error text. Labels should remain visible; placeholder text is not a replacement for a label.

## 5. Show a Server Error

Client validation cannot predict every server result. Keep a separate form-level message for cases such as a duplicate email or network failure:

```jsx
const [submitError, setSubmitError] = useState('');

async function onSubmit(values) {
  setSubmitError('');
  try {
    await createInvitation(values);
    reset();
  } catch {
    setSubmitError('We could not send the invitation. Please try again.');
  }
}
```

Render `submitError` near the form and make it perceivable, for example with `role="alert"`. Do not show raw server stack traces to users.

## 6. Common Mistakes

- Forgetting to connect the resolver, so the schema never runs.
- Using `placeholder` instead of a real label.
- Disabling submit without explaining that the form is submitting.
- Treating client validation as security or server validation.
- Showing an error only by color, without text.
- Reusing error element IDs across repeated form instances.

## Practice

Add a `department` field with a limited set of valid values. Add a minimum name length, test empty and malformed email values, and confirm the success status is announced after submission.
