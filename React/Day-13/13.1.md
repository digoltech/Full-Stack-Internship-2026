# Week 4 — Day 13.1: Component Testing and Debugging

**Topics:** Vitest, Testing Library, user events, pure-function tests

## 1. Test Setup

```bash
npm install -D vitest @testing-library/react @testing-library/user-event jsdom
```

Configure Vitest in `vite.config.js` and add a test script to `package.json`.

## 2. Testing Components

```jsx
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import Counter from "./Counter";

test("increments the counter", async () => {
  const user = userEvent.setup();
  render(<Counter />);

  await user.click(screen.getByRole("button", { name: "Increase" }));

  expect(screen.getByText("1")).toBeInDocument();
});
```

- Query by role and accessible name rather than implementation details.
- Use `userEvent` for realistic interaction.
- Test behavior from the user's point of view.
- Add setup for `jest-dom` matchers only if the package is installed.

## 3. Testing Pure Logic

Extract filtering and sorting functions into utility files. Test them with no browser UI:

```js
expect(filterProducts(products, "phone")).toEqual([...]);
```

## 4. Debugging a Broken Application

- Read the first error and find the real failing line.
- Reproduce the bug with one minimal action.
- Inspect props, state, URL parameters, network data, and browser storage.
- Test one hypothesis at a time.
- Add a focused regression test after fixing the bug.
