# 1.1

1. What is React?
React is a JavaScript library for building user interfaces. It helps
developers split a screen into smaller pieces called components,
then compose those pieces into complete pages and applications.

A user interface (UI) is everything the user sees and interacts with:
navigation bars, forms, buttons, cards, menus, lists, dashboards, and so
on.
Real-life example: an online shopping website
A shopping page may contain:
- A header with a logo and search bar
- A navigation menu
- Product cards
- A cart summary
- A footer
Instead of building the entire page as one large block, we can create
reusable components such as Header, ProductCard, CartSummary, and
Footer.

A product card can be reused for every product. Only its data changes.
What problem does React solve?
Imagine a task manager with 50 tasks. When a user marks one task as
completed, the interface should update the task's appearance and the
completed-task count. In a traditional approach, the developer may
manually find and change multiple DOM elements. As the interface grows,
these manual updates can become difficult to maintain.

React encourages developers to describe what the UI should look like
for the current data. When the data changes, React updates the
necessary parts of the interface.

React does not eliminate JavaScript, HTML concepts, or CSS. It gives us
a structured way to build and update the UI.

2. Imperative vs declarative UI
Imperative approach
Imperative code describes the steps required to change something.
<p id="message">Not completed</p>
<button id="complete">Complete task</button>

<script>
  const button = document.querySelector("#complete");
  const message = document.querySelector("#message");

  button.addEventListener("click", () => {
    message.textContent = "Completed";
  });
</script>
The code explicitly finds DOM elements and tells the browser how to
change them.
Declarative approach
Declarative code describes the desired UI based on data. React manages
the DOM updates.
import { useState } from "react";

function TaskStatus() {
  const [completed, setCompleted] = useState(false);

  return (
    <section>
      <p>{completed ? "Completed" : "Not completed"}</p>
      <button onClick={() => setCompleted(true)}>
        Complete task
      </button>
    </section>
  );
}

export default TaskStatus;
Here, completed describes the current status. The UI is based on that
value. We will study state and events in more detail on Day 2; for now,
focus on the declarative idea.

Important: React does not mean that DOM knowledge is useless.
Understanding the DOM helps you understand what React is managing for
you.

3. What is a component?
A component is a reusable piece of UI. In modern React, components are
commonly JavaScript functions that return JSX.
function WelcomeMessage() {
  return <h1>Welcome to our internship!</h1>;
}
A component can be small, such as a button, or large, such as a complete
dashboard section.
Component composition
Composition means building a larger interface by combining smaller
components.
function Header() {
  return <header><h1>Task Manager</h1></header>;
}

function MainContent() {
  return <main><p>Manage your daily tasks here.</p></main>;
}

function Footer() {
  return <footer><small>Built by the internship team</small></footer>;
}

function App() {
  return (
    <>
      <Header />
      <MainContent />
      <Footer />
    </>
  );
}

export default App;
App composes three smaller components. Each component has a clear
responsibility.
Real-life analogy
Think of a car assembly line. A car is made from smaller systems such as
wheels, seats, lights, and a dashboard. Each system can be developed and
checked separately, then assembled into the final product. Components
support a similar style of organization in UI development.

4. What are Vite and npm?
- Node.js lets JavaScript tools run outside the browser.
- npm installs and manages packages for a JavaScript project.
- Vite provides a development server and build tooling for modern
  frontend projects.
- React is the UI library used to build the interface.
Vite is not React itself. It is one way to set up and run a React
project.

5. Check your environment
Open a terminal and run:
node --version
npm --version
You should see version numbers. If either command is not recognized,
install a supported Node.js LTS release and reopen the terminal. Use a
version compatible with the current Vite requirements.

6. Create a React project using Vite
Run these commands one at a time:
npm create vite@latest task-manager -- --template react
cd task-manager
npm install
npm run dev
What each command does:
1. npm create vite@latest ... creates a new project using Vite's
   React template.
2. cd task-manager moves into the project directory.
3. npm install installs the dependencies listed in package.json.
4. npm run dev starts the local development server.
The terminal will show a local address, often similar to
http://localhost:5173/. Open the exact address shown in your terminal.
If you already have a project
Do not create a second project unnecessarily. Move into the existing
project folder, install dependencies if needed, and run its development
script.

7. Understand the project structure
A newly generated Vite React project may look similar to this. Template
files can vary by Vite version.
task-manager/
├── node_modules/
├── public/
├── src/
│   ├── assets/
│   ├── App.css
│   ├── App.jsx
│   ├── index.css
│   └── main.jsx
├── index.html
├── package.json
├── package-lock.json
└── vite.config.js
Important files and folders
  File or folder        Purpose
  src/                Application source code
  src/App.jsx         Main application component in the starter project
  src/main.jsx        Entry point that mounts React into the HTML page
  src/index.css       Global styles
  src/App.css         Styles used by the starter App component
  public/             Static files served as-is
  index.html          HTML document containing the root element
  package.json        Project metadata, scripts, and dependencies
  package-lock.json   Records the resolved npm dependency tree
  node_modules/       Installed packages; normally not committed to Git
  vite.config.js      Vite configuration
How does the application start?
The HTML file contains a root element:
<div id="root"></div>
The React entry point finds that element and renders the application
inside it. A typical src/main.jsx resembles:
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./index.css";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
- createRoot connects React to the root DOM element.
- App is the main component.
- StrictMode helps reveal certain issues during development. In
  development, some functions or effects may run more than once to
  help identify unsafe behavior; this does not mean the production app
  will necessarily behave the same way.

9. Common setup issues
npm or node is not recognized
Install Node.js LTS, reopen the terminal, and verify the versions again.
Missing dependencies
Run npm install from the folder containing package.json.
The browser cannot open the page
Check that npm run dev is still running and use the local URL printed
in the terminal.
The terminal says the port is already in use
Vite may offer another port. Open the URL it actually prints.
The page is blank
Check the terminal and browser console. Look for misspelled imports,
syntax errors, missing exports, and incorrect component names.
A component is not displayed
Check that it is imported, included in the JSX tree, and exported
correctly.

10. Key takeaways
- React is a JavaScript library for building user interfaces.
- Components divide interfaces into reusable pieces.
- Composition combines components into a larger interface.
- Vite helps scaffold, serve, and build the project.
- main.jsx mounts the app; App.jsx commonly contains the main
  component.
- JSX lets you describe UI using a syntax that resembles HTML inside
  JavaScript.
