## Section E — Debugging Challenge (10 Marks)

Find and fix **all** the problems in the code below.

```jsx
import { useState } from "react";

function App() {
  const [tasks, setTasks] = useState(JSON.parse(localStorage.getItem("tasks")));
  const [completed, setCompleted] = useState(0);

  function addTask(title) {
    tasks.push({ id: tasks.length, title, done: false });
    setTasks(tasks);
  }

  function toggle(id) {
    const task = tasks.find((t) => t.id === id);
    task.done = !task.done;
    setCompleted(tasks.filter((t) => t.done).length);
  }

  return (
    <div>
      <button onClick={addTask("Test")}>Add</button>
      <p>Completed: {completed}</p>
      <ul>
        {tasks.map((task, index) => (
          <li key={index} onClick={() => toggle(task.id)}>
            {task.title}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default App;
```

Questions:

1. Identify at least **six** problems.
2. Rewrite the component correctly.
3. Add saving to `localStorage`.

### Section B — Expected Points

1. The parent owns the state and passes a function (`onAddTask`) to the child. The child calls it with the new data. The parent updates its state and passes the new data back down.
2. It is duplicate information that can go out of sync. It can be calculated: `tasks.filter(t => t.completed).length`.
3. Spread is shallow. Without copying `address`, the new object would share the same `address` object with the old state (mutation risk). Every level that changes must be copied.
4. Stored data can be missing or corrupted, and `JSON.parse` throws on invalid text. A crash would break the whole app on start.
5. `useState` re-renders when changed and is used for displayed data. `useRef` does not re-render; it is used for DOM access and mutable values that are not displayed.

### Section C

1. `1` (all three calls read the same `count` value of 0).
2. `3`.
3. `3 4`.
4. `"Mumbai"` (spread is shallow; the nested object is shared).
5. The screen keeps showing `Clicked 0 times`. Changing `ref.current` does not trigger a re-render, so the new value is never displayed (it is only read on the next render caused by something else). Use `useState` for values that must appear on screen.

### Section E — Problems and Fix

Problems:

1. `JSON.parse(null)` returns `null`, so `tasks` may be `null` and `tasks.map` crashes. Use a fallback (`?? []`) with `try/catch`.
2. `JSON.parse(...)` is evaluated on every render; use a lazy initialiser.
3. `completed` is duplicate state; derive it.
4. `tasks.push` mutates state.
5. `setTasks(tasks)` passes the same reference.
6. `id: tasks.length` can create duplicate ids after deletion; use `crypto.randomUUID()`.
7. `toggle` mutates the task object.
8. `onClick={addTask("Test")}` calls the function during render.
9. `key={index}` is a poor key for changing lists.
10. Nothing writes to `localStorage`.

Corrected version:

```jsx
import { useEffect, useState } from "react";

function loadTasks() {
  try {
    return JSON.parse(localStorage.getItem("tasks")) ?? [];
  } catch {
    return [];
  }
}

function App() {
  const [tasks, setTasks] = useState(loadTasks);

  useEffect(() => {
    localStorage.setItem("tasks", JSON.stringify(tasks));
  }, [tasks]);

  function addTask(title) {
    setTasks((prev) => [...prev, { id: crypto.randomUUID(), title, done: false }]);
  }

  function toggle(id) {
    setTasks((prev) =>
      prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t))
    );
  }

  const completed = tasks.filter((t) => t.done).length;

  return (
    <div>
      <button onClick={() => addTask("Test")}>Add</button>
      <p>Completed: {completed}</p>
      <ul>
        {tasks.map((task) => (
          <li key={task.id} onClick={() => toggle(task.id)}>
            {task.title}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default App;
```
