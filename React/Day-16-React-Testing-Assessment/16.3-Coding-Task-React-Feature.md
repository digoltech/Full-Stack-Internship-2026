# 15.3 — React Coding Tasks

**Total Marks:** 75  
**Suggested Duration:** 150–180 minutes

## Coding Task 1 — Components, State, and Forms (25 Marks)

Build a React `Course Manager` interface.

### Requirements

1. Create at least six course or task objects.
2. Render cards using `map()` and stable `id` keys.
3. Add a controlled search input.
4. Add All, Active, and Completed filters.
5. Add one form for creating a course or task.
6. Validate required fields and display errors.
7. Implement add, edit, and delete operations.
8. Use immutable state updates.
9. Derive counts and filtered items instead of duplicating state.
10. Add loading, empty, and success states.

## Coding Task 2 — Routing and API Integration (25 Marks)

Build a routed product or job catalogue.

### Requirements

1. Create at least four routes.
2. Build a shared layout with navigation and `<Outlet />`.
3. Add a list route and dynamic details route.
4. Use `useParams()` for the details page.
5. Add search and at least one filter.
6. Store search and filter state in the URL when appropriate.
7. Fetch list and details data from a public API.
8. Create a service module for API requests.
9. Handle loading, error, empty, and success states.
10. Use `AbortController` or an ignore-outdated-response guard.

## Coding Task 3 — Context, Hooks, and Testing (25 Marks)

Improve a React application with reusable state and tests.

### Requirements

1. Create a Context provider for theme or cart state.
2. Use `useReducer` for at least one complex state area.
3. Add a custom hook that contains reusable logic.
4. Add a local-storage hook or persistence utility.
5. Use `useMemo`, `useCallback`, or `React.memo` only where it has purpose.
6. Add at least one reusable UI component.
7. Install Vitest and React Testing Library.
8. Add a test script to `package.json`.
9. Test at least five user interactions or reducer scenarios.
10. Test one loading, empty, error, or no-results state.

## Submission Checklist

- [ ] The app runs with `npm run dev`.
- [ ] Tests run with `npm test`.
- [ ] `npm run build` succeeds.
- [ ] No direct state mutation remains.
- [ ] Role and label queries are used in component tests.
- [ ] The UI is responsive and keyboard accessible.
- [ ] A README explains setup, features, architecture, and test commands.

## Viva Questions

1. Which state is owned at component level, Context level, or reducer level?
2. Why should derived values not be stored separately?
3. How does `useParams()` read dynamic route values?
4. How can a custom hook improve code reuse?
5. Which React test interactions prove actual user behavior?
