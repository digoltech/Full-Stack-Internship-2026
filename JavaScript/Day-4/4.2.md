# Day 4.2 — Error Handling and Debugging

## Learning Objectives

Students should be able to recognize common JavaScript errors, handle exceptions with `try...catch`, create meaningful error messages, and debug code systematically.

## 1. Common JavaScript Errors

### Syntax Error

Occurs when JavaScript cannot parse the code.

```javascript
// Missing closing parenthesis
console.log("Hello";
```

### Reference Error

Occurs when code accesses an identifier that is not defined in the current accessible scope.

```javascript
console.log(userName);
```

If `userName` has not been declared in an accessible scope, JavaScript throws a `ReferenceError`.

### Type Error

Occurs when an operation is invalid for a particular value.

```javascript
const user = null;

console.log(user.name);
```

This throws a `TypeError` because properties cannot be accessed directly on `null`.

## 2. Using `try...catch`

`try...catch` lets you handle certain runtime exceptions instead of allowing them to terminate the current execution path unexpectedly.

```javascript
try {
  const user = null;
  console.log(user.name);
} catch (error) {
  console.log("Something went wrong.");
  console.log(error.message);
}
```

The `try` block contains the risky operation. If it throws an exception, execution moves to the `catch` block.

## 3. Using `finally`

The `finally` block runs after the `try` and `catch` processing, whether an exception occurred or not.

```javascript
try {
  console.log("Processing started");
} catch (error) {
  console.log(error.message);
} finally {
  console.log("Processing finished");
}
```

This can be useful for cleanup operations.

## 4. Throwing Custom Errors

Use `throw` when your code detects a condition that should be treated as an error.

```javascript
function withdraw(balance, amount) {
  if (amount <= 0) {
    throw new Error("Amount must be greater than zero");
  }

  if (amount > balance) {
    throw new Error("Insufficient balance");
  }

  return balance - amount;
}

try {
  console.log(withdraw(1000, 1200));
} catch (error) {
  console.log(error.message);
}
```

Validate inputs and communicate failures clearly instead of silently returning incorrect results.

## 5. Debugging with `console`

Useful console methods include:

```javascript
console.log("Normal information");
console.warn("Warning message");
console.error("Error message");
console.table([
  { name: "Asha", marks: 80 },
  { name: "Ravi", marks: 65 }
]);
```

`console.table()` is particularly helpful when inspecting arrays of objects.

## 6. Browser DevTools

Students should practice the following workflow:

1. Open the browser's Developer Tools.
2. Inspect the **Console** for errors.
3. Add a breakpoint in the **Sources** panel.
4. Execute the program step by step.
5. Inspect variable values and the call stack.
6. Fix the issue and test the program again.

A debugger statement can also pause execution:

```javascript
function calculateTotal(price, quantity) {
  debugger;

  return price * quantity;
}

calculateTotal(100, 3);
```

When browser DevTools are open, execution pauses at `debugger`.

## 7. Handling JSON Parsing Errors

JSON parsing can throw an error if the input is invalid.

```javascript
const input = '{"name":"Asha"}';

try {
  const data = JSON.parse(input);
  console.log(data.name);
} catch (error) {
  console.error("Invalid JSON:", error.message);
}
```

This is useful when working with data received from files or external sources.

## Practice Tasks

### Task 1 — Identify Errors
Write one example each of a `SyntaxError`, `ReferenceError`, and `TypeError`. Explain the cause of each.

### Task 2 — Input Validation
Write a function that accepts a person's age and throws an error if the age is negative.

### Task 3 — Safe JSON Parsing
Create a function that parses a JSON string and handles invalid input using `try...catch`.

### Task 4 — Debugging
Create a function that calculates the average of an array of numbers. Use breakpoints or console statements to find why it returns an incorrect result when the array is empty.

### Task 5 — Error Messages
Write a `divide(a, b)` function that throws an error if `b` is zero. Handle the error when calling the function.

## Review Questions

1. What is the difference between a syntax error and a runtime error?
2. What is the purpose of `try...catch`?
3. When does the `finally` block execute?
4. What does the `throw` keyword do?
5. How can breakpoints help debug an application?

## Completion Criteria

Students can identify common errors, handle exceptions, validate function inputs, and use browser DevTools to trace program execution.
