# 20.1 — Easy Projects (7 Projects)

**Level:** Beginner · **Time per project:** 1–2 weeks · **Goal:** Ship your first complete, deployed React app.

Read [20.0 — Project Guide and Standards](20.0-Project-Guide-and-Standards.md) first. Every project below assumes that guide's folder structure, Git rules, and Definition of Done.

### What "Easy" means here

- One main screen, maybe one detail screen.
- Data comes from a public API, a local JSON file, or `localStorage`.
- No authentication, no payments, no real backend.
- You can finish the core flow in a few days and spend the rest polishing.

### What you must still do (even on Easy)

- All four states: loading, empty, error, success.
- Responsive at 375px and 1440px.
- Deployed live link.
- README with screenshots.
- At least 2 tests.
- Conventional Commits.

## Project 1 — Weather Dashboard

### Definition

A single-page app that shows current weather and a short forecast for a city the user searches, with the last searched city remembered between visits.

### What You Will Build

A search box at the top. When the user types a city and submits, the app calls a weather API and renders a card with temperature, condition icon, humidity, wind, and a 5-day forecast strip. The last city is saved to `localStorage` and loaded automatically on the next visit. A "Use my location" button uses the browser Geolocation API. The background subtly changes with the condition (sunny, rain, snow, night).

### Use Cases

- **Daily check:** A user opens the app each morning and sees their saved city's weather in one glance.
- **Travel planning:** A user searches several cities before a trip and compares the 5-day forecast.
- **Learning geolocation:** A user taps "Use my location" instead of typing a city name.
- **Portfolio demo:** A reviewer opens the live link and immediately sees a working API integration.

### Suggested Features

- City search with debounce (300ms).
- Current conditions card + 5-day forecast list.
- Unit toggle: °C / °F (persisted).
- Recent searches (last 5, persisted).
- Geolocation button with permission handling.
- Condition-based background or icon.
- "Last updated" timestamp and a refresh button.

### Tech Stack

React · Vite · Tailwind CSS · Open-Meteo (no key) or OpenWeatherMap (free key) · `localStorage` · Vitest + RTL

### Reference

- API: [Open-Meteo](https://open-meteo.com/en/docs) — free, no key, includes geocoding.
- API: [OpenWeatherMap](https://openweathermap.org/api) — free tier, needs a key.
- Geocoding: [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api)
- Geolocation: [MDN — Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API)
- UI inspiration: [Dribbble — weather app](https://dribbble.com/tags/weather-app)
- Icons: [Lucide — weather icons](https://lucide.dev/icons/?search=cloud)
- Weather icon set: [Weather Icons](https://erikflowers.github.io/weather-icons/)

### Stretch Goals

- Hourly forecast chart.
- Air quality index.
- Multiple saved cities with a switcher.

## Project 2 — Movie / TV Search App

### Definition

A search app that lets a user find movies and TV shows by title or keyword and view details such as poster, rating, overview, and release date.

### What You Will Build

A search input with a debounced query. Results render as a responsive poster grid. Clicking a poster opens a detail view (route or modal) with a larger backdrop, overview, rating, and genres. A "Watchlist" button saves titles to `localStorage`, viewable on a separate page.

### Use Cases

- **"What was that movie?"** A user remembers a partial title and searches for it.
- **Watchlist building:** A user saves titles to watch later without creating an account.
- **Comparison:** A user checks ratings and release dates before choosing what to watch.
- **Portfolio demo:** Shows API search, routing, and persisted state in one small app.

### Suggested Features

- Debounced search (300ms).
- Poster grid with lazy-loaded images.
- Detail route `/movie/:id` with backdrop and overview.
- Watchlist page with add/remove.
- Empty state for "no results".
- Loading skeletons for the grid.
- Error state with retry.

### Tech Stack

React · Vite · Tailwind CSS · React Router · TanStack Query · TMDB API · `localStorage`

### Reference

- API: [TMDB — Getting Started](https://developer.themoviedb.org/docs/getting-started) (free key, attribution required)
- API: [OMDb](https://www.omdbapi.com/) (alternative, free key)
- Routing: [React Router — Tutorial](https://reactrouter.com/start/library/tutorial)
- Data fetching: [TanStack Query — Quick Start](https://tanstack.com/query/latest/docs/framework/react/quick-start)
- UI inspiration: [Dribbble — movie app](https://dribbble.com/tags/movie-app)
- Image placeholder: [TMDB image sizes guide](https://developer.themoviedb.org/docs/image-basics)

### Stretch Goals

- Genre filter chips.
- Infinite scroll on search results.
- "Similar movies" section on the detail page.

## Project 3 — Recipe Finder

### Definition

An app where a user searches recipes by name or ingredient, opens a recipe, and saves favourites for later.

### What You Will Build

A search bar plus category chips (Breakfast, Dessert, Vegetarian…). Results show a card with image, title, and category. The detail view shows ingredients, step-by-step instructions, and a YouTube link if available. Favourites are stored in `localStorage` and shown on a `/favourites` route with a count badge in the navbar.

### Use Cases

- **"What can I cook?"** A user searches by an ingredient they already have.
- **Meal planning:** A user browses a category and saves several recipes for the week.
- **Shopping list:** A user opens a saved recipe and reads the ingredient list at the store.
- **Learning:** A user follows the numbered instructions step by step.

### Suggested Features

- Search by name and by ingredient.
- Category filter chips.
- Recipe detail with ingredients and numbered steps.
- Favourites with add/remove and a navbar count.
- Random recipe button.
- Empty and error states.
- Skeleton cards while loading.

### Tech Stack

React · Vite · Tailwind CSS · React Router · TheMealDB API · `localStorage`

### Reference

- API: [TheMealDB](https://www.themealdb.com/api.php) (free test key `1`)
- API: [TheCocktailDB](https://www.thecocktaildb.com/api.php) (same format, good for a variant)
- Routing: [React Router — Docs](https://reactrouter.com/)
- UI inspiration: [Dribbble — recipe app](https://dribbble.com/tags/recipe-app)
- Icons: [Lucide — utensils](https://lucide.dev/icons/?search=utensils)

### Stretch Goals

- Shopping list generated from ingredients.
- Filter by area/cuisine.
- "Surprise me" random recipe on the home page.

## Project 4 — Personal Task Manager (To-Do)

### Definition

A task manager where a user adds, edits, completes, deletes, and filters tasks, with everything saved in the browser.

### What You Will Build

An input to add a task. Each task has a title, a completed checkbox, and a delete button. Filters: All / Active / Completed. A counter shows remaining tasks. Tasks persist in `localStorage` and survive refresh. Optional: due date, priority tag, and drag-to-reorder.

### Use Cases

- **Daily planning:** A user adds today's tasks in the morning and checks them off.
- **Study tracking:** A student lists assignments and filters to see what is left.
- **Offline use:** A user on a plane keeps working because data is local.
- **Learning CRUD:** The simplest complete create/read/update/delete flow in React.

### Suggested Features

- Add, edit (inline), toggle, delete.
- Filters: All / Active / Completed.
- Remaining count.
- Clear completed.
- Persist to `localStorage` with a custom `useLocalStorage` hook.
- Empty state per filter.
- Keyboard: Enter to add, Escape to cancel edit.

### Tech Stack

React · Vite · Tailwind CSS · `useReducer` + Context · `localStorage` · Vitest + RTL

### Reference

- State: [React — `useReducer`](https://react.dev/reference/react/useReducer)
- Context: [React — Passing Data Deeply with Context](https://react.dev/learn/passing-data-deeply-with-context)
- Storage: [MDN — `Window.localStorage`](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)
- UI inspiration: [TodoMVC](https://todomvc.com/) · [Dribbble — todo app](https://dribbble.com/tags/todo-app)
- Testing: [React Testing Library — Intro](https://testing-library.com/docs/react-testing-library/intro/)

### Stretch Goals

- Drag-and-drop reorder with `@dnd-kit/core`.
- Due dates with overdue highlighting.
- Undo delete via a toast.

## Project 5 — Quiz App

### Definition

A multiple-choice quiz app that fetches questions from an API, tracks the score, shows a result screen, and lets the user restart.

### What You Will Build

A start screen with category and difficulty selectors. One question at a time with four answer buttons. On answer, the correct option is highlighted and the wrong choice (if any) turns red. A progress bar and score counter. A result screen with score, percentage, and a restart button. Optional: a timer per question and a review of wrong answers.

### Use Cases

- **Self-testing:** A student picks a topic and difficulty to practise.
- **Classroom warm-up:** A teacher runs a quick 10-question round.
- **Interview prep:** A user reviews which answers they got wrong.
- **Learning state machines:** The app moves through clear phases: idle → loading → playing → answered → finished.

### Suggested Features

- Category and difficulty selection.
- One question at a time with shuffled answers.
- Immediate feedback with correct/incorrect styling.
- Progress bar and score.
- Result screen with percentage and restart.
- Timer per question (optional).
- Error state if the API fails, with retry.

### Tech Stack

React · Vite · Tailwind CSS · Open Trivia DB · `useReducer` · Vitest + RTL

### Reference

- API: [Open Trivia DB](https://opentdb.com/api_config.php) (no key)
- API docs: [Open Trivia DB — API](https://opentdb.com/api.php?amount=10)
- State: [React — `useReducer`](https://react.dev/reference/react/useReducer)
- UI inspiration: [Dribbble — quiz app](https://dribbble.com/tags/quiz-app)
- Accessibility: [WAI — Radio Group Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)

### Stretch Goals

- High score in `localStorage`.
- Review screen listing wrong answers.
- Sound effects on correct/incorrect.

## Project 6 — Expense Tracker

### Definition

A small money tracker where a user adds income and expense entries, sees the balance, and views a breakdown by category.

### What You Will Build

A form with amount, type (income/expense), category, and date. A list of transactions with delete. A summary card showing total income, total expenses, and balance. A simple chart (bar or donut) of spending by category. Data persists in `localStorage`. Optional: filter by month.

### Use Cases

- **Monthly budgeting:** A user logs expenses and checks the balance at month end.
- **Category awareness:** The chart shows where most money goes.
- **Learning derived state:** Totals and chart data are computed from the list, not stored separately.
- **Learning forms:** Amount validation, required category, and date handling.

### Suggested Features

- Add transaction form with validation.
- Transaction list with delete and category icon.
- Summary cards: income, expense, balance.
- Category breakdown chart.
- Month filter.
- Empty state with an "Add your first transaction" call to action.
- Currency formatting with `Intl.NumberFormat`.

### Tech Stack

React · Vite · Tailwind CSS · Recharts (or a CSS bar chart) · `localStorage` · React Hook Form

### Reference

- Charts: [Recharts — Getting Started](https://recharts.org/en-US/guide)
- Forms: [React Hook Form — Get Started](https://react-hook-form.com/get-started)
- Number formatting: [MDN — `Intl.NumberFormat`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat)
- UI inspiration: [Dribbble — finance app](https://dribbble.com/tags/finance-app)
- Design rules: [Refactoring UI](https://www.refactoringui.com/)

### Stretch Goals

- Export transactions to CSV.
- Budget per category with a progress bar.
- Dark mode toggle.

## Project 7 — Book Library

### Definition

A searchable book library where a user finds books by title or author, views details, and keeps a personal reading list.

### What You Will Build

A search input that queries Open Library. Results show cover, title, author, and year. Clicking a book opens a detail view with description and subjects. A "Want to read" / "Reading" / "Finished" status can be set per book and is saved in `localStorage`. A `/library` page groups saved books by status.

### Use Cases

- **Finding a book:** A user searches by title or author and checks the cover and year.
- **Reading list:** A user saves books and tracks reading status.
- **Book club:** A user shares their "Want to read" list.
- **Learning lists:** The library page is a real example of grouping and sorting derived data.

### Suggested Features

- Debounced search by title and author.
- Cover grid with fallback cover image.
- Detail view with description and subjects.
- Status selector: Want to read / Reading / Finished.
- Library page grouped by status.
- Empty state for "no books saved yet".
- Error state with retry.

### Tech Stack

React · Vite · Tailwind CSS · React Router · Open Library API · `localStorage`

### Reference

- API: [Open Library — Search API](https://openlibrary.org/developers/api)
- API: [Open Library — Covers](https://openlibrary.org/dev/docs/api/covers)
- Routing: [React Router — Docs](https://reactrouter.com/)
- UI inspiration: [Dribbble — book app](https://dribbble.com/tags/book-app)
- Icons: [Lucide — book](https://lucide.dev/icons/?search=book)

### Stretch Goals

- Reading progress percentage.
- Notes per book.
- Sort library by date added or title.
