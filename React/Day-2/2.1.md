## 2. What Is State in React?

State is information that a component remembers between renders.

Consider a few examples from real applications:

| Application | Example of State |
|---|---|
| E-commerce | Cart item count |
| Instagram-like app | Like count |
| Task manager | List of tasks |
| Login form | Email and password fields |
| Dashboard | Selected filter |
| Navigation | Whether a menu is open |

Whenever a user performs an action, the state may change, and React can render the updated UI.

### Example: A normal JavaScript variable

```jsx
function Counter() {
  let count = 0;

  function increase() {
    count = count + 1;
    console.log(count);
  }

  return (
    <div>
      <h2>{count}</h2>
      <button onClick={increase}>Increase</button>
    </div>
  );
}

export default Counter;
```

**Problem:** Clicking the button changes the variable, but React does not know it needs to update the displayed value. The UI remains at zero.

This is why we use React state instead of an ordinary variable for data that affects the UI.

## 3. What Is Event Handling?

Event handling allows an application to respond to user interactions.

Examples include clicking a button, typing into an input, submitting a form, or selecting an option.

### Common React events

| Event | Purpose |
|---|---|
| `onClick` | Handles a click |
| `onChange` | Handles changes in an input |
| `onSubmit` | Handles form submission |
| `onKeyDown` | Handles a keyboard key press |
| `onMouseEnter` | Handles the mouse entering an element |

### Example 1: Button Click

```jsx
function App() {
  function handleClick() {
    alert("Welcome to React!");
  }

  return (
    <button onClick={handleClick}>
      Click Me
    </button>
  );
}

export default App;
```

**Explanation:**

- `handleClick` is a JavaScript function.
- `onClick` registers that function as the click handler.
- The function executes when the user clicks the button.

### Important: Passing a function vs calling a function

Correct:

```jsx
<button onClick={handleClick}>Click</button>
```

Incorrect for a normal click handler:

```jsx
<button onClick={handleClick()}>Click</button>
```

The second example calls the function during rendering instead of waiting for a click.

### Example 2: Passing Arguments to an Event Handler

```jsx
function Greeting() {
  function greet(name) {
    alert(`Hello, ${name}!`);
  }

  return (
    <button onClick={() => greet("Rahil")}>
      Greet
    </button>
  );
}

export default Greeting;
```

We use an arrow function because we want to call `greet()` only when the user clicks the button.

## 4. Introduction to `useState`

`useState` is a React Hook used to store and update state inside a functional component.

### Syntax

```jsx
const [state, setState] = useState(initialValue);
```

The three important parts are:

- `state`: the current value.
- `setState`: the function used to request a state update.
- `initialValue`: the value used when the component initializes.

### Example: Counter Application

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>Counter</h1>
      <h2>{count}</h2>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>

      <button onClick={() => setCount(count - 1)}>
        Decrease
      </button>

      <button onClick={() => setCount(0)}>
        Reset
      </button>
    </div>
  );
}

export default Counter;
```

### How it works

1. React initializes `count` to `0`.
2. The component displays the current count.
3. When the user clicks Increase, `setCount()` requests an update.
4. React renders the component with the updated value.
5. The displayed number changes.

### Rules for using `useState`

1. Import it from React.
2. Call it at the top level of a component or custom Hook.
3. Do not call it inside loops, conditions, or nested functions.
4. Do not modify the state variable directly.
5. Use the setter function to update the state.

Incorrect:

```jsx
count = count + 1;
```

Correct:

```jsx
setCount(count + 1);
```

### Updating Based on the Previous State

When a new state value depends on the previous value, a functional update is often the safest approach.

```jsx
setCount((previousCount) => previousCount + 1);
```

For example, this is especially useful when scheduling multiple updates based on the same state value.

## 5. Using Different Types of State

State can hold strings, numbers, Boolean values, arrays, and objects.

### A. String State

```jsx
const [name, setName] = useState("Student");
```

Useful for names, search terms, and form values.

### B. Number State

```jsx
const [age, setAge] = useState(18);
```

Useful for counters, quantities, and numeric values.

### C. Boolean State

```jsx
const [isVisible, setIsVisible] = useState(true);
```

Useful for showing or hiding menus, messages, and dialogs.

### D. Array State

```jsx
const [students, setStudents] = useState([
  "Aarav",
  "Priya",
  "Neel"
]);
```

Useful for task lists, products, and student records.

To add a student without modifying the existing array:

```jsx
setStudents((previousStudents) => [
  ...previousStudents,
  "Krisha"
]);
```

### E. Object State

```jsx
const [user, setUser] = useState({
  name: "Rahil",
  role: "Developer"
});
```

To update one property while preserving the other properties:

```jsx
setUser((previousUser) => ({
  ...previousUser,
  role: "Senior Developer"
}));
```

**Remember:** Arrays and objects in state should generally be updated immutably rather than modified in place.

## 6. Handling Input Fields with State

React forms commonly use state to track what the user types. An input whose value is controlled by React state is called a controlled input.

### Example: Live Name Input

```jsx
import { useState } from "react";

function NameForm() {
  const [name, setName] = useState("");

  return (
    <div>
      <h2>Enter Your Name</h2>

      <input
        type="text"
        value={name}
        onChange={(event) => setName(event.target.value)}
        placeholder="Type your name"
      />

      <p>
        Welcome, {name || "Student"}!
      </p>
    </div>
  );
}

export default NameForm;
```

### Explanation

- `value={name}` makes the input value come from state.
- `onChange` handles changes to the input.
- `event.target.value` contains the text currently entered.
- `setName()` updates the state.
- React displays the new value in the paragraph.

## 7. What Is `useEffect`?

`useEffect` is a React Hook that lets a component synchronize with external systems.

Common examples include:

- Updating the browser tab title.
- Fetching data from an API.
- Setting up a timer.
- Registering an event listener.
- Connecting to an external service.

It is not necessary for every calculation or state update. If a value can be calculated directly from existing props or state, calculate it during rendering instead of creating an unnecessary effect.

### Basic Syntax

```jsx
import { useEffect } from "react";

useEffect(() => {
  // Synchronize with an external system.

  return () => {
    // Optional cleanup.
  };
}, [dependencies]);
```

The dependency array tells React which reactive values the effect depends on.

## 8. Understanding the Dependency Array

### Example A: No Dependency Array

```jsx
useEffect(() => {
  console.log("Effect ran");
});
```

React runs this effect after every committed render.

### Example B: Empty Dependency Array

```jsx
useEffect(() => {
  console.log("Effect initialized");
}, []);
```

The effect runs after the component mounts. React Strict Mode in development may run an additional setup-and-cleanup cycle, so it should not be treated as a guaranteed exactly-once mechanism.

### Example C: A Specific Dependency

```jsx
useEffect(() => {
  document.title = `Count: ${count}`;
}, [count]);
```

The effect runs after the initial mount and again when `count` changes.

### Summary

| Dependency Array | Behaviour |
|---|---|
| Omitted | After every committed render |
| `[]` | After mount; development Strict Mode may repeat setup |
| `[count]` | After mount and when `count` changes |

## 9. Practical Example: Counter with `useEffect`

```jsx
import { useEffect, useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Count: ${count}`;
  }, [count]);

  return (
    <div>
      <h2>Count: {count}</h2>

      <button onClick={() => setCount((c) => c + 1)}>
        Increase
      </button>
    </div>
  );
}

export default Counter;
```

**Expected behaviour:**

- The page displays the counter.
- Clicking the button increases the value.
- The browser tab title updates to reflect the new value.

This example combines state, event handling, and an effect.

## 10. Cleanup in `useEffect`

Some effects create resources that need to be released, such as intervals and event listeners.

### Example: Timer

```jsx
import { useEffect } from "react";

function Timer() {
  useEffect(() => {
    const intervalId = setInterval(() => {
      console.log("One second passed");
    }, 1000);

    return () => {
      clearInterval(intervalId);
    };
  }, []);

  return <h2>Timer is running</h2>;
}

export default Timer;
```

### Why is cleanup important?

Without cleanup, an interval or event listener may continue running when it is no longer needed.

Cleanup runs before React re-runs an effect with changed dependencies and when the component unmounts. React Strict Mode also uses an extra development setup-and-cleanup cycle to help expose incomplete cleanup logic.

## 11. Common Mistakes

### Mistake 1: Direct State Mutation

Incorrect:

```jsx
students.push("Krisha");
```

Correct:

```jsx
setStudents((previous) => [...previous, "Krisha"]);
```

### Mistake 2: Missing Dependencies

If an effect reads a reactive value, that value generally belongs in the dependency array.

```jsx
useEffect(() => {
  document.title = name;
}, [name]);
```

### Mistake 3: Using `useEffect` for Simple Calculations

Avoid storing a derived value in state if it can be calculated directly.

Instead of maintaining a separate state for completed tasks:

```jsx
const completedTasks = tasks.filter((task) => task.done).length;
```

### Mistake 4: Creating an Infinite Update Loop

An effect that updates state on every render without suitable dependencies can repeatedly trigger renders.

Students should understand why dependencies matter and avoid unnecessary state updates inside effects.
