# 1. Introduction to React Components

## 1.1 What is a component?

A component is a reusable piece of a user interface.

In React, components are commonly written as JavaScript functions that return JSX.

Example:

```jsx
function WelcomeMessage() {
  return <h1>Welcome to React!</h1>;
}

export default WelcomeMessage;
```

Here, `WelcomeMessage` is a React component.

It can be used inside another component:

```jsx
function App() {
  return (
    <main>
      <WelcomeMessage />
      <p>Let's learn React components.</p>
    </main>
  );
}

export default App;
```

The `<WelcomeMessage />` syntax tells React to render the component.

## 1.2 Real-life example: an e-commerce website

Imagine an online shopping website with 100 products.

Every product card may contain:

- Product image
- Product name
- Price
- Rating
- Availability
- Add-to-cart button

Without reusable components, you might repeatedly write the same HTML structure for every product.

With React, you can create one `ProductCard` component and reuse it for all 100 products.

The layout remains the same, but the information changes.

## 1.3 Why do we use components?

### Reusability

Write the UI once and reuse it in different places.

### Maintainability

If you change the product card layout, you can update one component instead of editing 100 separate blocks.

### Readability

Smaller components make a large application easier to understand.

### Separation of responsibilities

A header, product card, navigation menu, and footer can each have their own purpose.

### Team collaboration

Different developers can work on different components with fewer conflicts.

## 1.4 Component naming conventions

React component names should begin with a capital letter.

Correct:

```jsx
function Header() {
  return <h1>My Website</h1>;
}
```

Incorrect convention:

```jsx
function header() {
  return <h1>My Website</h1>;
}
```

Use the capitalized component in JSX:

```jsx
<Header />
```

Lowercase names such as `<header>` and `<section>` refer to built-in HTML elements.

**Best practice:** Use meaningful names such as `StudentCard`, `ProductList`, `TaskItem`, and `NavigationBar`.

# 2. Creating Functional Components

## 2.1 Basic component

Create a file called `Welcome.jsx`.

```jsx
function Welcome() {
  return (
    <section>
      <h1>Welcome to the Internship</h1>
      <p>Start learning React today.</p>
    </section>
  );
}

export default Welcome;
```

Now import it into `App.jsx`.

```jsx
import Welcome from "./Welcome.jsx";

function App() {
  return (
    <main>
      <Welcome />
    </main>
  );
}

export default App;
```

### What happens?

1. `Welcome.jsx` defines the component.
2. `export default Welcome` makes it available to other modules.
3. `App.jsx` imports the component.
4. `<Welcome />` renders it inside the application.

## 2.2 Multiple components in one file

For small examples, several components can be defined in the same file.

```jsx
function Header() {
  return <header><h1>Learning Portal</h1></header>;
}

function MainContent() {
  return <main><p>Today's topic is React.</p></main>;
}

function Footer() {
  return <footer>Internship Training</footer>;
}

function App() {
  return (
    <>
      <Header />
      <MainContent />
      <Footer />
    </>
  );
}

export default App;
```

For a larger project, it is usually clearer to move reusable components into separate files.

# 3. Understanding Props

## 3.1 What are props?

**Props** are inputs passed from a parent component to a child component.

Props allow a reusable component to display different information without duplicating its structure.

Example:

```jsx
function StudentCard(props) {
  return (
    <article>
      <h2>{props.name}</h2>
      <p>{props.role}</p>
    </article>
  );
}

function App() {
  return (
    <main>
      <StudentCard name="Aarav" role="Frontend Intern" />
      <StudentCard name="Diya" role="Backend Intern" />
      <StudentCard name="Kabir" role="Full Stack Intern" />
    </main>
  );
}

export default App;
```

All three cards use the same component, but each displays different information.

## 3.2 Parent and child components

In the previous example:

- `App` is the parent component.
- `StudentCard` is the child component.
- `name` and `role` are props.

The parent supplies the values, and the child uses them to display the UI.

### Real-life analogy: an ID card template

Imagine a company ID card template.

The layout contains a name, photo, department, and role. Every employee uses the same layout, but the information is different.

A React component is like the template, and props provide the information inserted into it.

## 3.3 Destructuring props

Instead of writing `props.name` and `props.role` repeatedly, you can destructure the properties.

```jsx
function StudentCard({ name, role }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>{role}</p>
    </article>
  );
}
```

This is equivalent to accessing the values through `props.name` and `props.role`.

Destructuring makes the component easier to read.

## 3.4 Default prop values

You can provide a default value when a prop is omitted or its value is `undefined`.

```jsx
function StudentCard({
  name,
  role = "Learner",
}) {
  return (
    <article>
      <h2>{name}</h2>
      <p>{role}</p>
    </article>
  );
}

function App() {
  return (
    <>
      <StudentCard name="Aarav" role="Frontend Intern" />
      <StudentCard name="Diya" />
    </>
  );
}

export default App;
```

The first card displays `Frontend Intern`. The second displays `Learner`.

A default value does not replace an explicit `null` value.

## 3.5 Passing different data types through props

Props can contain different JavaScript data types.

### String

```jsx
<StudentCard name="Aarav" />
```

### Number

```jsx
<CourseCard duration={12} />
```

### Boolean

```jsx
<StatusBadge isActive={true} />
```

### Array

```jsx
<SkillList skills={["HTML", "CSS", "React"]} />
```

### Object

```jsx
const student = {
  name: "Diya",
  role: "Frontend Intern",
};

<StudentDetails student={student} />
```

### Function

```jsx
<ActionButton onAction={handleAction} />
```

Strings can be passed using quotes. JavaScript variables, numbers, booleans, arrays, objects, and expressions are passed using curly braces.

## 3.6 Example: a course card with multiple props

```jsx
function CourseCard({
  title,
  duration,
  level,
  published,
}) {
  return (
    <article>
      <h2>{title}</h2>
      <p>Duration: {duration} weeks</p>
      <p>Level: {level}</p>
      <p>{published ? "Published" : "Draft"}</p>
    </article>
  );
}

function App() {
  return (
    <CourseCard
      title="React Fundamentals"
      duration={2}
      level="Beginner"
      published={true}
    />
  );
}

export default App;
```

Notice that the `published` prop is a boolean, so it is passed using curly braces.

# 4. Props Are Read-Only

Props should be treated as read-only inputs.

A child component should not directly modify a prop.

Incorrect:

```jsx
function Score({ marks }) {
  marks = marks + 10;

  return <p>Marks: {marks}</p>;
}
```

This is not the correct way to update application data.

If a value needs to change, use state in the component that owns that value, or have the parent pass a callback that performs the appropriate update.

For now, remember:

- Props pass data into a component.
- Props help components become reusable.
- Props should not be mutated by the receiving component.
- State will be covered in the next React sessions.

# 5. Passing Functions as Props

A parent can pass a function to a child so that the child can notify the parent when an action occurs.

Example:

```jsx
function ActionButton({ onAction }) {
  return (
    <button type="button" onClick={onAction}>
      Click Me
    </button>
  );
}

function App() {
  function handleAction() {
    console.log("The child button was clicked.");
  }

  return <ActionButton onAction={handleAction} />;
}

export default App;
```

When the button is clicked, React calls `onAction`, which refers to the parent's `handleAction` function.

### Important difference

Correct:

```jsx
<ActionButton onAction={handleAction} />
```

Incorrect for this purpose:

```jsx
<ActionButton onAction={handleAction()} />
```

The second example calls the function immediately while rendering instead of passing the function for later execution.

Function props are commonly used for:

- Button clicks
- Form submissions
- Delete actions
- Notifications to parent components
- Child components requesting changes

# 6. Component Composition

## 6.1 What is composition?

Component composition means combining smaller components to create a larger interface.

For example, a learning dashboard might contain:

- Header
- Navigation
- Welcome panel
- Course list
- Footer

Each piece can be developed separately and then combined in `App`.

Example:

```jsx
function Header() {
  return (
    <header>
      <h1>Learning Portal</h1>
    </header>
  );
}

function WelcomePanel({ studentName }) {
  return (
    <section>
      <h2>Welcome, {studentName}!</h2>
      <p>Continue learning React today.</p>
    </section>
  );
}

function Footer() {
  return <footer>Internship Training Program</footer>;
}

function App() {
  return (
    <>
      <Header />

      <main>
        <WelcomePanel studentName="Aarav" />
      </main>

      <Footer />
    </>
  );
}

export default App;
```

## 6.2 Component tree

The application structure can be represented as:

```text
App
├── Header
├── main
│   └── WelcomePanel
└── Footer
```

A component tree shows how components are nested within one another.

### Why is this useful?

When an application becomes large, the component tree helps developers understand:

- Which components belong to a page.
- Which components are reused.
- Where props are passed.
- How the interface is divided into manageable sections.

# 7. The `children` Prop

Sometimes we want to create a reusable container whose content changes depending on where it is used.

React provides the special `children` prop for content placed between a component's opening and closing tags.

Example:

```jsx
function Panel({ title, children }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      <div>{children}</div>
    </section>
  );
}

function App() {
  return (
    <main>
      <Panel title="Announcement">
        <p>React training starts today.</p>
      </Panel>

      <Panel title="Today's Topics">
        <ul>
          <li>JSX</li>
          <li>Components</li>
          <li>Props</li>
        </ul>
      </Panel>
    </main>
  );
}

export default App;
```

Both panels share the same outer layout, but their inner content differs.

## Real-life examples

The `children` pattern is useful for:

- Cards
- Dialogs and modals
- Layout containers
- Panels
- Reusable page sections
- Notification boxes

It avoids hardcoding the inner content into the component.

# 8. Rendering Components from Arrays

Applications often receive a collection of records.

For example, a training dashboard might have 12 students. Rather than manually writing 12 student cards, we can render them from an array.

```jsx
function StudentCard({ name, role, completedTasks }) {
  return (
    <article className="student-card">
      <h2>{name}</h2>
      <p>Role: {role}</p>
      <p>Completed tasks: {completedTasks}</p>
    </article>
  );
}

function StudentList() {
  const students = [
    {
      id: 1,
      name: "Aarav",
      role: "Frontend Intern",
      completedTasks: 4,
    },
    {
      id: 2,
      name: "Diya",
      role: "Full Stack Intern",
      completedTasks: 6,
    },
    {
      id: 3,
      name: "Kabir",
      role: "Frontend Intern",
      completedTasks: 3,
    },
  ];

  return (
    <section>
      <h1>Internship Students</h1>

      <div className="student-grid">
        {students.map((student) => (
          <StudentCard
            key={student.id}
            name={student.name}
            role={student.role}
            completedTasks={student.completedTasks}
          />
        ))}
      </div>
    </section>
  );
}

function App() {
  return <StudentList />;
}

export default App;
```

### Why use `key`?

The `key` helps React identify each list item when the list changes.

Use a stable, unique identifier, such as a database ID.

Avoid using array indexes for lists whose items may be inserted, deleted, or reordered.

### Passing an entire object

You can also pass the student object as a single prop:

```jsx
{students.map((student) => (
  <StudentCard
    key={student.id}
    student={student}
  />
))}
```

Then use it in the child:

```jsx
function StudentCard({ student }) {
  return (
    <article>
      <h2>{student.name}</h2>
      <p>Role: {student.role}</p>
      <p>Completed tasks: {student.completedTasks}</p>
    </article>
  );
}
```

Both approaches are valid. Choose the one that gives your component a clear and understandable interface.

# 9. Organizing Components into Separate Files

As an application grows, keeping every component inside `App.jsx` becomes difficult to maintain.

A possible structure is:

```text
src/
├── components/
│   ├── Header.jsx
│   ├── Footer.jsx
│   ├── StudentCard.jsx
│   ├── StudentList.jsx
│   └── Panel.jsx
├── App.jsx
├── main.jsx
└── index.css
```

## 9.1 Create a Header component

File: `src/components/Header.jsx`

```jsx
function Header() {
  return (
    <header>
      <h1>Internship Portal</h1>
    </header>
  );
}

export default Header;
```

## 9.2 Import the component

File: `src/App.jsx`

```jsx
import Header from "./components/Header.jsx";

function App() {
  return (
    <>
      <Header />

      <main>
        <h2>Dashboard</h2>
        <p>Welcome to the internship.</p>
      </main>
    </>
  );
}

export default App;
```

The relative path starts from the file containing the import.

## 9.3 Default exports

A file can export one default value.

```jsx
function Footer() {
  return <footer>Internship Training</footer>;
}

export default Footer;
```

Import it without curly braces:

```jsx
import Footer from "./components/Footer.jsx";
```

## 9.4 Named exports

A module can export multiple named values.

```jsx
export function Header() {
  return <header>Learning Portal</header>;
}

export function Footer() {
  return <footer>Training Program</footer>;
}
```

Import them with matching names inside curly braces:

```jsx
import { Header, Footer } from "./Layout.jsx";
```

Do not confuse the two import styles.

# 11. Common Mistakes

## Mistake 1 — Lowercase component names

Incorrect:

```jsx
function studentCard() {
  return <h2>Student</h2>;
}
```

Correct:

```jsx
function StudentCard() {
  return <h2>Student</h2>;
}
```

## Mistake 2 — Incorrect component usage

Incorrect:

```jsx
<studentCard />
```

Correct:

```jsx
<StudentCard />
```

## Mistake 3 — Mixing up props and strings

Incorrect:

```jsx
<StudentCard name={Aarav} />
```

This tries to read a JavaScript variable called `Aarav`.

Correct when passing a literal string:

```jsx
<StudentCard name="Aarav" />
```

Correct when passing a variable:

```jsx
const name = "Aarav";

<StudentCard name={name} />
```

## Mistake 4 — Modifying props

Do not directly change a prop inside the child component. Use state or a parent callback for changing data.

## Mistake 5 — Calling a callback during rendering

Incorrect:

```jsx
<ActionButton onAction={handleAction()} />
```

Correct:

```jsx
<ActionButton onAction={handleAction} />
```

## Mistake 6 — Missing imports

If `Header` is defined in another file, import it before using it.

## Mistake 7 — Incorrect exports

Make sure default and named exports match their corresponding imports.

## Mistake 8 — Missing list keys

Use stable identifiers for items returned from `map()`.
