# Week 4 — Day 12.2: Upload and Optimistic UI Exercises

## Exercise 1 — Profile Image Upload

1. Create a file input with image-only validation.
2. Reject files larger than a named limit.
3. Preview the local file with `URL.createObjectURL()`.
4. Send it using `FormData`.
5. Revoke preview URLs when they are no longer needed.

## Exercise 2 — Optimistic Like

1. Update the like count immediately.
2. Send the update to the API.
3. Restore the previous count on failure.
4. Keep the button disabled or guarded during an in-flight request.
5. Show a retryable error message.

## Exercise 3 — Optimistic Add Item

1. Add a temporary item to the list.
2. Give it a temporary client id.
3. Replace it with the server item on success.
4. Remove it and restore the form on failure.
5. Explain which user actions should not be optimistic.

## Submission Checklist

- Loading, success, and error states are visible.
- Uploaded files are validated before network work.
- No duplicate upload request can start from repeated clicks.
- The UI rolls back to a consistent state after failure.
- README explains one optimistic update and its rollback strategy.
